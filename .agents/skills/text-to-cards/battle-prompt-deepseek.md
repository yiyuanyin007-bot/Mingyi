## 项目背景

我正在为一位中医学习者设计一个基于《伤寒论》《金匮要略》的方剂思维训练系统。知识底座主要是倪海厦注解的《伤寒论》《金匮要略》。

**核心目标**：提升临床开方思维，即从症状、病机、药物反推/正推方剂的能力。

**系统组成**：
1. **卡片体系**：管理学习进度、安排艾宾浩斯复习
2. **AI 导师**：用户与 AI 围绕原文和疑惑进行对话，生成三级笔记
3. **前端训练系统**：v7 原型，三栏布局，支持方剂模式和临床模式
4. **后台提取 Skill（text-to-cards）**：从 Markdown/HTML/CHM/PDF 等源文本自动提取卡片

## 请评审的内容

### 1. 卡片结构设计（v0.2）

我们目前设计了三类卡片：

- **source_card（条文卡）**：保存《伤寒论》原文条文
- **formula_card（方剂卡）**：保存一个方剂的核心信息
- **experience_card（经验卡）**：保存倪海厦讲解、医案、个人心得

方剂卡的关键字段：

```json
{
  "id": "gui-zhi-tang",
  "formula_name": "桂枝汤",
  "source_text_ids": ["shl-012"],
  "data": {
    "core_symptoms": ["汗出", "恶风", "脉浮缓"],
    "secondary_symptoms": ["头痛", "发热"],
    "pathology": "风邪袭表，营卫不和",
    "herbs": [...],
    "usage": "...",
    "contraindications": [...],
    "variants": ["gui-zhi-jia-ge-gen-tang"],
    "confusable_formulas": ["ma-huang-tang", "ge-gen-tang"],
    "allow_multiple": false,
    "mapping_note": ""
  }
}
```

**请评审**：
- `core_symptoms` / `secondary_symptoms` 的区分是否合理？有没有更好的区分方式？
- `confusable_formulas` 作为卡片字段是否必要？还是应该动态计算？
- `source_text_ids` 引用独立条文卡，是否过度设计？
- 还有哪些字段是临床学习必需但目前缺失的？

### 2. 八个训练向量

每张方剂卡支撑 8 个训练向量：

| 向量 | 方向 | 示例 |
|------|------|------|
| 0→1 | 方名→症状 | "桂枝汤的使用场景是？" |
| 1→0 | 症状→方名 | "汗出恶风脉浮缓，选方？" |
| 0→2 | 方名→药物 | "桂枝汤的药物组成？" |
| 2→0 | 药物→方名 | "桂芍姜枣草，是哪首方？" |
| 0→3 | 方名→用法 | "桂枝汤怎么煎服？" |
| 3→0 | 用法→方名 | "以水七升微火煮取三升，是哪首方？" |
| 0→4 | 方名→病机 | "桂枝汤的辨证机理？" |
| 4→0 | 病机→方名 | "风邪袭表营卫不和，选方？" |

**请评审**：
- 这 8 个向量是否覆盖了临床开方所需的核心能力？
- 是否有冗余或缺失的向量？
- "症状→方名"和"病机→方名"在真实临床中是否是同一种能力？
- 剂量变化、加减变化、合方是否应作为独立向量？

### 3. 前端交互设计

v7 原型：
- 左栏：方剂卡片列表
- 中栏：学习详情 / 考试界面 / 复习仪表盘
- 右栏：掌握度 / 本次考试卡片
- 两种模式：
  - **方剂模式**：针对单张卡片进行全向量考试
  - **临床模式**：选择一个主方，系统自动补齐相似方，进行症状→方名辨析

**请评审**：
- 三栏布局的信息密度是否合理？
- 方剂模式 vs 临床模式的切换是否有学习科学依据？
- 临床模式用"易混方"作为干扰项，是否能有效训练辨证能力？
- 复习仪表盘（逾期/今日/未来）是否会造成焦虑或形式主义？

### 4. 后台提取可行性

当前提取流程：
1. 预处理：编码检测、去 HTML 标签、合并人工换行、按条文编号分段
2. 分段 → 分句
3. 识别元素：方名、症状、药物、用法、禁忌、病机、经验
4. 输出 Markdown+YAML 审阅文件
5. 人工审阅后生成 JSON

真实源文本包括：
- 倪海厦《伤寒论》GB2312 HTML 伪装的 .txt
- 《伤寒悬解》CHM 解压出的 ~600 个 HTML
- 扫描版 PDF（纯图片，需 OCR）
- .doc 文件

**请评审**：
- 从这种质量的源文本中自动提取高质量卡片，可行性如何？
- 最大的技术风险在哪里？
- 有没有更现实的替代方案（如先只做条文卡，不做经验卡）？
- OCR 扫描版 PDF 是否值得投入？
