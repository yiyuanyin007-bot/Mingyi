# Skill: 前端项目线上问题排查与部署 (frontend-debug-deploy)

## 触发条件

用户说以下任意指令时触发：
- "线上出问题了" / "线上白屏了" / "线上挂了"
- "部署有问题" / "部署不了"
- "帮我看看线上怎么回事"
- "帮我部署一下" / "帮我 Redeploy"
- 任何涉及 Vite 构建 + Vercel 部署的问题

## 输入

用户会提供：
- `{project_dir}` — 前端项目根目录路径
- `{online_url}` — 线上地址（如 `https://xxx.vercel.app`）
- `{bundle_glob}` — 构建产物 glob，如 `dist/assets/main-*.js`（默认值）
- `{entry_file}` — 相对入口文件路径，如 `src/app.js`
- `{known_functions}` — 要在 bundle 中检查的关键函数列表，如 `[init, switchView, renderDashboard]`
- 问题描述（白屏、功能失效、构建失败等）
- 可能用到的工具：**WebBridge**（必须可用，用于浏览器自动化部署）

> **输入参数化说明**：此 skill 为通用模板。调用时请将 `{project_dir}`、`{online_url}` 等替换为实际值。不写死任何特定项目的路径或函数名。

## 流程

### 第一步：环境检查 🏗

**目的：确认本地环境能否构建，npm/node 是否可用**

```bash
# 检查关键工具
node --version
npx --version
npm --version  # 如果不可用，标记为「异常」
```

检查清单：

| 项目 | 方法 | 结论 |
|------|------|------|
| node 可用 | `node -v` | ✅ / ❌ |
| npx 可用 | `npx --version` | ✅ / ❌ |
| npm 可用 | `npm -v` | ✅ / ❌ |
| Vite 可构建 | `npx vite build` | ✅ / ❌ |
| WebBridge 可用 | curl 测试 10086 端口 | ✅ / ❌ |

> **关键判断：** 如果 npm 不可用，则无法使用 `vercel CLI`。部署只能走 WebBridge + Vercel UI。

### 第二步：对比线上 vs 本地版本 🔍

**这是最重要的一步 — 先确认线上是不是最新代码！**

```bash
# 获取本地构建产物的文件名和大小
ls -la {bundle_glob:-dist/assets/main-*.js}

# 对比线上 bundle 文件名
# 打开浏览器 → 查看 <script src="...main-XXX.js"> 的 hash
# 或在 WebBridge 中执行:
# document.querySelector('script[src*="main-"]')?.src
```

**判断标准：**
- **线上和本地构建产物文件名不同** → ❌ 线上不是最新版本 → 直接跳到**第四步（部署）**，不要调代码！
- **文件名相同但功能有问题** → 进入**第三步（构建诊断）**

### 第三步：构建诊断 🛠

**只在确认线上与本地版本一致时执行。**

#### 3a. 本地构建验证

```bash
cd {project_dir}
npx vite build  # 检查有无报错
```

#### 3b. Bundle 内容检查

检查本地构建产物中关键函数是否存在：

```bash
# 列出所有 JS bundle
ls -la dist/assets/*.js

# 检查关键函数名
grep -o 'function [a-zA-Z_$][a-zA-Z0-9_$]*(' dist/assets/main-*.js | head -30
grep -oP '\w+\(\w+\)' dist/assets/main-*.js | head -20
```

或者用 Node.js 读取 bundle 源码做精确搜索：

```javascript
const fs = require('fs');
const content = fs.readFileSync('dist/assets/main-xxx.js', 'utf-8');
// 检查 init/switchView/renderDashboard 等已知函数
// 替换 {known_functions} 为实际函数名列表（如 init, switchView, renderDashboard）
const checks = {known_functions}.map(fn => `function ${fn}`);
checks.forEach(fn => console.log(fn, ':', content.includes(fn) ? '✅' : '❌'));
```

#### 3c. Bundle 中函数缺失的修复

如果在 bundle 中找不到入口文件的核心函数，说明被 Rollup treeshaking 删除了。

**修复方案（入口文件 `{entry_file}`）：**

1. 修改 `vite.config.js`：
```js
build: {
  rollupOptions: {
    treeshake: false,
    preserveEntrySignatures: 'strict',
  },
  modulePreload: false,
}
```

2. 在入口文件末尾添加保护代码（将 `init()` 替换为入口实际的核心启动函数）：
```js
// 在入口文件末尾添加
export const __ENTRY_GUARD__ = (typeof document !== 'undefined' ? 1 : 0);
{entry_core_call}; // 直接调用入口函数，如 init()
void document?.documentElement?.dataset?._v ?? ''; // 一行有副作用的代码
```

3. 重新构建验证：
```bash
npx vite build
# 重新检查 bundle 中函数是否存在
```

### 第四步：部署 🚀

#### 方式 A：Vercel CLI（推荐，需要 npm）

```bash
npx vercel --prod ./dist
```

#### 方式 B：WebBridge + Vercel UI（当 CLI 不可用时的兜底方案）

1. **打开 Vercel 登录页**
   ```javascript
   // WebBridge: navigate to https://vercel.com/login
   ```

2. **进入项目 → Deployments**
   找到项目名 → 点击 "Deployments" 导航链接

3. **找到最新部署**
   找到最近一次成功构建（或当前运行的部署）

4. **触发 Redeploy**
   - 点击部署进入详情页
   - 右上角找到 "Deployment Actions" 按钮（`aria-label="Deployment Actions"`）
   - 点击 → 菜单中选择 "Redeploy"
   - 弹出确认对话框 → 默认选择 Production → 点击 "Redeploy" 确认按钮

5. **等待构建完成**
   - 页面会跳转到新部署页面
   - 状态依次显示：Queued → Building → Ready
   - 等待约 1-3 分钟

#### 方式 C：git push (最理想，需要配置 GitHub 集成)

```bash
git add .
git commit -m "描述"
git push
# 如果 GitHub + Vercel 集成配置正常，会自动触发部署
```

### 第五步：线上验证 ✅

```bash
curl -s -o /dev/null -w "%{http_code}" "{online_url}"

# 如果无法网络访问，用 WebBridge 直接打开
// WebBridge: navigate to {online_url}
// 截图验证页面是否正常
```

线上 bundle 验证（在 WebBridge 或浏览器中）：

```javascript
// 获取线上 bundle 中的关键函数
// 替换 {known_functions} 为实际函数名列表
fetch(document.querySelector('script[src*="main-"]')?.src || '/assets/main-*.js')
  .then(r => r.text())
  .then(code => {
    {known_functions}.forEach(fn => {
      console.log('has ' + fn + ':', code.includes('function ' + fn));
    });
    console.log('size:', (code.length/1024).toFixed(0), 'KB');
  });
```

## 异常处理

| 症状 | 可能原因 | 处理方式 |
|------|---------|---------|
| `npm: command not found` | Node.js 安装问题 | 跳过 CLI，使用 WebBridge UI 部署 |
| `npx vite build` 失败 | 依赖缺失/版本冲突 | 检查 `package.json`、`node_modules` |
| Vercel UI 页面报错 "Something went wrong" | Vercel 渲染问题 | 点击 "Retry" 按钮重试 |
| Redeploy 后页面仍为旧版 | 构建未完成 | 等待 1-2 分钟，检查构建日志 |
| WebBridge click 不生效 | 按钮被框架层拦截 | 改用 `evaluate` 执行原生 JS `.click()` |
| bundle 中关键函数缺失 | treeshaking | 使用 `preserveEntrySignatures: 'strict'` 修复 |
