## 第一部分：V9 总体定位

### 1.1 产品名

**明医成长录**——从经方学习系统到中医临床能力成长平台。

### 1.2 一句话定位

> 以《伤寒论》方证为核心，通过"经典原文 + 现代医学解释 + 循证验证"三支柱，构建从方证反射弧到真实临床能力的递进式成长路径。

### 1.3 从"经方学习系统"到"明医成长录"的演进

| 维度 | 经方学习系统 v8 | 明医成长录 v9 |
|------|----------------|---------------|
| 定位 | 方剂记忆与考试工具 | 临床能力成长平台 |

## 第二部分：四阶段能力成长模型

### 设计理念

四个阶段对应中医临床能力形成的自然路径：

```
方-证对应 ──→ 条文理解 ──→ SP 模拟 ──→ 真实临证
（反射弧）    （理论深入）   （虚拟练习）   （实战闭环）
```

**注意**：四个阶段不完全串行。用户可能并行推进（如进行方-证训练的同时，也在阅读条文理解），也可能出现螺旋上升（临床后回来重新理解条文）。

### 三种使用形态

产品在任何阶段都支持三种使用形态：

1. **碎片训练**：5-15 分钟，利用零碎时间做方-证匹配、快速测试
2. **深度学习**：30-60 分钟，阅读详情页、做循证校验、写笔记
3. **临床辅助**：临证前快速复习、临证后记录反思（Phase 4 完整支持）

### Phase 2：条文现代化理解 + 循证验证

> **目标**：对条文建立"生理学拆解 → 病理生理学解释 → 中药药理学串联"的现代医学理解，并通过循证验证确保知识可靠。

#### 三通道理解框架

详情页中每个方剂的知识分为三个通道：

```
┌─────────────────────────────────────────┐
│  ① 经典原文（条文 + 方剂原文）          │
│  ② 现代医学解释                         │
│     ├─ 生理学拆解：这个方作用于哪个系统？│
│     ├─ 病理生理学：针对什么病理状态？    │
│     └─ 中药药理学：各味药的已知药理作用  │
│  ③ 循证验证结果                         │
│     ├─ 文献检索摘要                      │
│     ├─ 验证结论（可靠/待核实/有争议）    │
│     └─ 修正建议（如有）                  │
└─────────────────────────────────────────┘
```

#### 产品支持

## 第三部分：交互设计总则

### 3.1 卡片列表页设计原则

```
┌─────────────────────────────────────┐
│  [搜索框...]                        │
│                                     │
│  ┌─────────────────────────────────┐│
│  │ 桂枝汤    ████████░░  80%  [方] ││  ← 极简卡片
│  │ 太阳病 中风 桂枝证              ││
│  └─────────────────────────────────┘│
│  ┌─────────────────────────────────┐│
│  │ 麻黄汤    ██████░░░░  60%  [方] ││
│  │ 太阳病 伤寒 麻黄证              ││
│  └─────────────────────────────────┘│
│  ...                                │
└─────────────────────────────────────┘
```

1. **极简卡片**：每张卡片只展示三项内容
   - **名称**：方剂名（如"桂枝汤"）
   - **学习进度**：进度条 + 百分比，一目了然
   - **标签**：可点击聚合（如点击"太阳病"筛选所有太阳病方剂）
2. **点击卡片 → 进详情页**：列表页不展示任何额外信息
3. **快捷键体系**：
   - `Esc`：从详情页返回列表
   - 数字键/方向键：快速切换卡片
   - 所有快捷键在旁边可见（或在帮助面板中）

### 3.2 详情页设计原则（上下滚动长页面）

```
┌─────────────────────────────────────┐
│  ← 返回   桂枝汤    [📝笔记] [🔍]  │  ← 顶部导航 + 操作按钮
├─────────────────────────────────────┤
│  ▼ 经典原文（展开）                │
│  ┌───────────────────────────────┐ │
│  │ 条文原文 + 方剂原文           │ │
│  │ ...                            │ │
│  └───────────────────────────────┘ │
│                                     │
│  ▶ 现代医学解释（折叠）            │  ← 点击展开
│  ┌───────────────────────────────┐ │
│  │ 生理学拆解                    │ │
│  │ 病理生理学解释                │ │
│  │ 中药药理学串联                │ │
│  └───────────────────────────────┘ │
│                                     │
│  ▶ 循证结果（折叠）                │
│  ┌───────────────────────────────┐ │
│  │ 文献检索摘要 + 验证结论       │ │
│  └───────────────────────────────┘ │
│                                     │
│  ▼ 笔记区（展开）                  │
│  ┌───────────────────────────────┐ │
│  │ [Markdown 编辑器]             │ │
│  │ [🔍 循证校验] [有循证结果]   │ │
│  └───────────────────────────────┘ │
└─────────────────────────────────────┘
```

1. **上下滚动**：全部知识区块在一个页面内纵排，通过滚动浏览
2. **无 Tab 栏**、**无左侧导航** —— 只有上下滚动
3. **每个区块可折叠/展开**：
   - 经典原文：默认展开
   - 现代医学解释：默认折叠
   - 循证结果：默认折叠（有结果时显示标记）
   - 笔记区：默认展开
4. **顶部固定导航**：方剂名 + 返回按钮 + 关键操作（笔记/循证）

```
                    ┌──────────┐
                    │ 待校验   │ (初始状态)
                    └────┬─────┘
                         │ 点击"🔍 循证校验"
                    ┌────▼─────┐
                    │ 校验中   │ (按钮变灰，不可点击)
                    │ ⏳ 循证中…│
                    └────┬─────┘
                         │ 完成
              ┌──────────┼──────────┐
              │          │          │
         ┌────▼───┐ ┌───▼────┐ ┌───▼────┐
         │ 无结果  │ │ 有结果  │ │ 有争议  │
         │ (维持)  │ │ (显示) │ │ (标记)  │
         └────────┘ └────────┘ └────────┘
              │          │          │
              │     ┌────▼────┐     │
              │     │ 已更新   │     │
              │     │ (重新待) │     │
              └─────┴─────────┘─────┘
```

用户点击"有循证结果"后展开：

```
│                                      │
│  [一键更新笔记]                       │
└──────────────────────────────────────┘
```

### 4.3 一键更新机制

- 参考 `docs/evidence/correction_injection_plan.md` 的 `<!-- 循证修正意见 -->` 标记方案
- 操作流程：
  1. 生成修正方案（JSON 格式）
  2. 追加到笔记末尾（自动插入 `<!-- 循证修正意见 -->` 标记）
  3. 直接修改笔记中对应的内容（精确替换）
- 不可下载文献：自动生成 Markdown 待下载清单，用户下载后拖入指定目录

### 4.4 与循证审计体系的关系

V9 循证校验按钮是**产品层**的实现，下层依赖完整的循证审计体系：

```
产品层（V9 按钮）
  └─ 按钮状态机 + 结果视图 + 一键更新
       ↓ 调用
工作流层（如 method: evidence-audit）
  └─ 6 阶段 SOP：声明解析 → 检索 → 初验 → 复验 → 修正 → 登记
       ↓ 执行
项目级 Skill（.agents/skills/evidence-audit/SKILL.md）
  └─ 自动化 Agent 任务
       ↓ 参考
方法论文档（docs/evidence/）
  └─ SOP、Schema、报告模板、验证标准
```
