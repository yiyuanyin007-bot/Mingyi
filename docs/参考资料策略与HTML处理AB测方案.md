## 一、参考资料选择原则

### 1.1 核心原则：宁缺毋滥

- **主题相关**：资料必须围绕某张方剂展开（组成、功效、适应症、加减、医案、方解）。
- **来源可确认**：能明确说出作者/讲者、出处、原文链接或本地路径。
- **内容可审阅**：人不能只看机器摘要，必须能回到原文快速核对。
- **质量可靠**：优先收录注家本人（黄煌、倪海厦、冯世纶、胡希恕等）的讲解和医案；网友评论、转载、闲聊、导航页一律不收。
- **宁空勿滥**：如果一篇资料主题不聚焦、来源不清、质量存疑，**宁可空着也不挂**。

### 1.2 参考资料的两种形态

| 形态 | 说明 | 示例 |
|---|---|---|
| **外部链接** | 新浪博客、知乎、百度健康等可公开访问的 URL | 黄煌“我常用的几张经方”博客链接 |
| **本地资源** | 项目内 HTML/Markdown/PDF 的相对路径，前端可直接打开 | `raw/extracted-chm/60倪海厦大师经方讲座/.../*.html` |

> 由于很多原始材料是 HTML，未来会统一打包到项目内，references 字段应同时支持 `url` 和 `local_path`。

### 1.3 不放入参考资料区的内容

- 网友评论、论坛闲聊、转载但未标注出处
- 导航页、目录页、索引页
- 与方剂无关的养生、历史、版本考证（可收入资源库，但不挂到卡上）
- 质量低下或无法确认作者的“整理版”

## 二、HTML 资料处理的两种路径

未来大量 HTML 资料需要处理成“主题式参考资料”。存在两条路径：

### A 路径：HTML → Skill 直接提炼 → 填入模板

**流程**：

```text
raw/extracted-chm/<CHM>/<file>.html
        │
        ▼ Skill（接收 HTML + 方剂名）
        ▼ 直接输出 reference 对象
{
  "title": "...",
  "source": "...",
  "type": "article|case|lecture",
  "url": "...",
  "local_path": "...",
  "summary": "...",
  "tags": ["..."]
}
```

**优点**：
- 少一步清洗，端到端更快。
- Skill 可直接利用 HTML 标签结构（如 `sina_keyword_ad_area2`、`blogDetailDiv`）定位正文。
- 避免清洗规则误删信息。

**缺点**：
- HTML 噪音大（script/style/导航/广告/评论），Skill 需要很强的噪音过滤能力。
- 输出是黑盒，人工难以逐条核对“为什么摘了这段”。
- 不同 CHM 的 HTML 结构差异大，Skill 泛化成本高。
- 原始 HTML 不便于人直接阅读，references 中挂本地 HTML 路径时用户体验差。

### B 路径：HTML → 清洗成 Markdown → Skill 提炼 → 填入模板

**流程**：

```text
raw/extracted-chm/<CHM>/<file>.html
        │
        ▼ 清洗脚本（去标签、去噪音、保留正文和元数据）
        ▼
extracted/<CHM>/cleaned/<主题>/<file>.md
        │
        ▼ Skill（接收 Markdown + 方剂名）
        ▼ 输出 reference 对象
```

**优点**：
- Markdown 是中间档案，人工可读、可审阅、可追溯。
- Skill 输入干净，摘要质量更稳定。
- 清洗后的 Markdown 可以直接作为“本地资源”挂到 references 的 `local_path`。
- 清洗规则可复用、可迭代、可版本化。

**缺点**：
- 多一步工作。
- 清洗规则可能误删有用信息（如处方剂量、特殊排版）。
- 需要维护清洗脚本。

### C 路径（混合）：HTML → 轻量清洗 → Skill 提炼

**流程**：

```text
HTML → 只去 script/style/导航，保留段落和元数据 → Skill 提炼
```

**适用场景**：
- 当 HTML 结构非常规则时（如新浪博客），轻量清洗 + Skill 可以快速产出。
- 当资料量大、人工审阅成本高时，作为 A 和 B 的折中。

## 三、AB 测方案

### 3.1 测试目标

比较 A、B 两种路径在“生成高质量、主题相关、可审阅的参考资料”上的效果，决定未来 HTML 资料的默认处理路径。

### 3.2 测试样本

**来源**：
- **已清洗样本**：黄煌资料中与大柴胡汤、桂枝汤、八味除烦汤相关的 5 篇 Markdown（B 路径输入）。
- **原始 HTML 样本**：上述 5 篇对应的原始 HTML（A 路径输入）。

**为什么选这三个方**：
- 大柴胡汤：黄煌讲座重点方，医案多。
- 桂枝汤：现有卡片最完整，便于对比。
- 八味除烦汤：经验方，跨类别重复，考验版本控制。

### 3.3 测试方法

| 组别 | 输入 | 处理 |
|---|---|---|
| A 组 | 5 个原始 HTML 文件 | Skill 直接提炼，输出 reference 对象 |
| B 组 | 5 个已清洗 Markdown 文件 | Skill 提炼，输出 reference 对象 |

**Skill 提示词保持一致**：都告诉它“这是关于【方名】的资料，请提取主题相关的参考资料信息”。

### 3.4 评估指标

| 指标 | 权重 | 评估方式 |
|---|---|---|
| **主题相关性** | 30% | 输出的 reference 是否确实围绕目标方剂 |
| **信息完整性** | 25% | 是否包含组成、适应症、加减、剂量、医案等关键信息 |
| **噪音率** | 20% | 是否混入网友评论、导航、无关内容 |
| **人工审阅成本** | 15% | 输出是否需要大量修改才能用 |
| **可迁移性** | 10% | 同一 Skill/清洗规则是否容易应用到其他 CHM |

### 3.5 评估人员

- 主要由你（用户）做最终判断：A/B 哪组输出“更像人能直接用的参考资料”。
- 我也可以给出技术性评分（如字段完整度、JSON 合法性）。

### 3.6 输出物

- `docs/AB测_HTML处理路径_评估报告.md`
- 推荐默认路径（A / B / C）
- 一份标准化 Skill 提示词模板
- 如需 B 路径，输出通用清洗脚本配置草案

## 四、我的倾向性判断

在未做 AB 测前，我倾向于 **B 路径作为默认，C 路径作为特定场景优化**：

1. **人要读主题式内容** → Markdown 是更适合人读的主题式中间产物。
2. **参考资料需要可审阅** → 清洗后的 Markdown 让人能逐条核对来源。
3. **HTML 打包本地访问** → 清洗后的 Markdown 可以直接作为本地资源路径挂到 references。
4. **未来四个 CHM 数量大** → 先清洗再提炼，比让 Skill 直接处理 1563 个 HTML 更可控。

但 A 路径在以下场景可能更优：
- HTML 结构极其规则（如带 `itemprop="articleBody"` 的现代博客）。
- 只需要极少量关键字段（如标题 + URL + 一句话摘要），不需要完整正文。

因此 AB 测主要验证：**对于我们这批 GB 编码的博客式 CHM，B 路径的增量收益是否值得多一步清洗成本**。

## 五、references 字段设计（为 AB 测做准备）

无论 A/B，最终填入 `formula_card.data.canonical.references` 的结构建议如下：

```json
{
  "title": "黄煌教授 我常用的几张经方",
  "source": "黄煌教授经方沙龙",
  "source_type": "讲座记录",
  "type": "article",
  "url": "http://blog.sina.com.cn/s/blog_766c0caf0100vz3n.html",
  "local_path": "extracted/黄煌教授经方沙龙/cleaned/常用经方/黄煌教授_我常用的几张经方.md",
  "related_formula": "大柴胡汤",
  "summary": "2007年广东省中医院讲座，列出黄煌临床最常用13张经方，大柴胡汤用于胆囊炎/胰腺炎/高血压，强调腹诊心下按之满痛。",
  "tags": ["大柴胡汤", "胆囊炎", "腹诊"],
  "confidence": "high",
  "reviewed": true
}
```

字段说明：
- `type`：`article` / `case` / `lecture` / `experience`
- `local_path`：项目内可访问的清洗后文件路径
- `related_formula`：该资料主要关联的方剂（一张 reference 可关联多方）
- `confidence` / `reviewed`：支持审阅工作流
