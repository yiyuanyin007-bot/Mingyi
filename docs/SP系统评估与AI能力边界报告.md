## 二、AI能力评估与职责边界

### 2.1 我的核心能力

| 能力 | 等级 | 说明 |
|------|------|------|
| 文档阅读与理解 | 5/5 | 已完整阅读7份SP文档，理解体系全貌 |
| 数据生成与验证 | 5/5 | 可生成符合Schema的JSON，自动验证 |
| 批量生成协调 | 4/5 | sp_generator.py可自动组装数据包 |
| 症状口语化 | 4/5 | 有模板，但创新性表达需人工判断 |
| 临床真实性判断 | 3/5 | 缺乏真实临床经验 |
| 干扰项设计 | 4/5 | 算法可辅助，但需人工审核 |
| 前端交互实现 | 4/5 | 可修改index.html，需用户确认UI |

### 2.2 我的绝对边界（不可违反）

| 边界 | 说明 | 违反后果 |
|------|------|---------|
| 不做临床诊断 | 只生成患者叙事，不评判辨证 | 破坏SP模拟价值 |
| 不代替患者决策 | 不回答"该选什么方" | 违反绝对禁令 |
| 不编造条文 | 所有条文必须来自source_article_map | 教学错误 |
| 不创造幻觉症状 | 症状必须来自symptom_pool | 破坏方证对应 |
| 不替代用户反馈 | 无法判断病例难度是否合适 | 需用户实际使用验证 |
| 不执行无备份的修改 | 每次改数据必须备份 | 数据丢失风险 |

### 2.3 职责边界划分

**属于我（本对话）的职责**：
1. 生成新的SP病例JSON（按用户指定方剂/难度/人格）
2. 验证JSON合法性（schema compliance + governance.py）
3. 更新数据文件（sp_cases.json / symptom_expression_index.json / persona_system.md）
4. 维护文档一致性（CHANGELOG同步更新）
5. 运行批量生成器并处理输出
6. 备份文件到archive/目录

**不属于我（需用户确认或转交）的职责**：
1. 修改前端交互逻辑（app/index.html中的SP视图函数）→ 转交"交互设计系统"对话
2. 决定病例难度是否合适 → 需用户临床验证
3. 扩展至《金匮要略》→ 需用户确认优先级
4. 删除已有病例 → 需用户明确授权
5. 修改JSON Schema版本 → 架构决策，需用户确认
