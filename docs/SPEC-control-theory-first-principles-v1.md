## 〇、先建立一个共同的认知框架

### 0.1 控制论视角下的「明医成长录」

诺伯特·维纳的控制论核心只有一句话：**系统通过信息反馈实现自我控制。**

把「明医成长录」看成一个控制系统：

```
        用户临床开方
              │
              ▼
    ┌─────────────────┐
    │   疗效传感器     │  ← 临床反馈：有效/无效/副作用
    │  （目前缺失）     │
    └────────┬────────┘
             │ 反馈信号
             ▼
    ┌─────────────────┐
    │   控制器         │  ← 你的经方认知模型（六向量+SRS）
    │  （目前=出题引擎）│
    └────────┬────────┘
             │ 控制信号
             ▼
    ┌─────────────────┐
    │   执行器         │  ← 每日复习、弱项推荐、类方考试
    │  （目前完整）     │
    └────────┬────────┘
             │ 训练刺激
             ▼
    ┌─────────────────┐
    │   被控对象       │  ← 用户的大脑（经方认知网络）
    │  （不可测，可推断）│
    └────────┬────────┘
             │ 学习输出
             ▼
    ┌─────────────────┐
    │   传感器         │  ← 答题正确率、掌握度、错题本
    │  （目前部分）     │
    └─────────────────┘
             │
             ▼
        回到控制器（闭环）
```

**关键发现：你的系统目前是一个「开环训练器」——输入训练刺激，输出答题数据，但缺少「临床疗效」这个最终反馈。**

### 0.2 第一性原理：你真正相信什么？

从第一性原理出发，先列出你当前隐含的、未经严格验证的核心假设：

| 编号 | 你的假设（信念） | 来源 | 目前验证状态 |
|------|-----------------|------|------------|
| H1 | 经方学习 = 认知训练，不是资料积累 | 你个人学习经验 | 无对照实验 |
| H2 | 6 个向量覆盖了「方证对应」所需的全部认知维度 | 你个人归纳 | 无因子分析 |
| H3 | 间隔重复（SRS）是中医记忆巩固的最优策略 | 认知科学文献外推 | 未经中医场景验证 |
| H4 | 类方鉴别训练能提高临床选方准确率 | 你个人直觉 | 无临床对照 |
| H5 | 症状→方名（1→0）向量是最薄弱的临床能力 | 你个人观察 | 无群体数据 |
| H6 | 数据驱动推荐比「从头学到尾」更高效 | 一般学习科学外推 | 无中医场景 A/B 测试 |

**第一性原理的核心问题：这些假设中，有多少是真的，有多少只是「你觉得对」？**

## 一、问题一：数据怎么收集？

### 1.1 当前系统已收集的数据（传感器现状）

| 数据类型 | 收集方式 | 粒度 | 价值 | 问题 |
|---------|---------|------|------|------|
| 答题事件 | localStorage | 每题：题目/选项/对错/时间戳 | 高 | 单设备，不上传 |
| 掌握度状态 | 六向量状态机 | 每方×6向量：状态/下次复习时间 | 高 | 算法参数未校准 |
| 错题记录 | 错题本 | 每错：题目/正确答案/用户错选/时间 | 高 | 无分析利用 |
| 搜索行为 | 搜索历史 | 每次查询关键词 | 中 | 未关联到训练效果 |
| 用户留存 | 无 | 无 | — | 完全不知道用户用多久 |
| 临床行为 | 无 | 无 | — | 训练→临床的断链 |
| 疗效反馈 | 无 | 无 | — | 最根本的反馈缺失 |

### 1.2 从控制论看：需要补全的反馈回路

**核心问题：目前的系统是一个「训练闭环」，但缺少「临床闭环」。**

理想的完整闭环应该是：

```
用户学习 → 答题数据 → 掌握度更新 → 继续训练
   │                              │
   │                              │
   ▼                              ▼
临床开方 ← 疗效反馈 ← 患者跟踪 ← 训练完成标记
```

**Phase 1（现在可做，零成本）：** 训练数据闭环
- 用户每日答题 → 正确率 → 掌握度 → 下次出题
- 这已经是闭环，但只闭环在「记忆层面」

**Phase 2（需要设计，低成本）：** 临床行为闭环
- 在学习卡片增加「临床记录」入口
- 用户记录：今日遇到的患者 → 症状 → 我选了什么方 → 为什么
- 即使暂时没有疗效反馈，「临床决策记录」已经是巨大的数据资产

**Phase 3（需要信任，中等成本）：** 疗效反馈闭环
- 患者跟踪：记录服药后 3 天/7 天/14 天的反馈
- 疗效分级：痊愈/显效/有效/无效/加重/副作用
- 这个闭环一旦建立，你的系统就从「学习工具」变成「循证工具」

### 1.3 具体的数据收集策略

#### 策略 A：最小侵入式（不改临床流程，只记录）

在用户现有的临床工作流中，插入一个「记录」动作：

```
患者问诊 → 辨证选方 → 【记录到系统】 → 抓药/治疗 → 患者随访
                              │
                              ▼
                        记录结构：
                        - 患者ID（匿名）
                        - 主诉症状（结构化勾选）
                        - 舌象/脉象（选项）
                        - 六经定位（用户选择）
                        - 选用方剂（用户选择）
                        - 剂量调整（用户输入）
                        - 选择理由（可选文字）
                        - 预期效果（可选）
```

**关键设计：不增加用户负担。**
- 症状用「方剂卡片已有的 symptom_profile」做勾选，不打字
- 六经定位用已有的标签体系
- 方剂选择从已有 99 方中选择
- 整个记录过程 < 1 分钟

#### 策略 B：随访触发式（患者端）

```
用户记录处方后，生成一个随访链接/二维码
          │
          ▼
患者扫码 → 简单问卷（5题，3分钟）
          - 服药后症状变化（好转/无变化/加重）
          - 新出现的症状（勾选）
          - 整体感受（1-5分）
          - 是否继续服用（是/否/已停）
          - 副作用（有无/描述）
          │
          ▼
    数据回流到用户系统 → 疗效数据库
```

**这个策略一旦跑通，你就拥有了中国最稀缺的资源：真实世界的经方疗效数据。**

#### 策略 C：A/B 测试框架（验证假设的核心武器）

为了验证 H1-H6，你需要对照实验：

```
用户分群：
├─ 对照组 A：传统学习（自由浏览卡片，无考试）
├─ 实验组 B：六向量训练（当前系统）
├─ 实验组 C：六向量 + 类方鉴别强化（干扰项更难的版本）
└─ 实验组 D：AI 推荐路径（非弱项优先，而是知识图谱路径）

测量指标：
├─ 短期：答题正确率、掌握度变化斜率、每日学习时长
├─ 中期：模拟考试分数、类方鉴别准确率、条文背诵得分
└─ 长期：临床记录数、选方准确率（与标准答案对比）、疗效有效率

实验周期：
- 短期：2 周
- 中期：2 个月
- 长期：6 个月（足够覆盖一个临床周期）
```

### 1.4 数据收集的伦理与合规

**这是一个医疗相关系统，数据收集必须合规：**

| 数据类型 | 合规要求 | 当前状态 | 行动 |
|---------|---------|---------|------|
| 学习行为数据（答题/掌握度） | 用户同意即可 | 无用户协议 | 需添加隐私政策 |
| 匿名临床记录（症状/处方） | 匿名化 + 用户同意 | 未收集 | 需伦理审查（如学术合作） |
| 患者随访数据 | 患者知情同意 | 未收集 | 需患者授权协议 |
| 个人数据跨境 | 如用 Supabase/Firebase | 未开始 | 数据须留境内或明确告知 |

**建议：Phase 1 只收集学习行为数据，Phase 2 开始用「匿名临床记录 + 用户自我报告」方式收集，Phase 3 才引入患者随访。**

## 二、问题二：专利怎么实现？

### 2.1 软著 vs 专利：根本区别

| 维度 | 软著（已申请） | 发明专利（待评估） |
|------|-------------|------------------|
| **保护什么** | 代码的「表达」 | 技术「方案」 |
| **保护期限** | 个人：终身 + 50 年 | 20 年 |
| **审查方式** | 形式审查（登记制） | 实质审查（创造性审查） |
| **侵权判定** | 代码复制 | 技术方案实施 |
| **费用** | ~300 元 | ~5000-15000 元 |
| **周期** | 1-2 个月 | 2-3 年 |

**关键区别：软著保护的是你「怎么写的」，专利保护的是你「怎么想的」。**

### 2.2 从第一性原理看：哪些可以申请专利？

专利法保护的是「技术方案」，不保护：
- ❌ 科学发现（如"六经辨证体系"）
- ❌ 智力活动规则（如"学习方法"）
- ❌ 疾病诊断和治疗方法（这是法律红线）
- ✅ 计算机程序 + 技术效果（如「一种提升学习效率的方法」）

**所以问题变成：你的系统中，哪些不是「学习方法」，而是「技术方案」？**

### 2.3 可申请专利的技术点梳理

#### 候选专利 1：六向量认知映射训练系统

**技术方案描述：**
> 一种基于多向量认知映射的中医经方学习系统，其特征在于：
> 1. 将经方知识体系分解为六个双向认知向量（方名→症状、症状→方名、方名→药组、药组→方名、方名→禁忌、方名→煎服法）；
> 2. 每个向量独立追踪掌握状态，形成状态机（未知→正在学习→已掌握→已遗忘）；
> 3. 基于间隔重复算法，根据每个向量的答题表现动态计算下次复习时间；
> 4. 根据用户薄弱向量，自动生成针对性训练题目。

**可专利性评估：中等**
- 优点：「六向量分解」是你的原创性归纳，不是公知常识
- 风险：可能被视为「学习规则」而非「技术方案」
- 建议：重点强调「技术效果」（如：通过计算机实现个性化训练路径生成，降低遗忘率）

#### 候选专利 2：类方智能干扰项生成方法

**技术方案描述：**
> 一种用于中医经方鉴别诊断训练的干扰项生成方法，其特征在于：
> 1. 构建方剂相似度矩阵，基于症状谱重叠率、药物组成重叠率、六经归属一致性计算类方关系；
> 2. 出题时，从目标方剂的「近邻类方」中选取干扰项，而非随机抽取；
> 3. 干扰项的选取遵循「临床鉴别意义」原则：干扰项与正确答案在症状谱上具有部分重叠，但在关键鉴别症状上存在差异；
> 4. 通过控制干扰项的相似度阈值，动态调节题目难度。

**可专利性评估：较高**
- 优点：这是一个明确的算法技术方案，有技术效果（提高鉴别诊断能力）
- 风险：需证明「临床鉴别意义」是可量化、可实现的，而非主观判断

#### 候选专利 3：基于症状表达的多路径检索引擎

**技术方案描述：**
> 一种中医经方多路径检索系统，其特征在于：
> 1. 建立症状关键词到方剂的多对多索引；
> 2. 建立药物组合到方剂的反向索引；
> 3. 接收用户输入的症状描述，通过语义匹配引擎映射到结构化症状关键词；
> 4. 返回多路径检索结果：直接匹配方剂、症状关联方剂、药物反推方剂；
> 5. 结果按临床相关性排序，而非简单的关键词匹配度。

**可专利性评估：高**
- 优点：这是典型的信息检索技术，属于专利保护范畴
- 已有技术参考：Google 的 PageRank、医疗领域的诊断辅助系统（如 IBM Watson Health）都有类似专利

#### 候选专利 4：方剂掌握度状态机与自适应调度算法

**技术方案描述：**
> 一种基于状态机的中医知识掌握度追踪与自适应训练调度方法，其特征在于：
> 1. 为每个知识单元（经方）的每个认知维度（向量）建立独立状态机；
> 2. 状态转换由答题事件触发，根据正确率、连续正确次数、时间间隔计算状态转移概率；
> 3. 基于遗忘曲线模型，动态计算每个向量的下次复习时间；
> 4. 系统根据全局薄弱度分布，生成每日训练队列，优化长期记忆保持率。

**可专利性评估：中等偏高**
- 优点：状态机 + 自适应调度是明确的技术方案
- 风险：SRS 算法本身是公知技术（Anki/SuperMemo），需要证明你在「中医经方场景」的适配是创新性的

### 2.4 不能申请专利的内容（法律红线）

| 内容 | 原因 | 替代保护方式 |
|------|------|------------|
| 六经辨证体系本身 | 属于科学发现和医学知识 | 作为数据库著作权保护 |
| 方剂卡片的内容（症状、药物、剂量） | 属于传统知识 | 作为汇编作品受著作权保护 |
| 中医诊疗方法（辨证、选方） | 专利法明确排除「疾病诊断和治疗方法」 | 作为经验/商业秘密 |
| 学习方法论（「先学太阳病再学阳明病」） | 属于智力活动规则 | 作为课程设计受著作权保护 |

### 2.5 专利实现路径建议

| 阶段 | 动作 | 时间 | 预算 |
|------|------|------|------|
| **Phase 1（现在）** | 撰写专利交底书（4个候选技术点），找专利代理所评估 | 1-2 周 | 0 元（自撰写） |
| **Phase 2（软著拿到后）** | 提交发明专利申请（建议优先候选2和候选3） | 2-3 个月 | ~5000-8000 元/件 |
| **Phase 3（申请后）** | 补充实验数据（用户 A/B 测试结果）支撑专利创造性 | 6-12 个月 | 0 元（系统已有） |
| **Phase 4（审查期）** | 答复审查意见，可能需要修改权利要求书 | 1-2 年 | ~3000-5000 元 |

**关键建议：找专业专利代理所。** 个人撰写的专利被驳回率极高。代理所费用虽然高，但能把「你的思想」翻译成「审查员能理解的专利语言」。

## 三、问题三：怎么验证你思考的东西？

### 3.1 你思考的东西是什么？（从第一性原理还原）

从我们的对话历史和你的项目文档中，我提炼出你的核心思考：

> **核心命题 P**：通过「六向量认知训练 + 间隔重复 + 类方鉴别」的系统化方法，可以比传统的「背诵 + 临证模仿」更高效地培养中医经方的临床方证对应能力。

这个命题可以分解为 6 个可验证的子假设（H1-H6，见 0.2 节）。

**第一性原理问题：这个命题是「真」的吗？**

### 3.2 验证方法：从科学方法的四个层次

#### 层次 1：逻辑自洽性验证（现在可做）

**问题：六向量是否覆盖了方证对应的全部认知维度？**

验证方法：专家评审
- 找 3-5 位经方临床专家（如你的老师）
- 让他们独立评价：临床开方时，除了这 6 个向量，还需要什么知识？
- 如果专家一致认为「还缺少 X」，则 H2 被证伪或需修正

**问题：六向量之间的关系是什么？是正交的还是重叠的？**

验证方法：相关性分析
- 收集用户数据后，计算 6 个向量掌握度之间的皮尔逊相关系数
- 如果高度相关（r > 0.7），说明向量之间有冗余，不是正交的
- 如果低相关（r < 0.3），说明向量确实是独立的认知维度

#### 层次 2：内部效度验证（短期，2-4 周）

**A/B 测试设计：**

```
实验组（六向量训练）：使用「明医成长录」当前系统
对照组（传统学习）：使用「明医成长录」的「浏览模式」（去掉考试，只让自由看卡片）

测量指标：
├─ 记忆保持率：第 1 天学习 → 第 7 天测试 → 第 30 天测试
├─ 类方鉴别准确率：给一组相似症状，选择正确方剂
├─ 反向检索准确率：给一组药物，选择对应方剂
├─ 条文联想准确率：给一条症状，回忆对应原文条文
└─ 学习效率：达到同等正确率所需的训练时间

样本量：每组至少 30 人（统计学最低有效样本）
```

**关键操作：**
1. 在系统中增加「实验模式」入口，用户同意后被随机分配到 A/B 组
2. 对照组只能浏览卡片，没有考试和复习推送
3. 两组在 7 天和 30 天后各做一次统一测试
4. 比较两组的各项指标

#### 层次 3：外部效度验证（中期，3-6 个月）

**核心问题：训练效果能否迁移到真实临床？**

验证方法：临床模拟测试

```
前置条件：用户在系统上训练至少 2 个月

测试设计：
1. 选取 20 个标准化病人（SP）病例（已在系统内）
2. 用户独立进行「模拟问诊 → 辨证 → 选方」
3. 与专家标准答案对比，计算：
   - 选方正确率（与专家一致）
   - 鉴别诊断完整性（是否考虑了类方）
   - 剂量合理性（是否在标准范围内）

对比组：
├─ 实验组：使用系统训练 2 个月的用户
├─ 对照组 A：未使用系统、同等资历的中医学习者
├─ 对照组 B：使用系统但未坚持训练的用户（< 30 天）
└─ 对照组 C：资深经方医生（天花板参照）
```

**关键操作：**
- 与中医院校或临床科室合作
- 获得伦理审查批准（IRB）
- 所有数据匿名化

#### 层次 4：真实世界验证（长期，1-2 年）

**核心问题：训练是否能转化为更好的临床疗效？**

这是最难验证的，也是最有价值的。

```
研究设计：队列研究（非随机对照，因为无法随机分配患者）

实验组：使用系统训练后独立临床开方的医生
对照组：同等资历、未使用系统的医生

追踪指标：
├─ 客观指标：患者复诊率、处方有效率（患者自评）
├─ 主观指标：医生自信心评分、辨证思路清晰度
└─ 长期指标：患者满意度、医生经方使用频率

统计方法：
- 倾向性评分匹配（PSM），平衡两组基线差异
- 多元回归分析，控制患者年龄、性别、病程等混杂因素
```

### 3.3 验证的「可证伪性」设计

**第一性原理的关键：一个好的假设必须可以被证伪。**

你的假设 H1-H6 中，哪些是可以被证伪的？

| 假设 | 证伪条件 | 如果证伪了怎么办？ |
|------|---------|------------------|
| H2（6向量全覆盖） | 专家提出第 7 个关键向量 | 扩展为 7 向量，或承认模型不完美 |
| H3（SRS最优） | A/B 测试显示「自由学习」组的长期保持率更高 | 放弃 SRS，改回自由浏览模式 |
| H4（类方鉴别提高临床准确率） | SP 测试显示实验组与对照组无差异 | 重新设计类方训练，或承认类方训练不是瓶颈 |
| H5（1→0最薄弱） | 数据显示「0→禁忌」或「0→煎服法」的错误率更高 | 调整训练重点，优先薄弱向量 |
| H6（推荐路径更高效） | A/B 测试显示「按顺序学习」比「弱项优先」更快达到同等水平 | 放弃弱项优先，改回顺序学习 |

**关键心态：证伪不是失败，而是进步。如果 H4 被证伪，说明你找到了真正的瓶颈——可能是剂量换算、可能是条文背诵、可能是 SP 训练。这比「自以为知道」更有价值。**

### 3.4 验证的时间线

```
Month 1-2:  逻辑自洽性验证（专家评审 + 向量相关性分析）
Month 2-4:  内部效度 A/B 测试（记忆保持率、鉴别准确率）
Month 4-8:  外部效度 SP 测试（临床模拟）
Month 8-24: 真实世界队列研究（疗效追踪）
```

## 四、三个问题的交叉关系

```
                    ┌─────────────────┐
                    │   第一性原理     │
                    │  （你的假设）     │
                    │   H1-H6         │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
              ▼              ▼              ▼
    ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
    │  数据收集    │ │  专利实现    │ │  假设验证    │
    │ （控制论）   │ │（知识产权）  │ │（科学方法）  │
    └──────┬──────┘ └──────┬──────┘ └──────┬──────┘
           │               │               │
           │               │               │
           └───────────────┼───────────────┘
                           │
                           ▼
                   ┌───────────────┐
                   │   完整闭环     │
                   │  训练→临床→   │
                   │  疗效→数据→   │
                   │  模型进化      │
                   └───────────────┘
```

**关键洞察：这三个问题不是独立的，它们是同一件事的不同侧面。**

- 数据收集是「验证」的燃料（没有数据，无法验证）
- 验证是「专利」的根基（没有实验数据，专利缺乏创造性支撑）
- 专利是「数据收集」的护城河（别人不能复制你的技术方案，但你可以共享数据）
- 第一性原理是贯穿三者的灵魂（你始终要知道自己在验证什么、保护什么）
