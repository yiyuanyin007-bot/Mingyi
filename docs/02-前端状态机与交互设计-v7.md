## 文档定位

本文件是 **前端交互系统的架构设计文档**，聚焦三个层面：

1. **状态模型**：页面有哪些合法状态、状态之间如何迁移
2. **交互规范**：键盘快捷键的全局语义、模式切换的 UI 呈现
3. **数据流**：用户操作 → 状态变更 → DOM 更新 → 掌握度回写

**不包含**（已在 v3.0 顶层设计中定义）：
- 卡片 JSON 结构、掌握度算法、艾宾浩斯等级制度
- AI 导师工作流程、文件组织结构
- 制卡迭代流程

## 一、v6 硬伤诊断（摘自 Ds 评审）

| # | 硬伤 | 根因 | 严重度 |
|---|------|------|--------|
| 1 | `currentMode` / `currentExamMode` / `examMode` / `selectedCardIndices` 5 个状态变量相互耦合 | 状态模型未正交化 | 🔴 致命 |
| 2 | "考试这张卡"按钮语义取决于隐藏的 Tab 模式 | 操作语义依赖不可见状态 | 🔴 致命 |
| 3 | 空格键 6 种语义，Enter/空格 在弹窗中语义分裂 | 交互一致性崩溃 | 🔴 致命 |
| 4 | 掌握度硬编码，考试结果不回写 | 闭环验证失效 | 🟡 严重 |
| 5 | `userAnswer.includes(card.name)` 判定过于模糊 | 考试严肃性丧失 | 🟡 严重 |
| 6 | 争议标记 O/P 静默 flip，无 UI 反馈 | 元认知功能为空 | 🟢 中等 |
| 7 | `backToLearnFromInput` 目标视图不明确 | 导航模型未收敛 | 🟢 中等 |

**结论**：v6 的问题根源不在实现细节，而在概念模型。v7 必须从状态机开始重构。

## 二、正交化状态机

### 2.1 设计原则

1. **最小充分统计量**：状态变量之间无冗余、无隐含条件。每个状态变量独立表达一个正交维度。
2. **非法组合不可达**：不是"运行时检查避免"，而是"类型系统保证"——状态变量的取值空间天然不包含非法组合。
3. **单一状态源**：全局只有一个 `appState` 对象，所有状态变更都通过明确的 `transition()` 函数完成。
4. **状态可序列化**：任何时候 `JSON.stringify(appState)` 都能完整描述当前 UI 应呈现的内容。

### 2.2 状态定义

```javascript
// ========== v7 唯一状态对象 ==========
const appState = {
  // --- 页面级状态 ---
  page: 'dashboard' | 'learn' | 'exam',

  // --- 学习/考试上下文 ---
  activeCardId: string | null,      // 当前选中的卡片 ID
  selectedCardIds: string[],        // 多选卡片 ID 列表（临床模式用）

  // --- 考试参数 ---
  examMode: 'formula' | 'clinical', // 方剂模式（全向量）| 临床模式（症状→方名）
  examCardCount: 2,                 // 临床模式下考试卡片数量
  examVectors: string[],            // 本次考试涉及的向量列表（如 ['1→0'] 或 ['0→1','0→2',...]）

  // --- 考试进行中状态 ---
  currentQuestionIndex: 0,
  questions: [],                    // { cardId, vector, questionText, options, correctAnswer, ... }
  answers: [],                      // { cardId, vector, userAnswer, isCorrect }

  // --- UI 元状态 ---
  isInputBoxVisible: false,         // 输入框是否已展开
  isFeedbackModalVisible: false,    // 反馈弹窗是否显示
  isEndPanelVisible: false,         // 考试结束面板是否显示
};
```

### 2.3 关键简化

v6 中 5 个变量 → v7 中 1 个对象的 3 个关键字段：

| v6 变量 | v7 替代 | 说明 |
|---------|---------|------|
| `currentMode` ('learn'\|'exam'\|'input-exam') | `page` ('dashboard'\|'learn'\|'exam') | "input-exam" 不是独立页面，是 exam 页面的子状态，由 `examMode` + `examVectors` 决定 |
| `currentExamMode` ('clinical'\|'formula') | `examMode` | 语义不变，但不再是隐藏变量 |
| `examMode` ('all'\|'single') | 删除 | 考试范围由 `selectedCardIds` 和 `examVectors` 自然决定 |
| `examSingleCardIdx` | 删除 | 通过 `selectedCardIds[0]` 或 `activeCardId` 获取 |
| `selectedCardIndices` / `currentCardIdx` | `selectedCardIds` / `activeCardId` | 用 ID 替代索引，更鲁棒 |

### 2.5 状态迁移函数

```javascript
// ========== 核心迁移函数 ==========

function transition(newState) {
  // 1. 校验新状态的合法性
  assertValidTransition(appState, newState);

  // 2. 更新状态
  Object.assign(appState, newState);

  // 3. 根据新状态渲染 UI
  renderByState();
}

function assertValidTransition(from, to) {
  const { page } = to;
  // page 只能在这三个值之间
  if (!['dashboard', 'learn', 'exam'].includes(page)) {
    throw new Error(`非法 page: ${page}`);
  }
  // 进入 exam 必须指定 examMode
  if (page === 'exam' && !to.examMode) {
    throw new Error('进入 exam 必须指定 examMode');
  }
  // 进入 learn 必须指定 activeCardId
  if (page === 'learn' && !to.activeCardId) {
    throw new Error('进入 learn 必须指定 activeCardId');
  }
}

// ========== 常用迁移快捷函数 ==========

function goToDashboard() {
  transition({ page: 'dashboard', questions: [], answers: [] });
}

function goToLearn(cardId) {
  transition({ page: 'learn', activeCardId: cardId });
}

function startFormulaExam(cardId) {
  const card = getCard(cardId);
  transition({
    page: 'exam',
    examMode: 'formula',
    selectedCardIds: [cardId],
    examVectors: card.vectors,          // 全向量
    questions: generateAllVectorQuestions(cardId),
    currentQuestionIndex: 0,
    answers: [],
  });
}

function startClinicalExam(cardIds, count) {
  transition({
    page: 'exam',
    examMode: 'clinical',
    selectedCardIds: cardIds,
    examCardCount: count,
    examVectors: ['1→0'],               // 仅症状→方名
    questions: generateClinicalQuestions(cardIds, count),
    currentQuestionIndex: 0,
    answers: [],
  });
}

function submitCurrentAnswer(userAnswer) {
  const q = appState.questions[appState.currentQuestionIndex];
  const isCorrect = judgeAnswer(userAnswer, q.correctAnswer);
  appState.answers.push({ ...q, userAnswer, isCorrect });
  appState.isFeedbackModalVisible = true;
  renderByState();
}

function nextQuestion() {
  appState.currentQuestionIndex++;
  appState.isFeedbackModalVisible = false;
  appState.isInputBoxVisible = false;
  if (appState.currentQuestionIndex >= appState.questions.length) {
    appState.isEndPanelVisible = true;
  }
  renderByState();
}
```

## 四、统一交互键位规范

### 4.1 全局键位定义

**核心原则**：每个键的语义在所有视图中保持一致。用户只需记住"这个键是干什么的"，不需要记住"在这个页面这个键是干什么的"。

| 键 | 全局语义 | 说明 |
|----|---------|------|
| **空格** | 确认 / 前进 | 选择卡片后 → 开始考试；答题后 → 下一题；弹窗中 → 确认并前进 |
| **Enter** | 提交 / 确认 | 输入框中 → 提交答案；弹窗中 → 确认 |
| **ESC** | 取消 / 退出 / 承认不会 | 输入框中 → 取消输入；弹窗中 → 关闭弹窗；考试中 → 标记"记不清楚" |
| **Tab** | 切换模式 | 方剂模式 ↔ 临床模式（仅在学习视图中有效） |
| **Q/W/E/R** | 选项 1/2/3/4 | 仅在选择题考试中有效 |
| **O** | 标为错 | 仅在反馈显示后有效 |
| **P** | 标为对 | 仅在反馈显示后有效 |

### 4.2 各视图下的键位行为

#### DASHBOARD 视图

| 键 | 行为 |
|----|------|
| 空格 | 进入 LEARN 视图（显示上次或第一张卡片） |
| Enter | 同空格 |
| ESC | 无操作 |
| Tab | 切换考试模式（仅更新左栏显示，不改变视图） |

#### LEARN 视图

| 键 | 行为 |
|----|------|
| 空格 | 根据当前模式开始考试：方剂模式 → `startFormulaExam()`；临床模式 → `startClinicalExam()` |
| Enter | 同空格 |
| ESC | 返回 DASHBOARD 视图 |
| Tab | 切换考试模式（更新左栏模式标签 + 顶部栏按钮文字） |

#### EXAM 视图（选择题 — 方剂模式）

| 键 | 行为 |
|----|------|
| Q/W/E/R | 选择选项 1/2/3/4（高亮选中） |
| 空格 | 如果未选选项 → 无操作；如果已选选项 → 提交答案；如果反馈已显示 → 下一题 |
| Enter | 如果未选选项 → 无操作；如果已选选项 → 提交答案 |
| ESC | 返回 LEARN 视图（需确认"放弃当前考试？"） |

#### EXAM 视图（输入题 — 临床模式）

| 键 | 行为 |
|----|------|
| 空格 | 如果输入框未展开 → 展开输入框并聚焦；如果输入框已展开 → 提交答案 |
| Enter | 如果输入框未展开 → 展开输入框并聚焦；如果输入框已展开 → 提交答案 |
| ESC | 如果输入框未展开 → 标记"记不清楚"（提交空答案）；如果输入框已展开 → 收起输入框 |

#### 反馈弹窗（所有模式通用）

| 键 | 行为 |
|----|------|
| 空格 | 关闭弹窗 → 下一题（如果是最后一题 → 显示结束面板） |
| Enter | 关闭弹窗 → 返回 LEARN 视图（继续看卡片） |
| ESC | 关闭弹窗 → 重新作答当前题（输入框清空） |

### 4.3 Enter/空格 语义分裂问题的修复

v6 中反馈弹窗的 Enter=返回、空格=下一题 → **语义分裂**。

v7 修复：

```
弹窗中的两个选择：
  空格 → 继续考试流程（"前进"语义，符合空格键在考试中的一贯行为）
  Enter → 返回学习卡片（"确认返回"语义，符合 Enter 的"确认"一贯行为）

用户在选择题中习惯了"空格=前进/下一题"，
在弹窗中空格仍然是"前进/下一题"——一致性保持。
```

### 4.4 键位实现

```javascript
document.addEventListener('keydown', (e) => {
  const k = e.key.toLowerCase();

  // 全局 Tab：切换模式
  if (k === 'tab') {
    e.preventDefault();
    toggleExamMode();
    return;
  }

  // 根据 page 分发
  switch (appState.page) {
    case 'dashboard': handleDashboardKeys(k, e); break;
    case 'learn':     handleLearnKeys(k, e);     break;
    case 'exam':      handleExamKeys(k, e);      break;
  }
});

function handleExamKeys(k, e) {
  // 反馈弹窗优先处理
  if (appState.isFeedbackModalVisible) {
    if (k === ' ')    { e.preventDefault(); closeModal(); nextQuestion(); return; }
    if (k === 'enter'){ e.preventDefault(); closeModal(); goToLearn(appState.activeCardId); return; }
    if (k === 'escape'){ e.preventDefault(); closeModal(); retryCurrentQuestion(); return; }
    return;
  }

  // 方剂模式（选择题）
  if (appState.examMode === 'formula') {
    if (['q','w','e','r'].includes(k)) { e.preventDefault(); selectOption(k); return; }
    if (k === ' ' || k === 'enter') { e.preventDefault(); submitAnswer(); return; }
  }

  // 临床模式（输入题）
  if (appState.examMode === 'clinical') {
    if (k === ' ' || k === 'enter') {
      e.preventDefault();
      if (!appState.isInputBoxVisible) showInputBox();
      else submitInputAnswer();
      return;
    }
    if (k === 'escape') {
      e.preventDefault();
      if (appState.isInputBoxVisible) hideInputBox();
      else submitEmptyAnswer(); // 标记"记不清楚"
      return;
    }
  }

  // 通用 ESC：返回学习
  if (k === 'escape') {
    e.preventDefault();
    if (confirm('确定要退出当前考试吗？')) goToLearn(appState.activeCardId);
  }
}
```

## 五、模式显性化设计

### 5.1 问题

v6 中用户按 Tab 切换临床/方剂模式，但：
- 模式标签在左栏顶部（容易被忽略）
- "考试这张卡"按钮文字不变（用户无法预测按下去是输入题还是选择题）

### 5.2 v7 方案

**三处显性化**：

```
1. 左栏顶部 — 模式标签（始终可见，加醒目底色）
   ┌─────────────────────┐
   │  📋 方剂模式        │ ← 蓝色高亮底色
   │  按 Tab 切换        │
   ├─────────────────────┤
   │  卡片列表...         │
   └─────────────────────┘

2. 顶部栏按钮 — 文字根据模式动态变化
   方剂模式：[📝 全向量考试（方剂）]
   临床模式：[📝 症状→方名考试（临床）]

3. 学习详情中 — 提示文字
   方剂模式：选中卡片后按空格 → 全向量选择题（5题）
   临床模式：选中卡片后按空格 → 症状→方名填空题（N题）
```

## 六、答案判定规范

### 6.1 问题

v6 中 `userAnswer.includes(card.name) || card.name.includes(userAnswer)` 过于宽松，输入"桂枝"即可匹配"桂枝汤"，输入"桂"也能通过。

### 6.2 方案：三级判定

```javascript
/**
 * 答案判定函数
 * @param {string} userAnswer 用户输入
 * @param {string} correctAnswer 正确答案（方名）
 * @returns {object} { isCorrect: boolean, level: 'exact'|'fuzzy'|'wrong', feedback: string }
 */
function judgeAnswer(userAnswer, correctAnswer) {
  const input = userAnswer.trim();

  // Level 1: 精确匹配
  if (input === correctAnswer) {
    return { isCorrect: true, level: 'exact', feedback: '回答正确！' };
  }

  // Level 2: 模糊匹配（去掉常见后缀后再比较）
  // 例如 "桂枝汤加减" → "桂枝汤"
  const normalized = normalizeFormulaName(input);
  if (normalized === correctAnswer) {
    return {
      isCorrect: true,
      level: 'fuzzy',
      feedback: `回答正确（你输入了"${input}"，标准方名为"${correctAnswer}"）`
    };
  }

  // Level 3: 包含匹配（用户输入包含正确方名，但有多余内容）
  if (normalized.includes(correctAnswer) && normalized.length > correctAnswer.length) {
    return {
      isCorrect: true,
      level: 'fuzzy',
      feedback: `包含正确答案"${correctAnswer}"，但你写的是"${input}"。注意方名应准确。`
    };
  }

  // 答错
  return { isCorrect: false, level: 'wrong', feedback: `正确答案是"${correctAnswer}"` };
}

/**
 * 标准化方名：去掉常见修饰词
 */
function normalizeFormulaName(input) {
  return input
    .replace(/[加减合方化裁汤散丸丹饮片剂][\u4e00-\u9fa5]*$/g, '')
    .replace(/^[《》""''「」『』]/g, '')
    .replace(/[《》""''「」『』]$/g, '')
    .trim();
}
```

### 6.3 判定级别对掌握度的影响

| 判定级别 | 是否算对 | 对 streak 的影响 | 反馈内容 |
|---------|---------|-----------------|---------|
| `exact` | 是 | `streak_right += 1` | "回答正确！" |
| `fuzzy` | 是 | `streak_right += 1`，但附加提示 | 提示用户注意方名准确性 |
| `wrong` | 否 | `streak_wrong += 1` | 显示正确答案 |

```

                                  ↓ 结束
                            ┌─────┴─────┐
                            ▼            ▼
                      LEARN（桂枝汤）  DASHBOARD
```

### 7.4 实现

```javascript
// 记录用户的导航来源
const navigationHistory = [];  // 最多保留 3 步

function navigateBack() {
  if (navigationHistory.length === 0) {
    goToDashboard();
    return;
  }

}
```

## 八、掌握度回路（闭环）

### 8.1 问题

v6 中掌握度全部硬编码。考试结果不影响掌握度显示，复习仪表盘的建议与用户行为完全无关。

### 8.2 v7 方案：前端存储 + 实时更新

**原型阶段简化方案**（不需要 WorkBuddy API）：

```javascript
// 考试结束后，更新本地掌握度缓存
function updateMasteryAfterExam(answers) {
  const card = getCard(appState.activeCardId);

  answers.forEach(a => {
    const vectorKey = a.vector;  // 如 '1→0'
    const m = card.mastery[vectorKey];
    if (!m) return;

    // 更新 streak
    if (a.isCorrect) {
      m.streak_right++;
      m.streak_wrong = 0;
    } else {
      m.streak_wrong++;
      m.streak_right = 0;
    }

    // 连续对3次 → 升级
    if (m.streak_right >= 3) {
      m.level = Math.min(5, m.level + 1);
      m.streak_right = 0;
      if (m.level >= 5) m.status = '已掌握';
    }

    // 连续错2次 → 降级
    if (m.streak_wrong >= 2) {
      m.level = Math.max(0, m.level - 1);
      m.streak_wrong = 0;
      m.status = m.level < 3 ? '已遗忘' : '正在学习';
    }

    // 记录历史
    m.last_result = a.isCorrect ? 'right' : 'wrong';
    m.last_review = new Date().toISOString().split('T')[0];
    m.history.push({ date: m.last_review, result: m.last_result });
    if (m.history.length > 10) m.history.shift();
  });

  // 保存到 localStorage
  saveMasteryToStorage();

  // 重新渲染掌握度
  renderMastery();
}
```

**完整版方案**（部署后）：通过 WorkBuddy API 写回 JSON 文件，见 v3.0 顶层设计 §6。
