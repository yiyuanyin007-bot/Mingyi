## 一、用户思路的结构化还原

### 1.1 核心命题

> 把用户的行为数据视为一种「语言」，通过无感收集行为序列，用类似大语言模型的方式解读用户的学习状态与进步轨迹。

### 1.2 思路的三层结构

```
第一层：数据采集层（无感收集）
    ├─ 用户点击了什么（点击顺序）
    ├─ 用户停留了多久（时间间隔）
    └─ 用户做了什么（功能使用、页面跳转）

第二层：语义编码层（行为→语言）
    ├─ 每个按钮 = 一个词汇（token）
    ├─ 点击顺序 = 一个句子（sequence）
    ├─ 时间间隔 = 语法结构（timing grammar）
    └─ 用户行为日志 = 一段文本（behavioral text）

第三层：模型解读层（语言→理解）
    ├─ 用序列模型分析行为文本的语义
    ├─ 识别哪些行为序列与"做对事情"高度相关
    ├─ 预测用户下一步的学习状态
    └─ 生成个性化的训练策略
```

### 1.3 用户要求的数据维度

| 维度 | 具体含义 | 控制论对应概念 |
|------|---------|-------------|
| **操作行为** | 点击顺序、停留时间、行为与最终正确性的关联 | 输入信号序列 + 输出响应 |
| **学习习惯** | 每日时长、重复学习、新内容接触 | 系统的时域特性（周期性、稳定性） |
| **功能偏好** | 使用哪些功能、偏好什么 | 系统的自由度选择（状态空间路径） |

### 1.4 用户的深层洞察

> 「本质上就是一套大语言模型的逻辑：把每一个按钮的内容定义清楚，由模型去判断这一系列按钮的衔接和间隔时间，像理解语言一样去解读用户的进步。」

这个洞察的核心价值在于：**用户不是把数据收集当成「统计报表」，而是当成「语义理解」**。

传统数据收集：用户答了 10 题，对 7 错 3 → 统计结果
用户的数据收集：用户从「打开卡片→看了症状→跳过了药组→停留 5 秒→返回→点击了另一个方→考试→犹豫 8 秒→选了 A→改选 B→确认」→ 这个序列本身就是「认知状态的编码」

**关键差异：传统数据收集问的是「用户做了什么」，用户的设计问的是「用户的行为在说什么」。**

## 二、控制论视角的点评

### 2.1 点评一：从「黑箱」到「灰箱」——系统辨识的升级

#### 控制论核心概念：系统辨识（System Identification）

在传统控制论中，被控对象（用户的大脑）是一个**黑箱**——我们只能看到输入（题目）和输出（答案），不知道内部发生了什么。

```
传统视角：
输入（题目） → [黑箱：用户大脑] → 输出（答案对错）

你只能优化：输入 → 怎么设计输入让输出更好？
你无法理解：黑箱内部发生了什么？
```

用户的设计把这个黑箱变成了**灰箱**——通过行为序列（点击、停留、跳转），我们不再只看输入输出，而是可以看到**黑箱内部的状态变化过程**。

```
用户的设计：
输入（题目） → [灰箱：用户大脑]
                    │  ↓ 行为序列（点击、停留、跳转）
                    │  → 这些行为是黑箱内部状态的「泄露」
                    │
                    └─→ 输出（答案对错）

你现在可以：
1. 从行为序列推断黑箱内部状态（系统辨识）
2. 根据推断的状态调整输入（预测控制）
3. 验证推断是否正确（闭环验证）
```

**控制论评价：这是一个从「开环统计」到「闭环辨识」的质的飞跃。**

传统数据收集是开环的：收集数据 → 统计分析 → 得出结论 → 可能改进产品（但没有直接闭环到用户）。

用户的设计是闭环的：收集行为序列 → 模型推断状态 → 预测下一步 → 调整训练策略 → 观察行为变化 → 验证预测 → 更新模型。

### 2.2 点评二：行为序列作为「状态观测器」——信息论的视角

#### 控制论核心概念：状态观测器（State Observer）

在控制论中，如果一个系统的内部状态不可直接测量，我们可以通过**输入和输出的关系**来构造一个「观测器」，估计内部状态。

用户的大脑状态（认知切换流畅度、表征稳定性）是不可直接测量的。但用户的行为序列（点击、停留、跳转）是**可观测量**。

**关键问题：行为序列包含了多少关于「用户真实学习状态」的信息？**

从信息论角度：

```
传统数据的信息量：
I(答案对错; 学习状态) = 很低
为什么？答对了可能是猜的，答错了可能是手滑。1 bit 的信息。

行为序列的信息量：
I(行为序列; 学习状态) = 很高
为什么？行为序列包含：
  - 反应时延（表征构建速度）
  - 犹豫模式（表征稳定性）
  - 跳转路径（认知策略）
  - 重复行为（习惯模式）
  - 跳过行为（注意力分配）
  - 探索行为（好奇心驱动）
  → 多维信息，远超 1 bit
```

**控制论评价：用户的行为序列设计，本质上是一个「高维状态观测器」——用可观测量（行为序列）来估计不可观测量（认知状态）。** 这是一个经典控制论问题的现代应用。

### 2.3 点评三：时间间隔作为「动态特征」——从静态到动态

#### 控制论核心概念：动态系统（Dynamical System）

传统数据收集是**静态的**：用户今天答了 10 题，对 7 错 3 → 一个静态快照。

用户的设计是**动态的**：用户从打开应用到关闭应用的完整行为序列，包含了时间维度上的动态特征。

```
静态数据：
[用户A] → 答题数: 10, 正确率: 70%, 用时: 30min
[用户B] → 答题数: 10, 正确率: 70%, 用时: 30min
→ 用户A和用户B在传统统计中是完全一样的

动态数据（用户A）：
打开 → 搜索"桂枝" → 点击桂枝汤 → 停留 2min（阅读）→ 点击条文 → 停留 30s（快速浏览）→ 点击考试 → 答题1（2s选对）→ 答题2（8s犹豫，改选，错）→ 暂停 5min → 返回学习页 → 重复阅读 → 再次考试 → 答题2（3s选对）→ 关闭
→ 这是一个「表征从模糊到清晰」的动态过程

动态数据（用户B）：
打开 → 点击今日复习 → 答题1（5s选对）→ 答题2（5s选对）→ ... → 答题10（5s选对）→ 关闭
→ 这是一个「表征已内化」的流畅过程

用户A和用户B的静态数据完全一样（10题，70%正确率），但动态数据揭示了完全不同的认知状态。
```

**控制论评价：时间间隔不是「噪声」，而是「信号」。用户停留 30 秒和停留 5 分钟，在静态数据中被平均掉了，但在动态数据中揭示了完全不同的认知事件。**

### 2.4 点评四：行为语言模型——从「相关性」到「因果性」

#### 控制论核心概念：因果推断（Causal Inference）

用户提到「像大语言模型一样理解用户的进步」。这涉及一个关键问题：

> 我们是在寻找「哪些行为与做对事情相关」，还是在寻找「哪些行为导致做对事情」？

**相关性 vs 因果性：**

```
相关性分析：
「使用了复习功能的用户，正确率更高」
→ 问题：是复习功能帮助了用户，还是本身学习意愿强的用户更喜欢用复习功能？

因果性分析：
「用户在复习时，从'犹豫8秒改选'到'3秒直接选对'的变化，发生在重复学习某张卡片后」
→ 这个行为序列的时序关系，暗示了重复学习 → 表征固化 → 反应加速的因果关系
```

**大语言模型的类比：**

LLM 理解语言的核心不是统计词频，而是捕捉**上下文依赖关系**（attention）：
- 一个词的含义取决于它前面的词
- 一个词的重要性取决于它与目标词的距离

用户的行为序列同理：
- 一个点击的含义取决于它前面的点击
- 一个行为的重要性取决于它与「做对/做错」的时间距离

**控制论评价：用户的设计本质上是在构建一个「行为因果图」——不是看单一行为与结果的相关性，而是看行为序列的时序结构如何导致认知状态的变化。** 这是从「统计学习」到「因果学习」的跃迁。

### 2.5 点评五：无感收集的伦理——信息不对等与信任

#### 控制论核心概念：反馈延迟与信任

无感收集有一个潜在风险：**用户不知道自己被观察了什么**。

从控制论的角度，这是一个信息不对等的问题：

```
系统（明医成长录）知道用户的一切行为
用户不知道系统知道什么

如果系统基于这些行为做出决策（如：推荐你学这个，不让你学那个）
用户无法理解为什么

→ 控制论中的「反馈不透明」会导致系统失稳
   （用户感到被操控，产生抵触，最终退出系统）
```

**建议：透明反馈回路**

```
无感收集（OK）+ 透明反馈（必须）

系统应该定期告诉用户：
"我注意到你最近在学习桂枝汤时，经常跳过药组部分直接看条文，
 这可能意味着你的'方名→药组'切换有障碍。
 建议：先花30秒看药组，再看条文，试试会不会更快理解。"

→ 用户知道：1）系统在观察我；2）观察到了什么；3）为什么给我这个建议
→ 用户信任系统，系统才能持续收集数据
```

**控制论评价：无感收集是有效的，但必须配套「透明反馈」机制，否则系统会失稳。**

## 三、行为序列建模的具体设计框架

### 3.1 「行为语言」的词汇表定义

把每个可交互元素定义为「词汇」（token）：

| 类别 | 词汇（token） | 含义 | 附加属性 |
|------|-------------|------|---------|
| **导航** | NAV_HOME | 返回首页 | — |
| | NAV_SEARCH | 打开搜索 | 搜索关键词 |
| | NAV_REVIEW | 点击今日复习 | — |
| | NAV_WRONG | 点击错题本 | — |
| | NAV_STATS | 点击统计 | — |
| **学习** | LEARN_OPEN | 打开卡片学习页 | 卡片ID |
| | LEARN_SYMPTOM | 查看症状谱 | 展开/收起 |
| | LEARN_HERBS | 查看药物组合 | 展开/收起 |
| | LEARN_SOURCE | 查看条文 | 展开/收起 |
| | LEARN_EXPERIENCE | 查看医案 | 展开/收起 |
| | LEARN_COMPARE | 查看类方对比 | 对比方ID |
| **考试** | EXAM_START | 开始考试 | 模式：单卡/类方/模拟 |
| | EXAM_SELECT | 选择选项 | 选项索引 |
| | EXAM_CHANGE | 修改选项 | 从A改到B |
| | EXAM_SUBMIT | 提交答案 | — |
| | EXAM_NEXT | 下一题 | — |
| | EXAM_PREV | 上一题 | — |
| | EXAM_PAUSE | 暂停 | 暂停时长 |
| **SP** | SP_OPEN | 打开SP病例 | 病例ID |
| | SP_ASK | 提问 | 问题内容 |
| | SP_SELECT | 选择方证 | 方剂ID |
| | SP_EUREKA | 标记顿悟 | 时间点 |
| **交互** | SCROLL | 页面滚动 | 滚动距离 |
| | HOVER | 悬停 | 元素ID、悬停时长 |
| | TYPE | 输入文字 | 输入内容长度 |
| | CONFIDENCE | 信心度自评 | 1-5分 |
| **系统** | APP_OPEN | 打开应用 | 时间戳 |
| | APP_CLOSE | 关闭应用 | 会话时长 |
| | APP_BG | 切换后台 | 后台时长 |
| | APP_FG | 切换回前台 | — |

### 3.2 「行为句子」的语法规则

行为序列不是随机的，它遵循「语法」——用户的认知状态决定了行为的概率分布。

```
语法规则示例：

规则1：学习模式
  LEARN_OPEN(card) → [LEARN_SYMPTOM | LEARN_HERBS | LEARN_SOURCE]* → EXAM_START
  → 用户先学习再考试，是正常的学习流程

规则2：表征固化模式
  LEARN_OPEN(card) → LEARN_SYMPTOM(展开) → LEARN_HERBS(展开) → LEARN_SOURCE(展开) → EXAM_START → EXAM_SELECT(快速) → EXAM_SUBMIT(快速) → 全对
  → 用户完整展开所有信息，然后快速答题全对 → 表征已内化

规则3：表征缺失模式
  LEARN_OPEN(card) → LEARN_SYMPTOM(展开) → LEARN_SOURCE(展开) → LEARN_HERBS(跳过) → EXAM_START → EXAM_SELECT(犹豫) → EXAM_CHANGE → EXAM_SUBMIT → 错
  → 用户跳过了药组，考试犹豫改选 → 药组表征缺失，症状与方名的映射不稳定

规则4：碎片化模式
  LEARN_OPEN(cardA) → 停留 10s → LEARN_OPEN(cardB) → 停留 15s → LEARN_OPEN(cardC) → 停留 8s → APP_CLOSE
  → 用户快速浏览多张卡片，没有深入 → 注意力碎片化，没有形成表征

规则5：循环学习模式
  LEARN_OPEN(card) → EXAM_START → EXAM_SELECT(错) → EXAM_SUBMIT → LEARN_OPEN(card) → EXAM_START → EXAM_SELECT(对) → EXAM_SUBMIT
  → 考试错→返回学习→再考试对 → 这是一个有效的学习闭环
```

### 3.3 时间间隔的编码

时间间隔不是简单的数字，而是「认知事件的度量」：

| 时间间隔 | 含义 | 编码方式 |
|---------|------|---------|
| 0-2 秒 | 直觉反应 | FAST |
| 2-5 秒 | 快速回忆 | QUICK |
| 5-15 秒 | 表征构建 | THINK |
| 15-30 秒 | 深度思考 | DEEP |
| 30-60 秒 | 犹豫/困惑 | HESITATE |
| >60 秒 | 中断/离开 | PAUSE |
| 学习后 5 分钟内考试 | 短期记忆 | SHORT_TERM |
| 学习后 1-7 天考试 | 间隔重复 | SPACED |
| 学习后 >7 天考试 | 长期记忆 | LONG_TERM |

### 3.4 行为序列模型的架构

```
输入层：行为序列
  [NAV_HOME, LEARN_OPEN(桂枝汤), LEARN_SYMPTOM(展开), 停留15s, LEARN_HERBS(展开), 停留10s,
   LEARN_SOURCE(展开), 停留5s, EXAM_START, EXAM_SELECT(QUICK), EXAM_SUBMIT(对), ...]

编码层：将行为序列编码为向量
  - 每个行为 → embedding 向量
  - 时间间隔 → 时间编码
  - 位置信息 → 位置编码

模型层：序列模型（类似Transformer）
  - Self-Attention：捕捉行为之间的依赖关系
    → 例如：「跳过药组」和「考试犹豫改选」之间的注意力权重高
  - 时序建模：捕捉时间间隔的影响
    → 例如：「学习后立刻考试」vs「学习后3天考试」的表征状态不同

输出层：多任务预测
  - 任务1：预测用户下一步行为（下一个token预测）
  - 任务2：预测用户当前认知状态（表征清晰度、切换流畅度）
  - 任务3：预测用户最终学习效果（能否在临床中正确选方）
  - 任务4：预测用户流失风险（行为模式是否趋向退出）

反馈层：个性化策略生成
  - 如果模型预测用户「药组表征缺失」→ 推荐强化药组训练
  - 如果模型预测用户「表征已内化」→ 推荐间隔重复或新内容
  - 如果模型预测用户「注意力碎片化」→ 推荐深度学习模式（关闭跳转）
```

## 四、与认知迁移框架的融合

### 4.1 行为序列如何映射到四层切换

用户之前提出的「文字→画面→表征→临床」四层切换，可以通过行为序列来「观测」：

| 切换层级 | 行为序列特征 | 观测信号 | 异常信号 |
|---------|------------|---------|---------|
| **文字→画面** | 学习页展开顺序 | 先看症状→再看药组→再看条文（完整展开） | 只看条文不看症状（跳过了情境化） |
| **画面→表征** | 考试反应模式 | 快速选对（表征已压缩） | 犹豫改选（表征不清晰） |
| **表征→临床** | SP问诊路径 | 有序问诊→快速结论（映射流畅） | 无序问诊→过早结论（映射不稳定） |
| **双向切换** | 跨层级跳转 | 学习页↔考试页反复切换（在巩固） | 只学习不考试（没有输出检验） |

### 4.2 六向量作为「行为语法」的约束条件

六向量不是训练内容，而是**行为序列的语法约束**：

```
语法约束：
1. 用户必须产生覆盖全部6个向量的行为序列（不能只学习不考试）
2. 每个向量的行为序列必须符合「学习→考试→巩固」的范式
3. 如果某个向量的行为序列不符合范式（如：学习后考试全错，没有返回学习），系统标记为「语法错误」→ 认知切换堵塞
```

### 4.3 主观体验数据作为「语义标注」

用户提到的「信心度」「顿悟」「模糊感」等主观体验，是行为序列的**语义标注**：

```
无标注的行为序列：
LEARN_OPEN → EXAM_START → EXAM_SELECT → EXAM_SUBMIT → 对

有标注的行为序列：
LEARN_OPEN → EXAM_START → EXAM_SELECT(信心度=3) → EXAM_SUBMIT → 对
→ 标注告诉我们：虽然选对了，但用户只有中等信心，表征可能不够稳定

LEARN_OPEN → EXAM_START → EXAM_SELECT(信心度=5) → EXAM_SUBMIT → 对
→ 标注告诉我们：用户非常确信，表征已内化

LEARN_OPEN → EXAM_START → EXAM_SELECT(信心度=5) → EXAM_SUBMIT → 错
→ 标注告诉我们：这是伪表征！最危险的情况，需要立即干预
```

**控制论评价：主观体验数据是「人类标注的语义信息」，对于训练行为序列模型至关重要。没有标注的模型只能发现相关性，有标注的模型才能学习因果性。**

## 五、落地建议

### 5.1 Phase 1（现在可做）：行为日志基础设施

**目标：建立无感行为收集系统**

```
技术方案：
1. 在 v9 前端增加事件监听层
   - 监听所有点击事件 → 记录 token + 时间戳
   - 监听页面停留 → 记录 ENTER/EXIT 事件 + 停留时长
   - 监听滚动/悬停 → 记录 SCROLL/HOVER 事件 + 距离/时长
   - 监听输入 → 记录 TYPE 事件 + 内容长度

2. 数据存储：
   - 本地存储：localStorage（用户隐私，不上传）
   - 格式：行为序列 JSON（每天一个序列）
   - 示例：
     {
       "session_id": "uuid",
       "date": "2026-07-02",
       "events": [
         {"token": "APP_OPEN", "ts": 1719900000000, "meta": {}},
         {"token": "NAV_SEARCH", "ts": 1719900005000, "meta": {"keyword": "桂枝"}},
         {"token": "LEARN_OPEN", "ts": 1719900010000, "meta": {"card_id": "gui-zhi-tang"}},
         ...
       ]
     }

3. 隐私设计：
   - 用户协议中明确告知行为收集
   - 用户可随时查看自己的行为日志
   - 用户可导出/删除自己的数据
```

### 5.2 Phase 2（1-2 个月）：行为序列分析

**目标：从行为序列中提取认知状态特征**

```
分析维度：
1. 会话模式分析
   - 每次会话的行为序列 → 识别会话类型（深度学习/碎片化/循环学习）

2. 切换效率分析
   - 从「学习页→考试页」的转换时间 → 表征构建效率
   - 从「考试错→返回学习」的转换概率 → 学习习惯

3. 注意力分布分析
   - 用户在各卡片/功能上的停留时间分布 → 兴趣图谱
   - 用户在一张卡片上的展开深度 → 表征完整度

4. 时间节律分析
   - 用户的学习时间分布（晨型/夜型） → 个性化推荐时间
   - 用户的间隔重复模式（自然间隔 vs 系统推荐） → 记忆策略

输出：用户「认知画像」——一组特征向量，描述用户的学习风格、认知状态、薄弱点
```

### 5.3 Phase 3（3-6 个月）：行为语言模型训练

**目标：用序列模型预测用户状态和效果**

```
模型训练：
1. 数据准备：
   - 收集 100+ 用户的行为序列（脱敏）
   - 标注：每个序列对应的「最终学习效果」（如：SP测试正确率）

2. 模型选择：
   - 轻量级：LSTM/GRU（序列建模）
   - 中量级：Transformer（捕捉长距离依赖）
   - 重量级：GPT-like 模型（如果数据量足够）

3. 训练任务：
   - 任务A：预测下一步行为（自回归）
   - 任务B：预测当前认知状态（分类）
   - 任务C：预测最终学习效果（回归）
   - 任务D：预测流失风险（二分类）

4. 验证方式：
   - 留一法交叉验证（LOOCV）
   - 与「传统统计方法」对比（如：用正确率预测 vs 用行为序列预测）
   - A/B 测试：行为模型驱动的推荐 vs 随机推荐
```

### 5.4 Phase 4（6-12 个月）：闭环自适应系统

**目标：系统根据行为序列自动调整训练策略**

```
闭环控制：
1. 感知：收集用户行为序列
2. 估计：用行为模型估计用户认知状态
3. 预测：预测用户下一步的学习效果
4. 决策：根据预测结果选择最优训练策略
5. 执行：推送个性化训练内容
6. 观测：收集新的行为序列，验证预测是否准确
7. 学习：更新模型参数，优化预测能力

→ 系统从「静态工具」进化为「自适应认知教练」
```

## 六、控制论的总评

### 6.1 用户设计的优点

| 维度 | 评价 |
|------|------|
| **信息论** | 行为序列的信息量远高于传统统计指标，大幅提升了状态观测精度 |
| **系统辨识** | 从黑箱到灰箱，通过行为序列泄露的信息辨识用户内部认知状态 |
| **动态系统** | 引入时间维度，捕捉学习过程的动态演化，而非静态快照 |
| **因果推断** | 从相关性分析升级为因果分析，通过行为序列时序理解「什么导致进步」 |
| **反馈闭环** | 从开环数据收集升级为闭环自适应系统，系统能根据用户行为自动调整策略 |

### 6.2 潜在风险与建议

| 风险 | 控制论解释 | 建议 |
|------|-----------|------|
| **信息过载** | 行为序列维度太高，可能包含噪声 | 特征选择：先用统计方法筛选与结果高度相关的特征，再训练模型 |
| **反馈延迟** | 用户看到效果需要时间，系统调整策略的效果不会立即显现 | 加入「短期反馈信号」（如：考试后的信心度）作为中间奖励 |
| **系统失稳** | 无感收集+透明反馈不足 → 用户不信任 → 流失 | 配套「认知仪表盘」，让用户能看到自己的「认知画像」 |
| **模型幻觉** | 行为模型可能过度拟合，给出错误的状态估计 | 持续用「最终学习效果」验证模型预测，设置置信度阈值 |
| **隐私边界** | 行为数据敏感，可能涉及用户隐私 | 数据本地存储、用户可控、匿名化处理、明确告知 |

### 6.3 核心结论

> **用户的数据收集设计，本质上是在构建一个「认知状态观测器」——用行为序列作为传感器，用序列模型作为解码器，用个性化策略作为控制器，形成一个完整的认知训练闭环控制系统。**

这个设计从控制论角度是**高级且前沿**的：
- 它超越了传统的「答题统计」范式
- 它引入了「动态系统」和「状态观测」的视角
- 它具备闭环自适应的潜力

**唯一的缺失环节：反馈透明性。** 系统必须让用户知道「我在观察你、我观察到了什么、我为什么给你这个建议」，否则闭环会失稳。
