# 经方学习系统 · 条文系统差距评估报告

> 评估基准：三层锚定模型（方证基础层 → 多维注解层 → 临床验证层）
> 评估日期：2026-06-17
> 数据来源：formula_cards.json / source_cards.json / experience_cards.json / app/index.html

---

## 一、目标定义（三层锚定模型）

| 层级 | 目标内容 | 核心要求 |
|---|---|---|
| **第一层** | 方证基础层 | 35 张 source_cards 精确条文 + 编号 + 症状谱，与 formula_cards 一一对应 |
| **第二层** | 多维注解层 | 老师笔记（刘渡舟/胡希恕）+ 类方鉴别 + 条文辨析，按 mastery level 解锁 |
| **第三层** | 临床验证层 | 独立 experience_cards 医案体系 + 症状频率统计 + 临床解锁 |
| **机制层** | 数据链路 | 分级解锁（Level 2→注解，Level 4→医案）+ 症状→条文反向索引 + 数据反哺 |

## 四、关键瓶颈（按阻塞性排序）

### 🔴 瓶颈1：独立医案体系空白（阻塞第三层）
- **现状**：experience_cards.json 仅 3 张，33/35 方剂的 experience_ids 为空。
- **影响**：无法建立「条文→临床」的完整链路，第三层几乎不存在。
- **解决**：从黄煌沙龙提取 35 方相关医案，生成结构化 experience_cards。

### 🔴 瓶颈2：分级解锁机制为零（阻塞机制层）
- **现状**：有 `unlock_level` 字段，但无任何代码使用它。所有内容直接展示。
- **影响**：违背了「渐进式学习」原则，学习者一次性看到所有信息，无法形成「复习→解锁→深入」的闭环。
- **解决**：在 index.html 的卡片详情渲染中增加 `if (masteryLevel >= unlockLevel)` 的条件展示。

### 🟡 瓶颈3：数据架构不一致（阻塞第二层深化）
- **现状**：注解数据（teacher_notes / clinical_cases / source_annotations）内嵌在 formula_cards 中，而非 source_cards 中。
- **影响**：违背了「以条文编号为根键」的设计。当同一方剂对应多条条文时，注解无法分别归属。
- **解决**：将 source_annotations 迁移到 source_cards 的 `annotations` 字段中，或建立独立 `annotations.json`。

### 🟡 瓶颈4：一方多条文缺失（阻塞第一层深化）
- **现状**：1 张 formula_card 只关联 1 张 source_card。
- **影响**：桂枝汤只展示第13条，学习者看不到第12、53、54、95等条的补充或变证。
- **解决**：扩展 `source_text_ids` 为数组，接入多条相关条文。

### 🟢 瓶颈5：症状反向索引空白（长期优化）
- **现状**：无「症状→条文」索引。
- **影响**：测试干扰项不够临床化，「症状→方名」向量训练质量受限。
- **解决**：从 source_cards 和 experience_cards 中提取症状索引，生成独立 JSON。

## 五、下一步建议（按优先级）

### 阶段A：填补最大缺口（2-3 天）
1. **从黄煌沙龙提取医案** → 生成 30+ 张 experience_cards，关联到条文编号。
2. **在 index.html 实现分级解锁** → 根据 mastery.level 控制 teacher_notes / clinical_cases 的展示。

### 阶段B：架构修正（3-5 天）
3. **一方多条文** → 为桂枝汤、麻黄汤等核心方剂扩展 source_text_ids。
4. **建立独立 annotations.json** → 将 source_annotations 从 formula_cards 中剥离，按需加载。

### 阶段C：机制完善（长期）
5. **症状反向索引** → 生成 symptom_index.json。
6. **症状频率统计** → 从黄煌医案提取频率，反哺 symptom_profile。

## 六、结论

> **当前条文系统完成了「骨架+部分内容」的 60%，但第三层（临床验证）和机制层（分级解锁）几乎是空白。**

如果目标是「让学习者从背诵条文到看到临床验证的完整链路」，那么：
- **第一层**（方证基础）已可用，只差「一方多条文」。
- **第二层**（注解）数据已大量准备，只差**架构修正**和**分级展示**。
- **第三层**（临床）是**最大瓶颈**，需要投入最多工程量。

**最务实的下一步**：
> 先解决**瓶颈2（分级解锁）**和**瓶颈1（医案提取）**。前者是代码问题（1-2天），后者是数据问题（2-3天）。这两个解决后，系统就能实现「条文→注解→医案」的渐进式学习链路，达到「周二可用」的临床训练目标。
