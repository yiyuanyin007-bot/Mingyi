# 循证修正意见添加方案 · 文档

> **版本**：v1.0  
> **日期**：2026-06-22  
> **适用范围**：已通过审计且需修正的笔记（当前：小建中汤）；零修正通过的可选标注（当前：桂枝汤）  
> **前置条件**：审计报告已生成，审计智能体验证意见已确认

---

## 一、背景

目前循证审计流程已跑通 3 张卡片：

| 卡片 | 审计状态 | 修正项数 | 当前问题 |
|------|---------|---------|---------|
| 小建中汤 | 已通过（修正后再验证） | **5 项** | 修正意见沉睡在审计报告里，用户打开笔记看不到 |
| 桂枝汤 | 已通过（0 修正） | 0 | 用户不知道这张卡片已获循证验证 |
| 麻黄汤 | 待验证 | 3 | 待审计智能体验证后处理 |

**核心矛盾**：审计报告（`docs/evidence/reports/xxx_evidence_audit.md`）和修正意见（`CORR-xxx`）与用户日常查看的笔记（`localStorage`）物理分离。用户打开卡片看到的是「纯净版笔记」，看不到循证团队留下的修正意见，导致：
- 可能继续使用已标记为「可疑」的表述（如杏仁苷的氰化物机制）
- 不知道哪部分内容已获高质量文献支持、哪部分存疑
- 无法对修正意见进行「接受/拒绝/讨论」的交互

本方案解决：将修正意见直接追加到笔记正文下方，让用户在原生使用场景中可见、可交互。

## 二、技术操作方案（怎么改）

### 2.1 数据源定位

笔记存储在 **localStorage 8100 端口**，键名 `A01_card_notes`，JSON 结构：

```json
{
  "notes": {
    "xiao-jian-zhong-tang": {
      "cardId": "xiao-jian-zhong-tang",
      "cardName": "小建中汤",
      "content": "# 笔记正文..."
    }
  }
}
```

### 2.2 修改方式（推荐：WebBridge `evaluate` 注入）

**方式 A：WebBridge evaluate（推荐，无刷新持久化）**

```powershell
# 1. 读取当前笔记内容
# 2. 在 content 末尾追加修正区块
# 3. 通过 evaluate 写回 localStorage
```

**方式 B：本地 JSON 编辑后覆写（备份优先）**

1. 先用 `governance.py backup` 备份当前笔记到 `data/archive/`
2. 用 Python 脚本读取 `webbridge-mht.json` 格式的导出文件
3. 追加修正内容后，通过 WebBridge 或手动导入写回

**方式 C：用户手动复制粘贴（保底方案）**

1. 生成修正内容 Markdown
2. 保存为 `.md` 文件
3. 用户手动打开卡片笔记，滚动到末尾，粘贴

**本方案推荐：方式 A（WebBridge 自动注入）+ 方式 B（本地备份）双重保险。**

### 2.3 修改范围原则

| 原则 | 说明 |
|------|------|
| **只追加、不修改原文** | 绝不改动笔记原有正文，仅在末尾追加修正区块。保留原文完整性，避免破坏用户信任。 |
| **版本标识** | 追加区块内包含「循证审计版本号」和「修正日期」，确保用户知道这是哪一轮审计的意见。 |
| **可折叠** | 使用 HTML `<details>` 标签或 Markdown 区块，默认折叠，用户手动展开，不干扰正常阅读。 |
| **可撤销** | 追加内容有明确的「开始/结束」标记，如需撤销，可以精确删除该区块。 |

## 四、用户可见性设计（怎么看）

### 4.1 默认视图

用户打开卡片笔记时，看到的是完整的笔记 + 底部的修正区块。由于使用 `---` 水平分隔线 + 二级标题 `##【循证修正意见】`，视觉上与正文有明显的区分：

```
[笔记正文]
.
.
.
---
【循证修正意见】 ← 明确的分界线，用户不会误以为是正文
```

### 4.2 视觉提示（可选增强）

在笔记系统的 UI 中，如果支持自定义 CSS，可为修正区块添加：

- 左侧边框：淡蓝色竖线（表示「信息/提示」）
- 背景色：浅灰色（与正文区分）
- 字体大小：略小（0.95em）
- 顶部标签：「循证修正意见 · 已通过验证」

但当前版本是纯 Markdown 单文件系统，**上述 CSS 增强暂不可用**，仅通过 Markdown 格式本身实现区分。

### 4.3 用户交互（远期设想）

在后续版本（v9 或组件化重构）中，可考虑：
- 在笔记底部添加「循证」Tab，切换显示/隐藏修正意见
- 每条修正意见旁有「✅ 采纳」「❌ 忽略」「💬 讨论」按钮
- 用户采纳后，修正内容可自动同步到正文（但仍保留原文备份）

## 六、执行步骤（操作手册）

### 步骤 1：确认审计状态

- 读取 `docs/evidence/task_board.md`
- 确认卡片状态为「已通过」或「需修正」
- 读取对应审计报告（`docs/evidence/reports/xxx_evidence_audit.md`）
- 提取修正项（`CORR-xxx` 或 `## 六、严重问题`）

### 步骤 2：备份当前笔记

```bash
python scripts/governance.py backup "localStorage:xiao-jian-zhong-tang" "追加循证修正意见前备份"
```

或通过 WebBridge 导出 JSON 后复制到 `data/archive/`。

### 步骤 3：生成修正内容

基于审计报告中的修正记录，按 3.1 模板格式化，生成 Markdown 字符串。

### 步骤 4：注入笔记

**方式 A（WebBridge）**：

```powershell
# 通过 evaluate 读取当前笔记 → 追加修正内容 → 写回 localStorage
# 具体脚本见：scripts/inject_correction.py（可新建）
```

**方式 B（手动）**：

1. 通过 WebBridge 导出当前笔记内容
2. 在本地文本编辑器中追加修正内容
3. 通过 WebBridge 的 fill 或 evaluate 写回

### 步骤 5：验证注入结果

- 刷新卡片页面，滚动到笔记底部
- 确认修正区块正常显示
- 检查格式无错乱（标题层级、表格、分隔线）

### 步骤 6：登记 CHANGELOG

```bash
python scripts/governance.py entry "小建中汤笔记追加循证修正意见（5项）" "localStorage:xiao-jian-zhong-tang"
```

## 七、风险与应对

| 风险 | 可能性 | 应对措施 |
|------|--------|---------|
| WebBridge 注入失败 | 中 | 事先导出完整 JSON 备份；失败时手动复制粘贴 |
| 修正内容格式错乱 | 低 | 注入前先在本地 Markdown 编辑器预览；使用 `governance.py check-json` 验证 |
| 用户误将修正区块当作正文引用 | 低 | 修正区块使用明确的 `<!-- 循证修正意见开始/结束 -->` 标记，视觉上以 `---` 分隔 |
| 修正意见与正文冲突 | 低 | 修正意见只追加不修改原文，冲突风险极小；如有冲突，用户可在修正区块中标注 |

## 八、待讨论事项

1. **是否对零修正卡片（桂枝汤）追加「验证标注」？**
   - 方案 A：追加（让用户知道这张卡片已获循证验证）
   - 方案 B：不追加（保持笔记纯净，避免信息冗余）

2. **修正区块的默认状态：展开 vs 折叠？**
   - 方案 A：展开（用户一滚动到底部就看到，避免遗漏）
   - 方案 B：折叠（使用 HTML `<details>` 或自定义折叠语法，避免干扰阅读）

3. **修正意见是否同步回审计报告？**
   - 方案 A：不同步（审计报告是「过程记录」，笔记是「最终交付」）
   - 方案 B：同步追加（审计报告末尾也记录「已注入笔记」的确认信息）

4. **是否需要用户确认后注入？**
   - 方案 A：自动注入（已通过审计的修正项，直接追加到笔记）
   - 方案 B：用户确认（先生成预览，用户确认后执行注入）
