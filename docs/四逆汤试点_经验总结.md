## 一、资料清洗层

### 1.1 原始 Markdown 的可读性问题很普遍

不仅是倪海厦资料，黄煌 CHM 转出的 Markdown 也存在：

- 段落被无意义换行切断，阅读连贯性差。
- 条文编号 `(61)`、`(十)` 等分散在正文中间。
- 配方、主治、按语、现代应用混在一段。
- 没有章节标题，只能靠 `●` 之类的符号硬分隔。

**结论**：对于要挂到前端“查看原文”的资料，必须进行 Markdown 重排，否则用户点进去会觉得“这还不如不看”。

### 1.2 重排标准（v2 标准）

以 `附子_v2.md` 为样板，后续药证/言论清洗应遵循：

1. **保留 frontmatter**，新增 `cleaned_v2_path`、`cleaned_v2_date`、`word_count_v2`。
2. **使用 Markdown 多级标题**：一、二、三级标题清晰分层。
3. **条文编号保持原样**：用 `(61)`、`(十)`，不要做上标或奇怪符号。
4. **配方统一四段式**：组成 / 主治 / 现代应用 / 来源。
5. **方根用表格**：如附子-干姜-甘草一行，主治一行，代表方一行。
6. **药证发挥分小节**：脉、痛、禁忌、配伍、生炮等。

### 1.3 讲座类资料不适合直接挂原文

倪海厦 `人纪-伤寒论_cleaned.txt` 是口语讲座记录，噪音大、段落边界不清。直接挂链接会导致可读性极差。

**结论**：讲座类资料应做“主题提取”——把与某方相关的内容摘出来，生成一个独立的、有结构的 Markdown，再挂链接。不要让用户在几万字噪声里自己找。

## 二、结构化抽取层

### 2.1 `_structured.json` 很有价值

`附子_structured.json` 把原文中的 22 个含附子方剂、10 组方根、剂量、煎服法等全部结构化。

后续用途：

- 直接生成/更新方剂卡的 `references`。
- 作为出题系统的素材库（症状→方、方→症状、类方鉴别）。
- 作为记忆模型冲突检测的数据源。

### 2.2 抽取规则需要人工校验

自动抽取容易把“用量同方名含义”这类模糊表达也写进去，需要人工过一遍。

## 三、前端与链接层

### 3.1 “查看原文”必须指向可读版本

用户会真的点。如果点进去是未清洗的原始稿，会严重破坏学习体验。

**做法**：

- 已清洗的 → 指向 `_v2.md`。
- 讲座类 → 指向主题提取后的独立 Markdown。
- 原始文件保留，作为 archive，不用于前端展示。

### 3.2 “打开所在文件夹”的折中方案

浏览器无法从 `http://localhost` 直接打开 `file://` 本地文件夹。目前用本地 HTTP 服务的目录浏览功能替代，能列出文件夹内文件。后续如需更好体验，可考虑：

- 在 UI 上只保留“查看原文”。
- “打开文件夹”作为测试功能，后续删除。

### 3.3 经验卡 bug 要修

`getExperience(id)` 原先写成 `e.id === e.id`，永远返回第一条经验。这个 bug 会导致经验卡显示错误，已修复。

## 四、工作流经验

### 4.1 用 subagent 做格式化是可行的

`附子.md` 的重排和 JSON 抽取用 subagent 完成，效果较好，但输出需要人工抽查。

### 4.2 先做样板，再批量

不要一次性清洗所有文件。先做一个样板（附子），确认格式后再批量复制到甘草、干姜、经方言论等。

### 4.3 references 的 source_path 要及时同步

生成了 `_v2.md` 后，必须同步更新 `formula_cards.json` 中的 `source_path`，否则前端仍指向旧文件。
