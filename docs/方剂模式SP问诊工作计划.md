## 二、方剂模式 vs 条文模式 技术差异分析

### 2.1 核心差异

| 维度 | 条文模式（当前） | 方剂模式（目标） |
|------|----------------|------------------|
| 学生作答 | 选择条文编号（如第12条） | 选择方名（如桂枝汤） |
| 干扰项设计 | 相邻条文、同方简化条文、同病异方 | 同病异方、类方混淆、加减方 |
| 正确答案 | 条文ID（SHL-ty-12） | 方剂ID（gui-zhi-tang） |
| 鉴别逻辑 | 条文症状精确匹配 | 方证对应（necessary/common/excluding） |
| 学习路径 | 条文记忆 -> 条文识别 | 方证思维 -> 辨证选方 |
| 临床关联 | 偏理论（条文记忆） | 偏实践（开方决策） |

### 2.2 方剂模式干扰项设计策略

方剂模式的干扰项必须围绕**方证鉴别**设计，而非条文编号：

1. same_disease_different_formula（同病异方）— 核心干扰项
   例：桂枝汤 vs 麻黄汤（太阳病，但汗出/无汗对立）
   例：小柴胡汤 vs 大柴胡汤（少阳病，但有无里实）

2. same_formula_variant（同方加减）— 中等难度
   例：桂枝汤 vs 桂枝加葛根汤（项背强几几）
   例：四逆汤 vs 四逆加人参汤（下利/亡血）

3. incorrect_herb_composition（药物相近方）— 困难
   例：桂枝汤 vs 麻黄汤（都有桂枝/甘草，但麻黄/芍药互换）
   例：小柴胡汤 vs 柴胡桂枝汤（药物高度重叠）

4. same_symptom_opposite_pathology（同症异病）— 困难
   例：汗出（桂枝汤表虚）vs 白虎汤大汗（阳明里热）
   例：烦躁（大青龙表寒里热）vs 干姜附子汤（阳虚烦躁）

5. nearby_classic_reference（经典混淆）— 简单/中等
   例：伤寒论桂枝汤 vs 金匮桂枝汤（不同应用场景）

### 2.3 方剂模式JSON Schema变更（最小化）

Schema变更说明：
- 仅新增 herbs_preview 和 symptom_hint 字段（可选）
- 前端已支持 mode: formula 的渲染逻辑（需验证）
- 不破坏现有 mode: article 的43例病例

## 三、前端集成方案：卡片学习页 -> SP问诊

### 3.1 目标交互流程

用户点击方剂卡片 -> 进入学习页
  -> 学习页底部新增 'SP问诊练习' 按钮
  -> 点击后弹窗选择：
     - 条文模式（选条文编号）— 已有43例
     - 方剂模式（选方名）— 待生成63例
     - 难度选择（1/2/3）— 按用户熟练度推荐
  -> 进入SP问诊界面（复用现有左右分栏布局）
  -> 问诊结束 -> 选择方剂 -> 反馈（正确/错误 + 鉴别分析）
  -> 返回学习页 或 再来一组

### 3.2 UI改动点（app/index.html）

| 改动位置 | 改动内容 | 工作量 | 负责方 |
|----------|----------|--------|--------|
| 学习页底部 | 新增SP问诊练习按钮区 | 小 | 本对话（数据+逻辑建议） |
| 弹窗选择 | 新增模式选择弹窗（条文/方剂/难度） | 中 | 交互设计系统对话 |
| SP问诊视图 | 复用现有左右分栏，适配方剂模式选项 | 小 | 交互设计系统对话 |
| 结果反馈页 | 新增方剂鉴别分析（key_differentials） | 中 | 交互设计系统对话 |
| 答题选项渲染 | 方剂模式：显示方名+药物速览+症状提示 | 小 | 交互设计系统对话 |
| 导航栏 | 原SP问诊改为SP问诊（随机），卡片内改为SP问诊（定向） | 小 | 交互设计系统对话 |

### 3.3 数据流设计

卡片学习页 -> 知道当前 formula_id（如 gui-zhi-tang）
  -> 从 sp_cases.json 中筛选：
     formula_id == gui-zhi-tang AND mode == 'formula' AND difficulty == 用户选择
  -> 若找到 -> 直接加载该SP病例
  -> 若未找到 -> 提示'该方剂暂无处方模式SP，为您推荐随机SP问诊'
  -> 问诊结束后 -> 更新学习记录（localStorage）
     记录：formula_id / mode / difficulty / 正确率 / 问诊方向数

### 4.3 生成质量要求（每例）

1. 主诉：直接暴露2-3个核心症状（necessary + 1-2个common）
2. 问诊方向：10个方向全部预生成，但只暴露5个（diff2）
3. 干扰项：4个错误选项，必须包含：
   - 1个同病异方（同篇章不同方剂）
   - 1个类方混淆（加减方或药物相近方）
   - 1个同症异病机（症状相似但病机相反）
   - 1个其他方向干扰（如相邻篇章方剂）
4. 鉴别分析：必须包含 key_differentials 数组
   - 每个干扰项与正确答案的鉴别要点
   - 引用 symptom_profile.necessary/common/excluding 作为依据
5. 人格分配：按 persona_system.md 映射表
6. JSON验证：governance.py check-sp 0错误0警告
