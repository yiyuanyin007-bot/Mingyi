# 经方学习系统 · 数据管理功能交互设计报告

> **版本**：v1.0  
> **日期**：2026-06-21  
> **范围**：将 `restore_notes.html` 独立恢复功能集成到主系统，并建立统一数据管理面板  
> **目标用户**：陈医生（中医临床学习者，可能重装系统、换设备、多浏览器使用）

---

## 一、现状分析

### 1.1 现有数据管理功能

| 功能 | 位置 | 状态 | 问题 |
|------|------|------|------|
| 学习痕迹导出/导入 | 今日学习弹窗 | ✅ 可用 | 仅 traces，无笔记 |
| 重置学习进度 | 今日学习弹窗 | ✅ 可用 | 一键清空，无选择性 |
| 笔记恢复 | `restore_notes.html` 独立页面 | ⚠️ 孤立 | 用户必须知道 URL 才能访问 |
| 卡片笔记编辑 | 学习页底部 | ✅ 可用 | 单张编辑，无批量管理 |
| 错题本管理 | 仪表盘/弹窗 | ✅ 可用 | 可编辑/删除单条 |

### 1.2 用户真实场景

**场景 A：重装系统**
> 用户重装 Windows，Chrome 数据全部清空。打开主系统 → 学习进度归零，笔记归零。用户不知道有 `restore_notes.html` 这个页面存在。即使知道，也需要手动输入 URL 访问。

**场景 B：换设备**
> 用户在家用电脑学习，笔记写了 3 张卡片。到医院用另一台电脑，笔记不存在。希望在新设备上恢复。

**场景 C：误操作重置**
> 用户点击"重置学习进度"后发现错题本笔记也丢了，想恢复之前的状态。

**场景 D：多浏览器**
> 用户有时用 Chrome，有时用 Edge，数据不互通。希望选择性同步某些笔记。

## 二、设计原则（基于 Nielsen 十大可用性启发式）

### 原则 1：系统状态可见性（Visibility）
- 用户打开主系统时，**立即知道**是否有可恢复的备份数据
- 通过顶部横幅/徽章提示，而非隐藏菜单

### 原则 2：用户控制与自由（User Control）
- 不是"一键恢复全部"，而是**选择性恢复**——用户决定哪些卡片恢复
- 提供预览功能，让用户知道恢复的内容是什么
- 恢复前确认是否覆盖已有笔记（防错）

### 原则 3：错误预防（Error Prevention）
- 检测是否真的需要恢复（避免重复恢复覆盖新笔记）
- 覆盖前二次确认
- 保留原始独立页面作为 fallback

### 原则 4：一致性与标准（Consistency）
- 所有数据管理功能（导入/导出/备份/恢复/重置）**统一在一个入口**
- 与现有"今日学习"弹窗的导入/导出按钮风格一致

### 原则 5：识别而非回忆（Recognition）
- 用户不需要记住 `restore_notes.html` 这个 URL
- 恢复入口始终在系统内可见

### 原则 6：灵活性与效率（Flexibility）
- 新手：一键恢复全部（默认行为）
- 专家：选择性恢复、预览、增量合并

## 三、方案设计

### 方案对比

| 维度 | 方案 A：独立页面增强 | 方案 B：检测式弹窗 | **方案 C：混合模式（推荐）** |
|------|---------------------|-------------------|---------------------------|
| 发现性 | 仍需记住 URL | ✅ 启动自动检测 | ✅ 启动检测 + 常驻入口 |
| 集成度 | 低 | 中 | ✅ 高 |
| 开发成本 | 低 | 中 | 中 |
| 扩展性 | 差 | 中 | ✅ 好（支持多种数据类型） |
| 用户体验 | 差 | 良好 | ✅ 优秀 |

### 推荐方案：混合模式（C）

```
┌─────────────────────────────────────────────────────┐
│  主系统启动                                           │
│      │                                                │
│      ├─ 检测 localStorage 笔记是否为空                  │
│      │   ├─ 空 → 检查备份数据存在？                     │
│      │   │   ├─ 存在 → 顶部显示「恢复横幅」             │
│      │   │   └─ 不存在 → 静默（无提示）                 │
│      │   └─ 非空 → 静默（可手动进入数据管理）           │
│      │                                                │

│      │   └─ 打开「数据恢复弹窗」                       │
│      │       ├─ 展示备份卡片列表（可勾选）              │

│      │                                                │
│      └─ 用户点击 topbar「数据管理」按钮                 │
│          └─ 打开「数据管理面板」（3 标签页）             │
│              ├─ 概览：本地数据量 + 备份数据量            │
│              ├─ 恢复：从备份恢复（同启动弹窗）           │
│              └─ 备份/导出：一键备份当前数据到 JSON        │
└─────────────────────────────────────────────────────┘
```

## 四、详细交互设计

### 4.1 启动检测横幅

**触发条件**：
- 主系统加载完成
- `localStorage` 中 `A01_study_notes` 为空或不存在
- `data/notes_backup/restore_notes_data.json` 文件存在且包含数据

**UI 设计**：
```
┌─────────────────────────────────────────────────────┐
│  📦 检测到循证审计笔记备份（4 张卡片）                  │
│  系统检测到 localStorage 为空，可能是重装系统或首次访问。│
│  [查看并恢复]  [忽略，暂不恢复]  [了解详情]             │
└─────────────────────────────────────────────────────┘
```

**行为**：
- 点击「查看并恢复」→ 打开数据恢复弹窗
- 点击「忽略」→ 横幅消失，设置 `ignore_restore_banner_until` 时间戳（24 小时内不再显示）
- 点击「了解详情」→ 展开说明文字（解释为什么有这个提示）

- 点击「确认恢复」：二次确认弹窗 → 写入 localStorage → 显示成功反馈 → 刷新页面或自动更新笔记区域

### 6.2 检测逻辑

```javascript
async function checkRestoreAvailability() {
  // 1. 检查本地是否已有笔记
  const localNotes = loadStudyNotes(); // 已有函数
  const hasLocalNotes = localNotes.length > 0;
  
  // 2. 检查备份数据是否存在
  let backupData = null;
  try {
    const res = await fetch('../data/notes_backup/restore_notes_data.json');
    if (res.ok) backupData = await res.json();
  } catch (e) {}
  
  // 3. 判断是否需要显示横幅
  if (!backupData) return { available: false };
  
  const backupCards = Object.keys(backupData.notes || {});
  const missingCards = backupCards.filter(id => 
    !localNotes.some(n => n.cardId === id)
  );
  const overwriteCards = backupCards.filter(id => 
    localNotes.some(n => n.cardId === id)
  );
  
  return {
    available: true,
    total: backupCards.length,
    missing: missingCards.length,
    overwrite: overwriteCards.length,
    data: backupData
  };
}
```

### 6.3 恢复流程

```javascript
async function restoreSelectedNotes(selectedCardIds, backupData) {
  const existingNotes = loadStudyNotes();
  let restored = 0, updated = 0;
  
  for (const cardId of selectedCardIds) {
    const content = backupData.notes[cardId];
    const meta = backupData.meta[cardId];
    const idx = existingNotes.findIndex(n => n.cardId === cardId);
    
    const note = {
      cardId,
      content,
      createdAt: new Date().toISOString(),
      updatedAt: new Date().toISOString(),
      source: 'restore_backup',
      sourceAuditId: meta?.auditId
    };
    
    if (idx >= 0) {
      existingNotes[idx] = note;
      updated++;
    } else {
      existingNotes.push(note);
      restored++;
    }
  }
  
  saveStudyNotes(existingNotes);
  return { restored, updated };
}
```
