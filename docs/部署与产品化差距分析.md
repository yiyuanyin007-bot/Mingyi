## 二、距离「可部署网页」还有多远？

| 维度 | 当前状态 | 距离 | 关键步骤 |
|---|---|---|---|
| 托管 | 需要本地 `python -m http.server 8000` | 很近 | 上传到 GitHub Pages / Netlify / Vercel，写 `DEPLOY.md` |
| 缓存 | 无缓存策略，浏览器可能用旧数据 | 近 | 给 JSON 请求加 `?v=x` 或文件指纹 |
| HTTPS/域名 | 无 | 可选 | 静态托管平台默认提供 HTTPS，域名可选 |
| 移动端 | `mobile.html` 未同步 | 中 | 合并到响应式 `index.html` 或单独同步 |
| 离线可用 | 无 Service Worker | 远 | 加 PWA 能力 |

**结论**：如果只是想给朋友或学生访问，**2～3 天**即可完成部署 + 响应式 + 基础优化。

## 三、距离「可长期维护的产品」还有多远？

| 维度 | 当前状态 | 距离 | 关键步骤 |
|---|---|---|---|
| 数据范围 | 仅太阳病 36 方 | 远 | 扩展阳明、少阳、太阴、少阴、厥阴 |
| 内容深度 | 只有方卡，条文、医案、老师笔记未整合 | 中 | 接入 `source_cards.json`、小红书笔记、`clinical/` 医案 |
| 工程结构 | 单文件 2600+ 行 HTML/CSS/JS | 中 | 拆模块、加构建工具、加测试 |
| 用户系统 | 无登录，localStorage 单设备 | 远 | 导出/导入、云端同步、用户账户 |
| AI 导师 | 只能复制 Prompt | 中 | 接入 Kimi API 或 URL Scheme |
| 测试 | 只有手动 WebBridge 冒烟 | 中 | 单元测试、集成测试、CI/CD |
| 安全 | 大量 `innerHTML` | 中 | 改用 DOM API 或做转义 |
| 分析 | 只有累计统计 | 远 | 薄弱点分析、长期复习曲线、错题本 |

**结论**：如果要变成可长期维护、持续扩展的产品，预计还需要 **2～4 周**。

## 五、给第二个项目的经验资产

### 5.1 必须遵守的原则

1. **先备份再改数据/主入口**。
2. **JSON 修改后用 Python `json.load()` 验证**。
3. **浏览器缓存是隐形敌人**：每次大改后强制刷新或加缓存戳。
4. **统计类操作要幂等**：跨题导航时避免重复计分。
5. **掌握度更新按题目对象 ID，不要依赖全局 active 状态**。

### 5.2 推荐复用的模式

1. **数据与研究分离**：核心 Schema 保持精简，研究/来源/链接通过脚本注入。
2. **状态机驱动同一视图的多模式**：用 `mode` + `submitted` + `finished` 控制练习/考试行为。
3. **答案预填充 + 统一提交**：适合需要回顾、修改、批量判分的测试。
4. **WebBridge 截图验证 UI**：颜色、布局类改动用截图比 accessibility tree 更直观。

### 5.3 必须避开的坑

1. 不要把 `CARDS` 数组包成二维数组。
2. Windows 下处理中文 Markdown 先统一换行符 `\r\n` → `\n`。
3. WebBridge 截图路径避免中文，或截图后立刻搜索磁盘确认位置。
4. 别名必须显式处理（如麻杏甘石汤 = 麻黄杏仁甘草石膏汤）。
5. PowerShell 中文回显不可信，关键计数用 Python 二次验证。
