## 二、神经科学与学习科学理论映射

### 2.1 认知负荷理论（Cognitive Load Theory）— Sweller

**核心观点**：工作记忆容量有限（7±2个组块），教学设计应减少外在认知负荷、优化相关认知负荷、避免生成额外认知负荷。

**现状映射**：
- **外在认知负荷过高**：130种标签是扁平列表，用户看到「太阳病、解表剂、风伤卫、太阳病篇」时，需要同时处理4个无层次的信息，无预分类帮助快速筛选
- **搜索负荷**：用户想找到「所有表虚方」时，需要扫描全部130种标签，无分类索引
- **冗余负荷**：92%卡片同时有「太阳病」和「太阳病篇」，用户需要判断两者区别（实际上没有区别，只是重复）

**评估**：**严重违规**。标签数量（130种）远超工作记忆容量（7±2），且无分类结构帮助组块化。

### 2.2 组块化（Chunking）— George Miller

**核心观点**：信息需要组织成有意义的组块（chunk），每个组块内部元素紧密关联，组块之间边界清晰。人脑能同时处理 7±2 个组块。

**现状映射**：
- 当前标签体系是**纯扁平列表**，无组块结构
- 用户无法快速将「太阳病 + 解表剂 + 风伤卫」组块化为「表虚中风方」
- 标签与卡片知识结构（symptom_profile、pathology、herbs）无关联，无法形成「症状-病机-方」的组块

**评估**：**严重缺失**。标签体系应帮助用户建立「六经→病机→症状→方」的层次组块，而不是制造 130 个孤立标签。

### 2.3 提取练习（Retrieval Practice）— Roediger & Karpicke

**核心观点**：学习效果 = 提取次数 × 提取难度。提取线索越强、越一致，回忆效率越高。标签作为检索线索，应稳定、可预测。

**现状映射**：
- 标签作为检索线索**不稳定**：桂枝汤有「风伤卫」，麻黄汤有「寒伤营」，但葛根汤没有对应标签（只有「项背强痛」）
- 标签粒度不一致：搜索「汗出」找到2张，搜索「漏汗」找到1张，搜索「大汗」找到1张——同一症状不同表述，线索分裂
- 标签与卡片内症状不完全对应：卡片标签有「呕吐」但symptom_profile中无「呕吐」（如葛根加半夏汤）

**评估**：**检索线索弱**。标签应作为稳定、可预测的提取线索，帮助用户在「症状→方」的提取练习中快速定位。

### 2.4 精细编码 / 生成性学习（Elaborative Encoding）— Wittrock

**核心观点**：学习不是被动接收，而是主动构建意义。标签应促进学习者主动建立关联、生成理解。

**现状映射**：
- 标签是**被动分类**，而非主动生成线索。用户看到「太阳病」不会主动思考「为什么太阳病？哪些症状证明？」
- 缺乏**对比标签**：如「桂枝汤vs麻黄汤」的对比维度标签（表虚vs表实、汗出vs无汗、缓脉vs紧脉）
- 缺乏**推理链标签**：如「外邪→营卫不和→汗出恶风→桂枝汤」的因果链

**评估**：**未促进生成性学习**。标签应设计为「脚手架」，引导用户主动构建症状-病机-方之间的关联网络。

### 2.5 间隔重复（Spaced Repetition）— Ebbinghaus 遗忘曲线

**核心观点**：最佳复习间隔随掌握程度递增（1天→2天→4天→7天→14天→30天）。标签应帮助识别「需要复习什么」。

**现状映射**：
- 当前标签是**静态属性标签**，无动态学习状态标签
- 6个mastery向量（0→1、1→0、0→2、2→0、0→usage、0→contra）记录了学习状态，但**与标签体系完全脱节**
- 无法基于标签进行精准复习：如「用户太阳病方已掌握，但阳明病方薄弱」——标签无法驱动这种差异化复习策略

**评估**：**标签未服务于间隔重复**。应增加动态学习状态标签（如「薄弱：1→0」「待复习：0→2」），驱动个性化复习计划。

### 2.6 交错练习（Interleaved Practice）— Rohrer

**核心观点**：混合不同类型/主题的练习比集中同类练习更促进长期保持和迁移。标签应支持跨类别交错。

**现状映射**：
- 标签是**分类标签**，只能支持「同类集中练习」（如只看太阳病标签的卡片）
- 无法支持**跨类交错**：如「桂枝汤（太阳病）→ 四逆汤（少阴病）→ 小柴胡汤（少阳病）」的交错复习
- 无法支持**症状交错**：如「汗出」症状的桂枝汤 vs 白虎汤 vs 四逆加人参汤——跨六经但同症状

**评估**：**标签仅支持集中练习，不支持交错**。应设计「症状标签」和「病机标签」作为交错维度，而非仅六经标签。

### 2.7 迁移学习（Transfer Learning）— Thorndike

**核心观点**：迁移需要「相同要素」连接源领域和目标领域。标签应明确标识「哪些要素可迁移」。

**现状映射**：
- 类方（变方）有 variants 字段，但**无标签标识核心差异**：如桂枝汤 vs 桂枝加葛根汤 vs 桂枝去芍药汤——标签无法快速看出差异
- 无**药物组合迁移标签**：如「桂枝+芍药」出现在桂枝汤、小建中汤、桂枝加葛根汤中，但无标签标识这种核心组合
- 无**病机迁移标签**：如「阳虚」出现在真武汤、四逆汤、附子汤中，但标签未帮助建立这种关联

**评估**：**标签未促进迁移**。应增加「核心药对标签」和「核心病机标签」，帮助用户识别跨方的相同要素。

### 2.8 必要难度（Desirable Difficulties）— Bjork

**核心观点**：学习时引入适度困难（如生成效应、延迟反馈、交叉练习）比「容易学习」更能促进长期保持。标签不应让学习太容易，而应促进深层加工。

**现状映射**：
- 标签过于**直接和具体**：如「桂枝汤」标签是「太阳病、解表剂、风伤卫、太阳病篇」——太直白，不需要深层加工
- 缺乏**推理性标签**：如未标注「此方可治脉浮缓而不能治脉浮紧」——需要用户推理的对比信息
- 缺乏**整合性标签**：如未标注「表虚+营卫不和」——需要用户整合症状和病机

**评估**：**标签过于简单**。应增加需要用户进行「症状-病机-方」整合推理的标签，引入必要难度。

### 2.9 双编码理论（Dual Coding Theory）— Allan Paivio

**核心观点**：语言编码和视觉编码分别存储，双编码增强记忆。标签应支持视觉组织。

**现状映射**：
- 标签是**纯文本**，无颜色编码、无视觉层次
- 六经标签无颜色（如太阳病=橙、阳明病=红、少阳病=绿）
- 标签在UI中呈现为灰色小字，无视觉突出
- 标签云/标签树/标签矩阵等视觉组织完全缺失

**评估**：**视觉编码缺失**。标签应增加颜色编码和视觉层次，利用双编码增强记忆。

### 2.10 层次网络模型（Hierarchical Network Model）— Collins & Quillian

**核心观点**：概念按层次组织，上层概念属性向下继承。检索时从上层到下层逐层验证。

**现状映射**：
- 标签是**扁平列表**，无层次结构
- 无「太阳病 → 表证 → 表虚 → 汗出恶风 → 桂枝汤」的层次路径
- 用户无法从「上层概念」快速筛选到「具体方」

**评估**：**层次结构缺失**。标签应设计为层次网络，支持从上到下的逐层检索。

## 四、改进方案：三层标签体系

### 4.1 设计原则

| 原则 | 来源 | 说明 |
|------|------|------|
| **7±2原则** | Miller | 每层标签数 ≤ 7 个，总数 ≤ 7 层 |
| **层次组块** | 层次网络模型 | 六经 → 病机 → 症状 → 方，逐层继承 |
| **稳定线索** | 提取练习 | 同一概念用同一标签，避免同义多词 |
| **动态状态** | 间隔重复 | 标签记录学习状态，驱动复习 |
| **视觉双编码** | 双编码理论 | 颜色+形状+位置，增强记忆 |
| **必要难度** | Bjork | 标签促进深层加工，而非直接给答案 |
| **交错维度** | 交错练习 | 症状/病机/药对作为交错练习维度 |

### 4.2 三层架构

```
┌─────────────────────────────────────────────────────────────┐
│  第一层：分类维度（固定，每卡必有，1-3个）                      │
│  作用：快速定位，减少认知负荷，形成上层组块                      │
├─────────────────────────────────────────────────────────────┤
│  六经归属    │ 太阳/阳明/少阳/少阴/厥阴/太阴/合病/并病          │
│  篇章归属    │ 太阳病篇/阳明病篇/少阳病篇/少阴病篇/厥阴病篇/     │
│              │ 太阴病篇/霍乱病篇/差后劳复篇                      │
│  方剂类型    │ 解表剂/攻下剂/和解剂/温里剂/清热剂/补益剂/       │
│              │ 祛湿剂/祛痰剂/理血剂/固涩剂/驱虫剂                │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  第二层：内容标签（核心，每卡2-5个）                           │
│  作用：精细编码，促进症状-病机-方的关联构建                     │
├─────────────────────────────────────────────────────────────┤
│  核心症状    │ 从卡片symptom_profile.necessary + common提取      │
│              │ 限制：≤3个，优先必要症状                          │
│  核心病机    │ 从卡片pathology提炼，统一病机框架                 │
│              │ 框架：表/里/寒/热/虚/实/阴/阳/气/血/水/痰/瘀      │
│              │ 组合：如「表虚」「里热」「阳虚水泛」               │
│  核心药对    │ 从卡片core_combinations或核心2-3味药提取          │
│              │ 如「桂枝芍药」「麻黄杏仁」「柴胡黄芩」               │
│  特殊属性    │ 差异化标签，如「太少两感」「寒热错杂」「蛔厥」       │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  第三层：学习状态（动态，自动生成，0-3个）                     │
│  作用：驱动间隔重复，支持个性化复习                            │
├─────────────────────────────────────────────────────────────┤
│  薄弱向量    │ 根据mastery向量自动生成：如「薄弱：1→0」           │
│              │ 「薄弱：0→2」「待复习：0→usage」                  │
│  易混淆方    │ 根据错题记录自动生成：如「易混淆：麻黄汤」            │
│  已掌握      │ 全部向量level≥3时自动生成：如「已掌握」             │
│  高频错题    │ 某向量连续错误≥3次时自动生成：如「高频错题：1→0」  │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 标签数量控制

| 层级 | 标签数 | 每卡标签数 | 总标签数（上限） |
|------|--------|-----------|----------------|
| 第一层 | 7个六经 × 8个篇章 × 11个类型 = 26种 | 1-3个 | 3 |
| 第二层 | 症状(30) + 病机(20) + 药对(30) + 特殊(20) = 100种 | 2-5个 | 5 |
| 第三层 | 薄弱向量(6) + 易混淆方(动态) + 已掌握(1) + 高频错题(6) = 13种 | 0-3个 | 3 |
| **合计** | **139种** | **3-11个** | **11个** |

> **注**：虽然总种类仍接近130，但有明确层次后，用户每层只需处理7±2个，认知负荷大幅降低。

### 4.4 标签粒度标准化

**症状标签粒度规则**：

| 粒度级别 | 示例 | 使用场景 | 规则 |
|---------|------|---------|------|
| **一级（症状群）** | 表证、里证、汗出、发热、下利 | 六经大分类下的症状聚合 | 用于第一层/第二层跨卡片聚类 |
| **二级（具体症状）** | 恶风、无汗、大汗、微喘、烦躁 | 直接对应symptom_profile | 用于第二层精确对应 |
| **三级（症状组合）** | 汗出恶风、发热恶寒、心烦腹满 | 仅用于特殊属性标签 | 不单独作为症状标签 |

**当前问题与修正**：

| 当前标签 | 问题 | 修正方案 |
|---------|------|---------|
| 风伤卫 | 抽象病机，非症状 | 移至第二层「病机」：表虚 |
| 寒伤营 | 抽象病机，非症状 | 移至第二层「病机」：表实 |
| 项背强几几 | 具体症状，但粒度太细 | 合并为「项背强痛」或保留作为二级症状 |
| 表郁 | 病机标签 | 移至第二层「病机」：表郁 |
| 表郁化热 | 病机标签 | 移至第二层「病机」：表郁化热 |
| 太少两感 | 特殊属性 | 保留在第二层「特殊属性」 |
| 固阳解表 | 治法标签 | 合并到第一层「方剂类型」或第二层「特殊属性」 |
| 炙甘草 | 药物标签，不应在标签中 | 删除，或移至第二层「核心药对」 |
| 脉结代 | 脉象标签，不应在标签中 | 删除，或作为卡片内容而非标签 |

### 4.5 六经-篇章冗余解决方案

**方案：篇章标签降级为「元数据」而非「标签」**

- 卡片保留 `source_chapter` 字段（已有），但**不再作为标签展示**
- 标签中只保留「六经归属」（如「太阳病」），删除「太阳病篇」
- 篇章信息在卡片详情页展示，不在标签云/筛选中展示

**理由**：
- 六经和篇章是 1:1 映射（太阳病 → 太阳病篇），提供完全相同的信息
- 删除后减少 69 个冗余标签，认知负荷降低 25%
- 用户可通过「六经归属」筛选后，在详情页看到篇章信息

### 5.1 标签驱动的间隔重复

## 八、关键决策建议

### 决策 1：是否立即删除「XX病篇」标签？

**建议**：**是**，立即执行。

- 影响：58 张卡片标签减少 1 个，从 4.4 个/卡 → 3.4 个/卡
- 风险：低，source_chapter 字段已保留信息，详情页仍可展示
- 收益：减少 25% 冗余标签，认知负荷显著降低

### 决策 2：症状标签是否从 symptom_profile 自动提取？

**建议**：**是，但需人工审核**。

- 自动提取：necessary + common 症状 → 标准化标签（如「恶风」→「恶风」）
- 人工审核：处理同义不同词（如「项背强几几」→「项背强痛」）
- 收益：标签与卡片内容一致，检索线索稳定

### 决策 3：是否增加动态学习状态标签？

**建议**：**是，但分阶段**。

- 第一阶段：仅增加「薄弱向量」标签（读取 mastery 向量）
- 第二阶段：增加「易混淆方」标签（分析错题记录）
- 第三阶段：增加「已掌握」标签（综合评估）
- 收益：标签从「静态分类」升级为「动态学习导航」，直接服务于间隔重复和交错练习

### 决策 4：标签颜色编码是否必要？

**建议**：**是，但简化**。

- 最小可行：仅六经标签加颜色（6 种），其他标签灰色
- 完整方案：六经+病机+症状+药对各一种颜色（4 种主色+2 种辅助）
- 收益：双编码增强记忆，用户可快速识别卡片归属

## 十、结论

当前标签体系存在**三大核心问题**：

1. **结构问题**：130 种标签扁平无分类，违反认知负荷理论和组块化原则，92% 卡片存在六经+篇章冗余
2. **功能问题**：标签是静态分类标签，与学习状态（6 个 mastery 向量）完全脱节，无法驱动间隔重复和交错练习
3. **粒度问题**：标签粒度从「太阳病」到「项背强几几」跨度极大，检索线索不稳定，违反提取练习原理

**改进方向**：建立**三层标签体系**（分类维度 + 内容标签 + 学习状态），控制每层 ≤ 7±2 个组块，增加视觉双编码，深度整合复习算法，从「静态分类」升级为「动态学习导航」。
