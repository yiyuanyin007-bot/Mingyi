# 交互层协作提示词

> **来自**: 数据层  
> **面向**: 交互层（前端开发）  
> **任务**: 实现3个功能：学习轨迹仪表盘 + 开方SOP页面 + 新卡片UI验证  
> **数据支持**: Schema和接口说明已准备就绪

---

## 一、你的任务

数据层已完成本周全部6项任务（T-001~T-006），现在需要交互层接手开发前端UI。你需要实现以下3个功能：

### 功能1：学习轨迹仪表盘（P1）

**交付物**: `app/learning-dashboard.html`

**数据来源**: `schemas/learning_trajectory.json` + `schemas/learning_trajectory_interface.md`

**5个核心组件**:

1. **六经热力图**
   - 横轴：六经（太阳、阳明、少阳、太阴、少阴、厥阴）
   - 纵轴：掌握率（0%-100%）
   - 颜色：绿色（>80%）→ 黄色（50-80%）→ 红色（<50%）
   - 数据：从 `liu_jing_mastery` 读取

2. **六维雷达图**
   - 6个维度：方证对应、药物剂量、煎服法、条文记忆、鉴别诊断、临床应用
   - 数据：从 `radar_data` 读取
   - 可切换：按六经筛选（只看太阳病雷达图）

3. **趋势曲线**
   - 横轴：时间（最近30天）
   - 纵轴：掌握方剂数
   - 多条曲线：六经分别显示
   - 数据：从 `timeline` 聚合计算

4. **AI建议卡片**
   - 显示 `ai_suggestions` 数组中的建议
   - 优先级排序：P0（红色）→ P1（黄色）→ P2（绿色）
   - 可点击：点击建议跳转到对应方剂学习页
   - 类型标签：补弱 / 复习 / 强化 / 推荐

5. **时间轴**
   - 按时间倒序显示 `timeline` 事件
   - 事件类型：学习（蓝色）/ 考试（绿色）/ 复习（黄色）/ 开方（紫色）/ 总结（灰色）
   - 可筛选：按六经筛选、按事件类型筛选

**技术约束**:
- 纯CSS+JS实现，不依赖外部库（如ECharts）
- 用CSS Grid/Flex布局
- 雷达图用SVG绘制
- 热力图用CSS渐变实现
- 数据存储：localStorage，key = `sh_learning_trajectory_v1`
- 首次使用需要初始化（见接口说明中的 `initLearningTrajectory()`）

### 功能2：开方SOP页面（P1）

**交付物**: `app/prescription-sop.html`

**数据来源**: `schemas/prescription_sop.json` + `schemas/prescription_sop_interface.md`

**7步流程**（单页内区块切换，不拆多页）：

1. **Step 1: 信息采集**
   - 输入：主诉、症状（多选）、舌象、脉象
   - 自动分类：症状选择后，自动分类到六经（调用 `classifySymptoms()`）
   - 展示：结构化症状分类结果（sun_symptoms / yangming_symptoms 等）

2. **Step 2: 六经定位**
   - 系统推荐：显示 `system_suggestion` + `confidence`（如"太阳病 85%"）
   - 支撑症状：列表显示支撑症状及其置信度
   - 备选方案：显示 `alternatives`（如"阳明病 10%"）
   - 医生决策：勾选"同意系统推荐"或手动选择六经
   - 医生备注：文本输入框

3. **Step 3: 方证匹配**
   - 系统推荐：显示Top 3方剂（名称、概率、支撑条文、鉴别要点）
   - 医生选择：单选框选择方剂
   - 医生调整：如需修改方剂，显示调整界面（添加/删除药物）
   - 支撑条文：点击条文编号可查看原文

4. **Step 4: 剂量确定**
   - 基础标准：选择"教材标准/轻量标准/经方标准/原方标准"
   - 患者体重：输入体重（kg）
   - 自动计算：根据基础标准+体重计算默认剂量
   - 调整记录：记录每次调整（药物、调整量、原因）
   - 最终处方：显示最终处方（药物:剂量）

5. **Step 5: 煎服法与禁忌**
   - 自动填充：根据选择的方剂，自动从 `formula_cards.json` 读取煎服法
   - 禁忌事项：自动显示禁忌列表
   - 医生补充：文本输入框，补充注意事项

6. **Step 6: 记录与追踪**
   - 开方时间：自动记录当前时间
   - 复诊设置：选择复诊日期，勾选"设置提醒"
   - 疗效记录：后续可填写（痊愈/显著改善/改善/无效/加重/待观察）
   - 患者反馈：文本输入框
   - 医生记录：文本输入框
   - 复诊迭代：记录每次复诊的方剂和调整

**导航设计**:
- 顶部进度条：7步，当前步高亮
- 每步底部："上一步" + "下一步" 按钮
- 最后一步："完成开方" 按钮，保存到localStorage
- 可跳步：点击进度条任意步骤可跳转（但会提示"未保存的数据将丢失"）

**数据保存**:
- 每步完成后自动保存到 `sh_prescription_sop_v1`
- 数据格式：JSON数组，每个元素是一条SOP记录
- 记录编号：SOP-YYYYMMDD-NNN

## 二、数据接口说明

### 接口文件位置

| 功能 | Schema文件 | 接口说明文件 |
|------|-----------|-------------|
| 学习轨迹 | `schemas/learning_trajectory.json` | `schemas/learning_trajectory_interface.md` |
| 开方SOP | `schemas/prescription_sop.json` | `schemas/prescription_sop_interface.md` |

### 关键数据key

| key | 用途 | 数据格式 |
|-----|------|----------|
| `sh_learning_trajectory_v1` | 学习轨迹数据 | JSON对象 |
| `sh_prescription_sop_v1` | 开方SOP记录 | JSON数组 |
| `sh_index_v1_state` | 现有学习进度（不碰） | — |
| `clinical_records_v1` | 临床录入记录（不碰） | — |

### 读取方式

```javascript
// 学习轨迹
const trajectory = JSON.parse(localStorage.getItem('sh_learning_trajectory_v1')) || initLearningTrajectory();

// SOP记录
const sopRecords = JSON.parse(localStorage.getItem('sh_prescription_sop_v1')) || [];
```

### 写入方式

```javascript
// 学习轨迹
localStorage.setItem('sh_learning_trajectory_v1', JSON.stringify(trajectory));

// SOP记录
sopRecords.push(newRecord);
localStorage.setItem('sh_prescription_sop_v1', JSON.stringify(sopRecords));
```

## 五、Q&A

### Q1: 数据层的Schema什么时候到位？

A: 数据层已完成全部Schema（T-004/T-005），文件已写入：
- `schemas/learning_trajectory.json`
- `schemas/learning_trajectory_interface.md`
- `schemas/prescription_sop.json`
- `schemas/prescription_sop_interface.md`

交互层可直接读取这些文件。

### Q2: 如果数据层的Schema还没完成，可以先做什么？

A: 可以先用Mock数据搭建页面框架，等Schema到位后替换真实数据接口。Mock数据格式参考接口说明中的"完整示例数据"部分。

### Q3: index.html 只有19行占位页面，怎么整合导航？

A: 数据层已确认 `index.html` 丢失（从324KB变成19行）。交互层有两个选择：
- 方案A：先接受19行占位页，在上面增加两个导航按钮（临时方案）
- 方案B：如果用户有index.html备份，恢复后再整合

建议先采用方案A（临时），后续恢复完整系统后再调整。

### Q4: 两个新页面需要独立打开吗？

A: 是的。learning-dashboard.html 和 prescription-sop.html 作为独立页面存在，用户从index.html点击导航按钮进入，也可直接访问URL。

### Q5: localStorage数据量会超限吗？

A: 学习轨迹数据控制在5KB以内，SOP记录单条10KB以内，100条约1MB，远低于5MB限制。如果超出，建议自动清理最早期的SOP记录（保留最近50条）。
