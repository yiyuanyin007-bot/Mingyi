# 经方学习系统 · 三层锚定整合思路

> 以《伤寒论》条文编号为唯一根ID，打通「条文原文→注家讲解→临床医案」的学习链路。
> 作者：经方条文专家（AI） · 2026-06-19

---

## 1. 核心问题诊断

当前系统已有很好的 MVP 骨架（35 张卡片 + 6 向量 + 复习），但数据层存在三个**断裂**：

1. **条文与讲解断裂**：`source_cards` 是简化条文，老师笔记中有完整的刘渡舟/胡希恕讲解，但没有接入。
2. **方剂与医案断裂**：`formula_cards` 知道方剂的药物和症状，但学习者看不到这个方剂在真实病例中是怎么使用的。
3. **背诵与临床断裂**：6 向量训练是「方名→症状」，但临床思维是「症状→方名」，缺乏反向索引。

---

## 2. 三层锚定模型

### 2.1 锚点是什么？

**《伤寒论》条文编号**（如第13条、第35条）。

所有数据——方剂、讲解、医案——最终都锚定到同一个条文编号。这样无论学习者在哪个环节，系统都知道「你现在在条文第几条」。

### 2.2 三层结构

```
┌─────────────────────────────────────────────────────┐
│  第三层：临床验证层（experience_cards）                │
│  ┌──────────────────────────────────────────────┐   │
│  │  黄煌医案、临床病例、真实症状频率统计            │   │
│  └──────────────────────────────────────────────┘   │
│                    ↓ 解锁条件：mastery Level 4+    │
├─────────────────────────────────────────────────────┤
│  第二层：多维注解层（annotations）                     │
│  ┌──────────────────────────────────────────────┐   │
│  │  老师笔记（针道轩）、刘渡舟观点、胡希恕观点      │   │
│  │  条文辨析、类方鉴别                              │   │
│  └──────────────────────────────────────────────┘   │
│                    ↓ 解锁条件：mastery Level 2+    │
├─────────────────────────────────────────────────────┤
│  第一层：方证基础层（source_cards）                    │
│  ┌──────────────────────────────────────────────┐   │
│  │  《伤寒论》精确原文、条文编号、必要/常见/排除症状  │   │
│  └──────────────────────────────────────────────┘   │
│                    ↓ 基础层：始终可见                │
└─────────────────────────────────────────────────────┘
```

### 2.3 数据链路

```
formula_card（方剂）
   ↓ source_text_ids
source_card（条文）
   ↓ article_number
   ├──→ annotation（注解）← 老师笔记、注家讲解
   └──→ experience_card（医案）← 黄煌沙龙、临床病例
```

## 3. 整合的五大机制

### 机制1：以条文编号为「根键」

统一 ID 体系：

| 实体 | 根键 | 示例 |
|---|---|---|
| 条文卡 | `article_13` | 第13条原文 |
| 方剂卡 | `formula_gui-zhi-tang` | 桂枝汤 |
| 注解 | `annotation_13_liuduzhou` | 刘渡舟讲解第13条 |
| 医案 | `case_13_huanghuang_001` | 黄煌第13条相关医案 |

**映射关系**：
- `formula_card` 通过 `source_text_ids` → 关联到 `source_card`
- `source_card` 通过 `article_number`（如「第13条」）→ 关联到所有注解和医案
- `experience_card` 通过 `source_article_number` → 关联到具体条文

### 机制2：分级解锁式内容

与现有 `mastery` 机制结合，不要一次性 dump 所有信息：

| 掌握度 | 解锁内容 | 学习目的 |
|---|---|---|
| Level 0-1 | 核心条文 + 必要症状 | 建立方证锚点 |
| Level 2-3 | 解锁注家讲解（老师笔记原文） | 深化理解 |
| Level 4-5 | 解锁临床医案（真实病例） | 临床应用 |
| Level 6+ | 解锁类方对比（鉴别诊断） | 辨证精度 |

**为什么这样做**：符合「最近发展区」（ZPD）理论，每次复习不是重复，而是渐进式解锁。

### 机制3：老师笔记作为「权威注解」

在卡片中明确标注来源层级：

```
📖 条文原文（第13条）
太阳病，头痛，发热，汗出，恶风，桂枝汤主之。

🎓 老师笔记 · 针道轩
刘渡舟：本条论述太阳中风表虚证...
胡希恕：桂枝汤证是表虚，不是真正的中风...

🏥 临床参考（黄煌沙龙）
- 医案1：怕冷手指关节晨僵不适案（合桂枝汤）
- 医案2：敏感性胃炎案（合四逆汤）
```

**关键原则**：保留注家之间的**冲突观点**。刘渡舟和胡希恕对某些条文的理解不同，不要合并，而是分别标注，让学习者看到不同的辨证思路。

### 机制4：建立「症状→条文」反向索引

当前系统主要是「方名→症状」（0→1向量），但临床思维是「症状→方名」。

从 `source_cards` 和 `experience_cards` 中提取症状索引：

```yaml
症状「汗出」:
  - 第13条 → 桂枝汤
  - 第12条 → 桂枝汤
  - 第53条 → 桂枝汤
  - 第54条 → 桂枝汤
  - 第95条 → 桂枝汤

症状「无汗」:
  - 第35条 → 麻黄汤
  - 第38条 → 大青龙汤
  - 第31条 → 葛根汤
```

**用途**：
- 自动生成「症状→方名」测试题（1→0向量）
- 错误选项可以从**同类症状**的条文中选取（干扰项更合理）
- 支持临床检索：「患者主诉汗出，可能涉及哪些条文？」

### 机制5：症状频率统计（数据反哺）

黄煌沙龙中有大量真实病例，可以提取：

```yaml
方剂: 桂枝汤
临床医案症状频率:
  汗出: 95%
  恶风: 90%
  头痛: 75%
  发热: 70%
  脉浮缓: 60%
  鼻鸣干呕: 20%
```

**用途**：
- 修正 `formula_card` 中的 `symptom_profile.common`，让卡片上的「常见症状」更贴近临床现实
- 为「症状→方名」测试提供权重：频率高的症状应更常出现在考题中

## 4. 数据整合的优先级

以「周二能用」为底线，以「最小可用」为准则：

### Phase 1：根键巩固（已完成）
- [x] 为 35 张 `source_cards` 补充条文编号（A+D）
- [ ] 将条文编号同步到 `formula_cards` 的 `source_text` 和卡片展示

### Phase 2：注解接入（下一步）
- [ ] 从老师笔记中提取 35 张卡片对应条文的讲解（刘渡舟/胡希恕）
- [ ] 写入 `source_cards` 的 `annotations` 字段
- [ ] 在学习视图中增加「老师笔记」折叠面板

### Phase 3：医案解锁（下下一步）
- [ ] 从黄煌沙龙中提取与 36 目标方相关的医案
- [ ] 生成 `experience_cards`，关联到条文编号
- [ ] 在 `mastery` Level 4+ 时解锁医案阅读

### Phase 4：索引升级（长期）
- [ ] 建立症状→条文反向索引
- [ ] 升级测试干扰项生成逻辑
- [ ] 从医案中提取症状频率，反哺 `symptom_profile`

## 5. 关键技术约束

1. **无后端**：所有数据在前端 JSON 中，通过 `fetch('../data/*.json')` 加载。注解和医案必须做成独立的 JSON 文件，按需加载。
2. **localStorage 容量**：不要在本地存储所有医案和注解。只存储 mastery 进度，内容 JSON 在需要时 `fetch` 加载。
3. **JSON 体积**：注解 JSON 和医案 JSON 预计会较大，建议按「条文编号分段」或按「方剂分组」存储。
4. **备份策略**：每次新增 JSON 文件前备份到 `data/archive/`。

---

## 6. 总结

**整合的本质不是「加数据」，而是「建立链路」**。

以条文编号为根键，把「条文原文→注家讲解→临床医案」串成一条学习链。让学习者从背诵条文开始，逐步解锁深层理解，最终看到临床验证。每一次复习，不只是重复，而是渐进式深入。

这就是「三层锚定模型」的核心：
> **根在条文，深于注解，成于临床。**
