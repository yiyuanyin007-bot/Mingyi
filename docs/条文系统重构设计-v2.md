# 条文系统重构设计 v2 · 经验教训与神经科学设计原理

> **文档编号**：DOC-条文系统重构-v2  
> **创建时间**：2026-06-19  
> **创建原因**：用户发现 S 按钮打开的面板与卡片内点击打开的 slidePanel 是两套独立系统，条文原文和注家讲解被割裂在不同入口。这是一个深刻的架构设计错误，需要彻底反思并记录。  
> **经验教训等级**：🔴 重大（影响用户核心学习路径）

---

## 一、问题诊断：为什么会做出这个设计？

### 1.1 历史原因
- 条文系统经历了两次迭代：
  1. **v1（sourcePanel）**：只显示 `source_cards.json` 的原始条文，有「问 Kimi」和「记笔记」功能
  2. **v2（slidePanel）**：显示 `source_annotations` 的注家讲解（刘渡舟/胡希恕/个人总结），有标签切换和键盘快捷键
- 两次迭代是**独立开发**的，没有合并旧系统，导致双系统并存
- 旧系统的 S 按钮未移除，新系统的数据未接入旧入口

### 1.2 设计思维缺陷
- **数据优先于体验**：先有了两套数据源（source_cards.json + source_annotations），然后为每套数据做了一个面板，而不是从用户学习路径出发设计单一入口
- **增量式堆叠**：每次新需求都在现有代码上「加一块」，没有清理旧代码
- **缺乏认知负荷意识**：没有考虑用户在两个面板之间切换时的工作记忆负担

### 1.3 具体症状
| 症状 | 影响 | 用户感受 |
|------|------|----------|
| S 按钮打开 sourcePanel，只显示原文 | 看不到注家讲解 | "为什么条文和讲解不在一个地方？" |
| 卡片内点击打开 slidePanel，显示注家讲解 | 看不到原文（如果 source_annotations 的 text 为空） | "为什么原文没有？" |
| 两个面板独立存在 | 用户不知道哪个是「正确」的入口 | "我该怎么学习条文？" |
| 没有提取练习机制 | 被动阅读，看过就忘 | "看了很多遍，还是记不住" |

## 二、神经科学依据：条文系统应该遵循什么原理？

### 2.1 工作记忆限制（4±1）
- **原理**：人同时处理 4±1 个信息组块（Cowan, 2001; Miller, 1956）
- **对条文系统的要求**：
  - 一次只展示一个维度（先原文，再刘渡舟，再胡希恕）
  - 不要并排显示多位注家的内容
  - 标签切换是正确的设计，但需要更严格的渐进披露

### 2.2 组块化（Chunking）
- **原理**：将信息组织成有意义的组块，便于记忆和工作记忆操作（Miller, 1956）
- **对条文系统的要求**：
  - 条文原文 = 组块 1（核心）
  - 刘渡舟解析 = 组块 2（经典视角）
  - 胡希恕解析 = 组块 3（临床视角）
  - 个人总结 = 组块 4（生成视角）
  - 按顺序逐个加载，每个组块内部再细分

### 2.3 提取练习（Retrieval Practice）
- **原理**：主动回忆比被动重读效果好 2-3 倍（Roediger & Karpicke, 2006）
- **对条文系统的要求**：
  - 读完条文后，先遮住讲解，让用户自己总结"辨证要点"
  - 再展开对照，发现遗漏
  - 不是"看条文"，而是"先猜后验"

### 2.4 精细编码（Elaborative Encoding）
- **原理**：多维度编码（原文 + 病机 + 症状 + 对比）增强记忆（Craik & Lockhart, 1972）
- **对条文系统的要求**：
  - 提供"条文 → 方证 → 症状 → 病机"的关联链
  - 不是孤立文本，而是网络化知识

### 2.5 交错学习（Interleaving）
- **原理**：交替学习不同主题比集中学习效果好（Rohrer et al., 2007）
- **对条文系统的要求**：
  - 同一条文，先读刘渡舟（经典视角），再读胡希恕（临床视角）
  - 两位注家的差异点形成对比组块，增强记忆痕迹

### 2.6 生成效应（Generation Effect）
- **原理**：自己生成的信息比被动接收的记忆更牢（Slamecka & Graf, 1978）
- **对条文系统的要求**：
  - 让用户在"个人总结"标签页里写自己的理解
  - 系统保存，下次复习时优先显示自己的总结

### 2.7 间隔重复（Spaced Repetition）
- **原理**：在遗忘临界点复习效率最高（Ebbinghaus, 1885; Pimsleur, 1967）
- **对条文系统的要求**：
  - 条文内容应按"记忆向量"（0→1 / 1→0）的复习节奏触发
  - 不是随时打开，而是在复习时作为"奖励"解锁

## 三、设计的真正目的：不是"看条文"，而是"建立方证神经回路"

### 3.1 学习效果目标（四层回路）

```
第一层：看到条文原文 → 能立即反应出"这是哪方"（0→1 向量）
    ↓
第二层：看到症状描述 → 能定位到条文并推导病机（1→0 向量）
    ↓
第三层：对比两位注家 → 形成"刘渡舟重辨证、胡希恕重方证"的元认知框架
    ↓
第四层：个人总结 → 将条文内化为自己的临床决策语言
```

### 3.2 交互模式目标

| 目标 | 实现方式 |
|------|----------|
| 渐进式 | 先原文（必要），再注家（扩展），再个人（生成） |
| 主动式 | 不是"阅读"，而是"先猜后验" |
| 关联式 | 读完条文，立即做一道"条文→方名"题，巩固回路 |
| 间隔式 | 注家内容作为"复习奖励"，在向量复习时解锁 |

## 四、重构方案：单入口、分层、主动提取

### 4.1 架构层：统一为「条文学习面板」
- **废除** `sourcePanel`（旧面板），S 按钮直接打开 `slidePanel`
- `slidePanel` 同时读取 `source_cards.json`（原文）和 `source_annotations`（讲解）
- 一个入口，一个面板，一套状态

### 4.2 数据层：融合双数据源

```javascript
// 统一数据结构
{
  article_number: "48",           // 条文编号
  text: "原文",                   // 来自 source_cards.json
  annotations: {
    "刘渡舟": "...",              // 来自 source_annotations
    "胡希恕": "...",              // 来自 source_annotations
    "个人总结": "..."             // 来自 source_annotations
  },
  my_note: "...",                 // 来自 localStorage
  quiz: {...}                     // 关联的测试题
}
```

### 4.3 交互层：三阶段渐进披露

```
┌─────────────────────────────────────┐
│  第1步：原文（必须）                 │
│  显示条文，"遮住讲解"按钮            │
│  用户先读条文，思考"这是什么方？"     │
│  ↓ 点击"我的理解"                   │
│  弹出输入框：你认为核心症状是？       │
├─────────────────────────────────────┤
│  第2步：对比注家（扩展）              │
│  标签：条文 | 刘渡舟 | 胡希恕 | 对比  │
│  对比标签高亮两位注家的差异点          │
│  ↓ 读完注家                          │
│  弹出：两位注家的最大差异是什么？      │
├─────────────────────────────────────┤
│  第3步：个人总结（生成）              │
│  文本框：用自己的话总结               │
│  保存后，下次复习优先显示个人总结      │
└─────────────────────────────────────┘
```

### 4.4 键盘交互：符合认知顺序

| 按键 | 动作 | 神经科学依据 |
|------|------|-------------|
| `1` | 显示原文 | 先建立基础组块 |
| `2` | 显示刘渡舟 | 经典视角编码 |
| `3` | 显示胡希恕 | 临床视角编码，与2形成对比 |
| `4` | 显示对比 | 交错学习，强化差异 |
| `5` | 显示个人总结 | 生成效应，主动编码 |
| `Space` | 遮住/显示当前标签 | 提取练习（先遮住，再回忆） |
| `-` / `=` | 上条/下条文 | 间隔重复，不同条文交错 |
| `Esc` | 关闭面板 | 工作记忆释放 |

### 4.5 与练习系统联动
- 读完条文后，面板底部出现「立即测试」按钮
- 出题："这条条文对应哪个方？"（0→1 向量）
- 或："以下哪个症状是这条条文的必要症状？"（1→0 向量）
- 做错后，自动标记该条文为"薄弱"，下次复习时优先展示

## 六、经验教训总结

### 6.1 设计原则（从此铭记）
1. **用户路径优先于数据路径**：先问"用户怎么学"，再问"数据怎么存"
2. **单一入口原则**：同一学习对象只能有一个主入口，旧入口必须清理
3. **渐进披露原则**：根据掌握程度分层展示，不是一次性 dump 所有内容
4. **主动提取原则**：被动阅读是低效的，必须设计"先猜后验"机制
5. **神经科学驱动**：每个交互决策都应该能说出对应的认知原理

### 6.2 检查清单（未来新增功能时自查）
- [ ] 这个功能是否增加了新的入口？如果是，旧的入口是否已清理？
- [ ] 用户在这个功能中的工作记忆负荷是多少？是否超过了 4±1？
- [ ] 这个功能是否提供了主动提取的机会，还是只是被动阅读？
- [ ] 这个功能是否与练习系统联动？
- [ ] 这个功能是否遵循渐进披露原则？
