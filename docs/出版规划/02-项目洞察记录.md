## 二、项目核心洞察

### 2.1 这不是一个"工具"，是一套"知识工程方法论"

表面看是一个学习工具，但深层结构是一个**完整的个人知识系统工程**：
- **数据层**：原始素材 → 清洗 → 提取 → 审阅 → 卡片
- **训练层**：八向量映射 → 掌握度追踪 → SRS调度 → 每日复习
- **临床层**：义诊记录 → 经验提炼 → 卡片反哺 → 反馈闭环
- **治理层**：IDENTITY/AGENTS/CHANGELOG 三层约束

**关键洞察**：陈医生的真正贡献不是"做了一款APP"，而是**把中医学习这件事，从"经验驱动"变成了"系统驱动"**。

---

### 2.2 "三层锚定"是核心知识架构

```
条文层（source_card）
    ├── 原文出处、条文编号、症状词
    │
    ▼
方剂层（formula_card）
    ├── 原文锚定 + 症状谱 + 病机 + 药物 + 禁忌
    ├── canonical（原文标准）
    ├── empirical_distribution（经验分布）
    └── lineage（方剂谱系）
    │
    ▼
经验层（experience_card）
    ├── 临床经验 + 疗效记录 + 置信度
    ├── subjective_effective（主观有效）
    └── objective_change（客观变化）
```

**关键洞察**：大多数中医学习只停留在"条文层"或"方剂层"，很少有人把"临床层"结构化地挂回到学习系统中。这个三层锚定是**连接知与行的关键架构**。

---

### 2.3 八向量不是"考试题型"，是"认知映射"

市面上的经方学习工具多做成"背方名→背药物→背症状"的单向记忆。八向量的革命性在于：

```
        方名
       ↗  ↘
    症状 ←→ 药物
       ↘  ↗
       用法/病机
```

**关键洞察**：临床开方不是"从症状推导方名"这一种能力，而是**多方向、多粒度的映射网络**。八向量训练的是"认知灵活性"——看到方名能想到症状，看到症状能想到方名，看到药物也能想到方名。这是真实临床需要的"双向检索"能力。

---

### 2.4 "双轨制"是中医传承的方法论创新

`canonical`（原文标准）与 `empirical_distribution`（经验分布）分离，这解决了中医学习中一个长期痛点：

> "倪海厦说某个方可以加某个药，但原文没有这个药。听谁的？"

双轨制的回答：
- 原文记录进 `canonical`，不增不减
- 经验记录进 `empirical_distribution`，标注来源和置信度
- 学习者自己判断，系统只提供信息，不做权威裁决

**关键洞察**：这在学术方法论上接近"证据分级"（Levels of Evidence），但在中医领域，把"传统"和"经验"用结构化方式分离，是**前所未有的**。

---

### 2.5 "数据飞轮"比"初始数据量"更重要

陈医生反复强调"数据飞轮优先于初始数据量"（DeepSeek battle 共识）。这个理念的深层含义：

```
原始资料 → 清洗 → 提取 → 审阅 → 入库 → 使用 → 反馈 → 补充 → 原始资料
                ↑___________________________________________↓
```

**关键洞察**：很多学习者的问题是"资料太多，读不完"。陈医生的方案是**不要读完，而是建立一套能持续处理的管道**。飞轮转起来后，资料自己会分层、沉淀、过滤。这是**从"知识消费者"到"知识生产者"的跃迁**。

---

### 2.6 三层约束体系是AI时代项目管理的原创方法论

| 层级 | 文件 | 功能 | 约束对象 |
|------|------|------|----------|
| 身份层 | `IDENTITY.md` | 定义"我是谁、我遵循什么规则" | 本AI（协作者） |
| 规范层 | `AGENTS.md` | 定义"项目结构、修改约定、测试流程" | 所有AI协作者 |
| 记录层 | `CHANGELOG.md` | 定义"每次变更必须登记" | 所有变更操作 |

**关键洞察**：这不是传统的"项目管理"，而是**"人机协作治理"**。陈医生用结构化文档，把AI协作者的行为约束在可预期的轨道上。这背后是一种深刻的信任模型：不是"AI帮我做"，而是"AI是我的同事，我们需要共同遵守工作规范"。

---

### 2.7 "Battle机制"是元认知学习的尖端设计

```
个人记忆模型 → 新资料入库 → 冲突检测 → Battle讨论 → 模型更新 → 反哺出题
```

这不是"学习新知识"，而是**"让旧知识接受挑战并进化"**。Battle的两个必答题极具设计智慧：
1. "如果我的思路是对的，为什么没办法解释当前的问题？"
2. "我是否需要去更新、优化我的模型？"

**关键洞察**：这是认知心理学中的"元认知监控"（metacognitive monitoring）的落地化。但把它做成一个**系统化的、可审计的、可迭代的**机制，是陈医生的原创。

---

### 2.8 标准化病人（SP）是"条文→临床"的转换器

SP的设计核心是**信息分层**：
- L0（主动信息）：患者主诉中说出2-3个核心症状
- L1（浅层信息）：问对方向就给
- L2（深层信息）：追问细节才给
- L3（误导/噪声）：患者自己的误解，30%随机出现

**关键洞察**：这解决了中医学习中"条文是死的，临床是活的"的断裂。学生不是在背条文，而是在**模拟真实的、信息不完整的、有误导的临床场景**中训练辨证能力。这是OSCE（客观结构化临床考试）在中医经方训练中的本土化。

---

### 2.9 "来源感知清洗"是古籍数字化的方法论贡献

v1清洗失败（按空行分段，把倪海厦txt切成碎片）→ v2清洗成功（来源感知：倪海厦txt的空行是版式残留，不是段落分隔）。

**关键洞察**：这不是一个技术细节，而是一个**方法论原则**——"清洗策略必须来源感知，不能假设所有文本的空行都有相同语义"。这个原则对任何处理非结构化文本的领域（法律、历史、档案）都有迁移价值。

---

### 2.10 项目最大的隐性资产是"过程记录"

`docs/工程经验记录.md` 中沉淀了22个开发阶段的弯路与修复，这是**比代码更值钱的东西**。每个记录都有：
- 现象（发生了什么）
- 根因（为什么）
- 修复（怎么解决的）
- 经验（下次怎么做）

**关键洞察**：陈医生不是在做项目，他是在**做一部"学习科学实验日志"**。这22个阶段记录了一个真实的、有失败有纠偏的、非线性的认知过程。这是出版价值的核心所在。

## 四、项目中的关键矛盾与张力

### 4.1 "完成" vs "可用"的张力

陈医生反复说"先解决下一个真实学习动作"，而不是"补全所有设计文档"。这导致系统永远是"48.5%完成度"，但**已经能支撑真实学习**。这是一种**反完美主义的工程哲学**。

### 4.2 "原文锚定" vs "经验扩展"的张力

双轨制的设计就是为了管理这个张力：尊重原文但不盲从原文，容纳经验但不混淆经验。

### 4.3 "个人系统" vs "可复用方法"的张力

陈医生的系统是为"自己的学习"设计的，但出版要求它成为"别人的方法"。这需要在书中做**抽象化**和**通用化**的处理。

### 4.4 "AI协作" vs "人类决策"的张力

三层约束体系不是让AI替代人，而是让AI在**有约束的轨道**上高效工作。陈医生的核心决策（如删除三栏布局、保留八向量）始终由人类做出，AI负责执行和文档化。
