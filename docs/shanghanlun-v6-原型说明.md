# 《伤寒论》训练系统 v6 原型说明

> **文档性质**：交互原型规格说明  
> **对应文件**：`shanghanlun-v6.html`  
> **文档目的**：将网页原型的交互意图、状态机、数据模型 extracted 为可留存、可交接的规格，避免后续开发直接从 HTML 中逆向工程。  
> **状态**：v6 原型已验证核心交互流程，但数据层和部分状态仍为硬编码演示。

---

## 1. 原型定位

v6 是一个**单文件 HTML 交互原型**，用于验证以下核心假设：

1. 学习模式 vs 考试模式的切换是否顺畅
2. "临床模式"（症状→方名输入考试）的答题闭环是否自然
3. "方剂模式"（全向量选择题考试）的答题闭环是否自然
4. 左侧卡片列表、中间题目/详情、右侧统计/掌握度的三栏布局是否可用
5. 全局键盘快捷键（Q/W/E/R、空格、Enter、ESC、O/P）是否足够直观

**不是正式产品的目标架构**。当前实现为了快速验证，将结构、样式、逻辑、数据全部写在一个 HTML 文件中。

---

## 2. 运行方式

- 直接用浏览器打开 `shanghanlun-v6.html`，无需服务器
- 本地存储使用 `localStorage`（仅主题 `sh_theme`、今日统计 `sh_todayStats`）
- 数据目前硬编码在 `<script>` 中

## 3. 数据模型

### 3.1 卡片数据 `CARDS`

每张卡片是训练的最小单元。

```javascript
{
  id: 'gui-zhi-tang',           // 卡片唯一标识
  name: '桂枝汤',                // 方名（正确答案）
  desc: '太阳中风主方',          // 列表短描述
  vectors: [                     // 该卡片支持的训练向量
    '症状→方名',
    '方名→症状',
    '方名→药物',
    '药物→方名',
    '方名→用法'
  ],
  mastery: [                     // 各向量掌握度（当前硬编码为演示数据）
    { vector: '症状→方名', pct: 80, status: '已掌握', detail: 'Lv.4', color: 'var(--green)' },
    ...
  ],
  data: {                        // 题目生成素材
    symptoms: ['头痛','发热','汗出','恶风','脉浮缓'],
    formula_name: '桂枝汤',
    herbs: ['桂枝','芍药','生姜','大枣','甘草'],
    usage: '水煎温服避风忌生冷'
  }
}
```

### 3.2 卡片详情 `CARD_DATA`

学习模式下中间区域显示的详情内容。当前与 `CARDS` 分离，是**临时硬编码**。

包含：
- `name`：方名
- `tags`：标签数组
- `text`：原文条文 + 倪师注解（HTML）
- `herbs`：药物组成及剂量
- `diag`：辨证要点

### 3.3 复习计划 `REVIEW_DATA`

艾宾浩斯复习仪表盘的数据。当前是**硬编码 mock 数据**。

```javascript
{
  cardIdx: 1,                // 卡片在 CARDS 中的索引
  vector: '症状→方名',        // 向量
  status: 'overdue',         // overdue | today | future
  daysOverdue: 3,            // 逾期天数（负数表示未来）
  memoryStrength: 45,        // 记忆强度 0-100
  lastReview: '2026-06-09'   // 上次复习日期
}
```

### 3.4 今日统计 `sh_todayStats`

存储在 `localStorage`：

```javascript
{ date: '2026-06-12', completedQuestions: 0 }
```

每天自动重置。

## 4. 状态机

### 4.1 全局状态变量

| 变量 | 类型 | 说明 |
|------|------|------|
| `currentMode` | string | `'learn'` / `'exam'` / `'input-exam'` |
| `currentExamMode` | string | `'clinical'` / `'formula'`，决定考试类型 |
| `examMode` | string | `'all'` 全卡 / `'single'` 单卡 |
| `examSingleCardIdx` | number | `examMode='single'` 时指定卡片索引 |
| `currentCardIdx` | number | 当前选中的卡片索引 |
| `selectedCardIndices` | number[] | 多选模式下选中的卡片索引 |
| `examCardCount` | number | 临床模式默认考几张卡，默认 2 |
| `examState` | object | 选择题考试状态（题目、当前题、连续对、计时） |
| `clinicalExamState` | object | 输入考试状态（题目、当前题、总数） |

### 4.2 状态转换图

```
                    ┌─────────────────────────────────────┐
                    │                                     │
                    ▼                                     │
[初始] ──► [学习模式 learn]                              │
              │                                          │
              │ 点击卡片 / 空格（在仪表盘视图）            │
              ▼                                          │
        [学习详情视图]                                    │
              │                                          │
              │ 空格 / "考试这张卡"按钮                   │
              ▼                                          │
    ┌─────────────────┐                                  │
    │  currentExamMode │                                  │
    │   = 'clinical'   │                                  │
    └────────┬────────┘                                  │
             ▼                                            │
    [输入考试 input-exam]                                 │
             │                                            │
             │ Enter（弹窗提示"返回卡片模式"）             │
             └────────────────────────────────────────────┘
             │ 空格（下一题）
             ▼
    [输入考试下一题 / 结束返回学习]

    [学习详情视图]
             │
             │ currentExamMode = 'formula'
             ▼
    [选择题考试 exam]
             │
             │ "返回学习" / 结束面板 R
             ▼
    [学习模式 learn]
```

### 4.3 模式说明

| 模式 | 用户看到的内容 | 入口 |
|------|---------------|------|
| 学习模式-仪表盘 | 右侧显示逾期/今日/未来复习卡片 | 初始页面、点击左侧空白 |
| 学习模式-详情 | 中间显示卡片详情、右侧显示掌握度 | 点击左侧卡片 |
| 临床输入考试 | 中间显示症状，下方输入方名 | 学习详情中 currentExamMode=clinical 时按空格 |
| 方剂选择考试 | 中间显示题目+4选项 Q/W/E/R | 学习详情中 currentExamMode=formula 时按空格、或顶部"开始考试" |

## 6. 学习模式交互

### 6.1 初始状态

- 进入页面：`currentMode='learn'`，`currentExamMode='clinical'`
- 左侧显示 5 张卡片列表
- 右侧默认显示**复习仪表盘**（艾宾浩斯）
- 中间显示默认第一张卡片（桂枝汤）的详情

### 6.2 点击左侧卡片

- 行为：**进入学习详情视图**
- `currentCardIdx` 更新为点击的卡片
- `selectedCardIndices = [i]`
- 右侧从复习仪表盘切换到**掌握度面板**
- 中间重新渲染该卡片详情

### 6.3 点击左侧空白区域

- 行为：**返回复习仪表盘**
- 调用 `showCardListView()`
- 右侧显示 `reviewDashboardWrapper`，隐藏 `learningModeRight`

### 6.4 顶部"开始考试"按钮

- 当前是 `currentExamMode='clinical'` 时，行为取决于当前上下文
- 主要入口还是从学习详情按空格

### 6.5 Tab 键

- 在学习模式下按 `Tab`：切换 `currentExamMode`（clinical ↔ formula）
- 仅影响标签文字和考试数量设置是否显示
- 不影响当前详情显示

## 7. 临床模式考试（输入考试）

### 7.1 入口

1. 确保 `currentExamMode='clinical'`（默认就是）
2. 在学习详情视图，按 `空格` 或点击"考试这张卡"按钮
3. 系统从 `selectedCardIndices` 中随机抽取 `examCardCount` 张（默认 2 张）
4. 如果选中数量不足，自动随机补充
5. 进入 `input-exam` 模式

### 7.2 题目显示

- 中间上方显示：第 N/M 题
- 中间大字显示症状：`以下症状，请说出方名：头痛、发热、汗出、恶风、脉浮缓`
- 提示：`按空格键或回车键开始输入答案`
- 输入区域默认隐藏

### 7.3 答题流程

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 按 `空格` / `Enter` | 显示输入框，提示"请输入方名，按回车提交答案" |
| 2 | 在输入框输入方名 | 实时输入 |
| 3 | 按 `Enter` 或点击"回车键 提交答案" | 判断答案，显示反馈弹窗 |
| 4 | 按 `Enter` | 关闭弹窗，**返回学习模式** |
| 5 | 按 `空格` | 下一题（如果还有） |
| 6 | 按 `ESC` | 重新显示输入框，清空答案 |

### 7.4 答案判定规则

```javascript
isCorrect = userAnswer.includes(card.name) || card.name.includes(userAnswer)
```

即：用户答案包含正确方名，或正确方名包含用户答案，都算对。

### 7.5 反馈弹窗内容

- 标题：回答正确 / 回答错误
- 正确答案
- 解析：`<症状>是<方名>证典型表现。`

### 7.6 结束

- 答完最后一题后，按空格会 alert"已是最后一题，返回学习模式"
- 然后调用 `backToLearnFromInput()` 返回学习模式

---

## 8. 方剂模式考试（选择题）

### 8.1 入口

1. 将 `currentExamMode` 切换为 `'formula'`（按 Tab）
2. 在学习详情视图，按 `空格` 或点击"考试这张卡"
3. 系统对当前单张卡片的所有向量各出 1 题
4. 进入 `exam` 模式，显示选择题

### 8.2 题目显示

- 4 个选项，分别对应快捷键 `Q / W / E / R`
- 题目根据向量类型动态生成

### 8.3 答题流程

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 按 `Q/W/E/R` 或点击选项 | 选中选项，显示"空格键 提交答案"按钮 |
| 2 | 按 `空格` / `Enter` | 提交答案，显示反馈区 |
| 3 | 按 `空格` / `Enter` | 进入下一题 |
| 4 | 全部答完后 | 显示考试结束面板 |

### 8.4 结束面板

显示正确数、错误数、用时。按钮：
- Q：再来复习
- W：换个方式考你
- E：随机测试
- R：返回学习

## 10. 当前已验证的交互规则

以下规则已经过调试，可以视为相对确定：

1. 学习模式下点击卡片始终进入详情视图，不受 `currentExamMode` 影响
2. 临床模式采用输入考试，答案判定为字符串包含关系
3. 方剂模式采用 4 选 1 选择题，支持 Q/W/E/R 快捷键
4. 输入考试答题后 Enter 返回学习模式，空格下一题，ESC 重新输入
5. 每道新题输入框自动清空
6. 支持 light/dark 主题切换

## 11. 临时实现 / 已知问题

以下内容在 v6 中是**硬编码或临时实现**，正式开发时必须替换：

| 项 | 当前状态 | 后续处理 |
|----|---------|---------|
| `CARDS` | 5 张卡片硬编码 | 从 JSON/API 加载 |
| `CARD_DATA` | 与学习数据分离的硬编码 | 合并到 `CARDS` 真相源 |
| `REVIEW_DATA` | mock 数据 | 根据艾宾浩斯算法真实计算 |
| 掌握度 `mastery` | 硬编码 | 根据答题记录动态计算 |
| 进度条 | 第 1 题时显示 0%，最后 1 题显示不到 100% | 修正进度计算 |
| `incrementTodayStats` | 每次提交都递增 | 确认是否需要去重/按卡片去重 |
| 争议标记 O/P | 只修改内存，未持久化 | 接入 WorkBuddy API |
| 随机测试 E | 只有 `alert('随机测试 — 原型演示')` | 实现真实逻辑 |
| `startInputExam()` | 单卡输入模式，与临床模式有重叠 | 明确是否保留 |
| 全局 `keydown` | 有多个分支和特殊处理 | 建议重构为命令表模式 |

## 12. 与正式开发的衔接建议

### 12.1 先做 JSON 真相源

不要继续扩展 HTML 原型。建议下一步建立：

```
cards/
  gui-zhi-tang.json
  ma-huang-tang.json
  ...
```

每个 JSON 包含：
- id / name / desc
- vectors（支持的训练向量）
- data（symptoms / herbs / usage / text / diagnosis / tags）
- mastery（运行时计算，不从 JSON 读）

### 12.2 明确状态机

将 `currentMode` / `currentExamMode` / `examMode` 合并为单一状态机：

```javascript
const AppState = {
  view: 'dashboard' | 'card-detail' | 'clinical-exam' | 'formula-exam' | 'exam-result',
  selectedCardId: string | null,
  selectedCardIds: string[],
  exam: { ... },
  // ...
}
```

### 12.3 分离关注点

| 层 | 职责 |
|----|------|
| 数据层 | JSON 真相源、localStorage、WorkBuddy API |
| 状态层 | 状态机、动作（Action）、 reducer |
| 视图层 | React/Vue 组件，只负责渲染 |
| 交互层 | 快捷键绑定、事件处理 |

### 12.4 API 优先

如果后续要接 WorkBuddy，应该尽早定义 API 接口：

- `GET /api/cards` — 获取卡片
- `POST /api/session/{id}/answer` — 提交答案
- `POST /api/session/{id}/dispute` — 争议标记
- `GET /api/review` — 获取复习计划

### 12.5 原型与产品并行

- **HTML 原型**：继续用于快速验证新交互想法
- **Markdown 规格**：作为给程序员的开发依据（即本文档）
- **正式项目**：用框架（推荐 React + TypeScript）重新实现，不要试图把 HTML 直接迁移
