## 一、设计原则（您先确认这些原则是否合理）

| 原则 | 说明 | 您需要确认 |
|------|------|----------|
| **7±2原则** | 每层标签种类不超过 7 种，人脑工作记忆容量上限 | ✅/❌ |
| **层次组块** | 标签分三层，上层是「分类」，中层是「内容」，下层是「状态」 | ✅/❌ |
| **一页看清** | 一张卡片上标签总数不超过 7 个（含三层），不堆砌 | ✅/❌ |
| **颜色编码** | 六经各一种颜色，视觉记忆辅助 | ✅/❌ |
| **症状从数据来** | 症状标签必须从 symptom_profile 提取，不凭空造 | ✅/❌ |
| **病机从数据来** | 病机标签从 pathology 提炼，统一为框架词汇 | ✅/❌ |
| **药对从数据来** | 药对标签从 core_combinations 提取，2-4 味药一组 | ✅/❌ |
| **动态标签** | 薄弱向量、易混淆方等由系统根据学习记录自动生成 | ✅/❌ |
| **标签可点** | 点击标签可聚类/可考试（已有功能，保留） | ✅/❌ |

### 3.3 篇章归属（降级为详情页元数据，**不作为标签**）

**决策**：删除所有「XX病篇」标签（太阳病篇、阳明病篇等共 7 种）。

**理由**：
- 篇章与六经是 1:1 映射（太阳病 → 太阳病篇），信息重复
- 卡片已保留 `source_chapter` 字段，详情页仍可展示
- 删除后减少 7 种标签，认知负荷降低

**请确认**：删除「XX病篇」标签，只保留 `source_chapter` 字段在详情页展示？ ✅/❌
