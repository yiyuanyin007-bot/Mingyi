### T-005: 设计SOP数据Schema

**目标**: 为开方SOP页面提供数据Schema和接口说明

**交付物**:
- `schemas/prescription_sop.json`（JSON Schema）
- `schemas/prescription_sop_interface.md`（接口说明）

**内容要求**:
- 数据存储：localStorage，key = `sh_prescription_sop_v1`
- 数据结构：record_id + patient_id + doctor_id + created_at + 6个step
- Step 1: 信息采集（chief_complaint + symptoms + tongue + pulse + structured_input）
- Step 2: 六经定位（system_suggestion + confidence + supporting_symptoms + alternatives + doctor_agreement）
- Step 3: 方证匹配（system_recommendations[Top 3] + doctor_choice + doctor_adjustments）
- Step 4: 剂量确定（base_dosage + weight + adjustments + final_prescription）
- Step 5: 煎服法（usage + contraindications + notes + doctor_additional_notes）
- Step 6: 记录与追踪（prescribed_at + follow_up_scheduled + follow_up_reminder + outcome + iterations）
- 每步更新函数：createSOPRecord + updateStep2 + updateStep3 + updateStep4 + updateStep5 + completeRecord
- 与临床录入系统的整合方式（方案A/方案B）
- 完整示例数据：桂枝汤开方全流程

**验收标准**:
- [ ] JSON Schema通过验证
- [ ] 接口说明包含：每步的更新代码示例
- [ ] 包含完整示例数据（可直接复制给交互层）
- [ ] 与现有localStorage key隔离（不冲突）
- [ ] 包含与临床录入系统的整合方案

## 风险与应对

| 风险 | 概率 | 影响 | 应对方案 |

| 交互层开发延迟 | 中 | 验收延后 | 数据层先提供Mock数据，交互层可提前搭建框架 |
