# 关于《伤寒论》训练系统 v4 与顶层设计的差距分析

我已查看了 `shanghanlun-v4.html`（桌面文件，1296行，单文件HTML应用），并与 `_design/00-顶层设计-最终对齐版.md`（v3.0）进行了逐条对比。以下是可以直接转给 WorkBuddy 的评估结论。

---

## 一、总体判断

`shanghanlun-v4.html` 是一个**功能可用的前端原型**，完成了：
- 5个方剂的卡片展示
- 学习模式与考试模式切换
- 四选一答题 + 反馈 + 统计
- 主题切换、键盘快捷键

但距离顶层设计 v3.0 的要求，**差距非常大**。当前实现本质上是一个"静态演示版"，尚未接入顶层设计定义的数据层、状态层和 WorkBuddy API。

---

## 二、与顶层设计的核心差距

### 1. 架构层面：未接入 WorkBuddy API（最严重）

| 顶层设计要求 | 当前实现 |
|-------------|---------|
| 前端只展示，不计算状态 | ✅ 部分符合（前端确实只展示） |
| 前端不直接写 JSON，通过 WorkBuddy API 写 | ❌ 完全没有 API 交互 |
| WorkBuddy 计算掌握度、等级、next_review | ❌ 无 |
| JSON 文件层是真相源 | ❌ 数据硬编码在 JS 数组里 |
| 前端读取 `02-读书笔记/理论/*.json` | ❌ 无文件读取 |

**结论**：v4 目前是一个独立运行的前端 demo，没有后端/WorkBuddy 支撑，也没有持久化。

### 2. 数据层面：硬编码 vs JSON 真相源

顶层设计要求每张卡片是一个独立 JSON 文件，包含完整字段：
```json
{
  "id": "gui-zhi-tang",
  "type": "formula_card",
  "formula_name": "桂枝汤",
  "tags": [...],
  "data": { source_text, symptoms, pathology, herbs, usage, contraindications, ... },
  "experiences": [...],
  "mastery": { "0→1": {...}, "1→0": {...}, ... 共8个向量 }
}
```

当前实现只有三个分离的 JS 数组：
```js
const CARDS = [...];       // 5个卡片的元数据
const CARD_DATA = [...];   // 学习内容
const EXAM_DATA = [...];   // 考试数据
```

**问题**：
- 同一方剂的数据分散在三个数组，容易不同步
- 没有 `mastery` 字段，无法追踪掌握度
- 没有 `experiences` 经验卡片
- 没有 `allow_multiple`、`mapping_note` 等字段

### 3. 训练向量：5个 vs 8个

顶层设计定义了 **8个训练向量**：
- `0→1` 方名→症状
- `1→0` 症状→方名
- `0→2` 方名→药物
- `2→0` 药物→方名
- `0→3` 方名→用法
- `3→0` 用法→方名
- `0→4` 方名→病机
- `4→0` 病机→方名

当前实现只实现了 **5个向量**，缺少：
- ❌ `3→0` 用法→方名
- ❌ `0→4` 方名→病机
- ❌ `4→0` 病机→方名

### 4. 掌握度系统：静态写死 vs 完整状态机

| 顶层设计 | 当前实现 |
|---------|---------|
| 8个向量独立掌握度 | ❌ 无 |
| 状态：未知/从未掌握/正在学习/已掌握/已遗忘 | ❌ 无 |
| level 0-5 艾宾浩斯等级 | ❌ 无 |
| streak_right / streak_wrong | ❌ 只有当前 session 的临时计数 |
| total_rights / total_wrongs / history | ❌ 无 |
| 答对升级、答错降级规则 | ❌ 无 |
| 卡片堆状态机（卡池→等待区→待复习堆→抽检堆） | ❌ 无 |

当前右栏的"掌握度"进度条是**写死的静态 HTML**，没有实际计算逻辑。

### 5. AI 导师：完全缺失

顶层设计要求：
- 前端调用 LLM API（用户自己的 Kimi API）
- 使用 `ai_tutor/prompt.md` 作为 system prompt
- 对话生成三级笔记，存入 `ai_tutor/notes/`
- 原始对话记录存入 `session_logs/`

当前实现：❌ **完全没有 AI 导师功能**。

### 6. 每日任务与快速筛选：完全缺失

顶层设计要求：
- 每日凌晨 WorkBuddy 生成 `tasks/daily_YYYYMMDD.json`
- 快速筛选测试（3-5题）找出今日学习目标
- ZPD 驱动的今日学习路径

当前实现：❌ 只有静态的"开始考试"按钮，没有任务系统。

### 7. 随机测试（抽检）：只有占位符

顶层设计要求：
- 从"待随时抽检堆"抽取 level=5 的向量
- 只记录结果，不改变学习进度
- 答错后 status 变为"已遗忘"，重新进入复习流

当前实现：
```js
function randomTest() {
  alert('随机测试 — 原型演示');
}
```
❌ 只是弹窗占位。

### 8. 文件组织结构：单文件 vs 完整目录体系

顶层设计定义了完整的目录结构：
```
Claw/
├── 02-读书笔记/理论/
│   ├── gui-zhi-tang.json
│   ├── experiences/
│   ├── raw_materials/
│   └── session_logs/
├── 03-工作项目/伤寒论金匮要略训练系统/
│   ├── MISSION.md
│   ├── ai_tutor/prompt.md
│   ├── ai_tutor/notes/
│   └── tasks/
```

当前实现：❌ 只有桌面上的一个 HTML 文件。

### 9. 多选题与映射唯一性：缺失

顶层设计要求：
- `allow_multiple` 字段标记映射不唯一时需出多选题
- `mapping_note` 备注映射不唯一的情况
- 制卡迭代流程解决映射冲突

当前实现：❌ 完全没有这些概念。

### 10. 课程与参考文档：缺失

顶层设计要求：
- `lessons/*.html` 自包含短课程
- `reference/*.html` 备忘单/速记卡

当前实现：❌ 无。

## 三、代码质量问题（独立观察）

除了上述与设计的差距，v4 代码本身也存在一些需要修复的问题：

### 1. 单文件耦合严重
- 1296 行 HTML/CSS/JS/数据全在一个文件
- 不利于维护、版本控制和扩展

### 2. 硬编码导致扩展困难
- 新增一个方剂需要同时改 `CARDS`、`CARD_DATA`、`EXAM_DATA`、`getQuestionText()` 里的题目、`renderOptions()` 里的选项分支
- 这是反模式，应改为从统一数据中自动生成题目和干扰项

### 3. 存在实际 Bug
- **进度统计不准确**：`completed = examState.currentQ`，提交后 currentQ 未增加，导致统计滞后一题
- **markDispute 可能取到 undefined**：`examState.questions[examState.currentQ-1]` 在边界情况下会越界
- **学习模式下按 O/P 也会触发 markDispute**：而此时没有有效题目

### 4. 大量使用 `innerHTML`
- 如果未来接入用户输入或后端数据，会有 XSS 风险
- 静态文本建议改用 `textContent`

### 5. 数据没有持久化
- 考试结果、掌握度、主题设置（除主题外）全部不保存
- 刷新页面即丢失

## 四、下一步建议（按优先级）

### P0：必须先做（否则无法对齐顶层设计）

1. **建立 JSON 真相源**
   - 把 `CARDS`/`CARD_DATA`/`EXAM_DATA` 合并为顶层设计要求的单卡片 JSON 格式
   - 先创建 `02-读书笔记/理论/gui-zhi-tang.json` 等 5 个卡片文件
   - 每个卡片包含完整的 8 个向量 mastery 字段（初始化为"未知"）

2. **定义 WorkBuddy API 接口**
   - 前端如何提交答题结果
   - WorkBuddy 如何返回更新后的 mastery 状态
   - 接口字段、请求格式、错误处理

3. **实现掌握度状态机**
   - 按 v3.0 的晋级/降级规则实现
   - 计算 level、status、next_review
   - 写入卡片 JSON 的 mastery 字段

### P1：尽快补齐

4. **接入 AI 导师**
   - 创建 `ai_tutor/prompt.md`
   - 前端调用 LLM API（Kimi）
   - 实现三级笔记写入 `ai_tutor/notes/`

5. **补齐 8 个训练向量**
   - 新增 `用法→方名`、`方名→病机`、`病机→方名` 三种题型

6. **拆分文件结构**
   - 把单文件拆分为 HTML + CSS + JS + data/*.json

### P2：优化体验

7. **修复已知 Bug**
   - 进度统计、markDispute 边界、快捷键跨模式冲突

8. **实现每日任务和快速筛选**
   - WorkBuddy 每日生成任务文件
   - 前端读取并展示今日学习路径

9. **增加数据持久化**
   - 考试记录、掌握度、学习历史保存到 JSON

---

## 五、一句话总结

> v4 是一个**合格的前端原型**，证明了"卡片展示 + 四选一考试 + 答题反馈"的交互是可行的；但它目前**完全没有接入顶层设计定义的数据层、状态层和 WorkBuddy API**，距离可用产品还有较大距离。下一步的关键不是继续美化前端，而是**先建立 JSON 真相源 + WorkBuddy API + 掌握度状态机**。
