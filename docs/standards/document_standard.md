# 项目文档元信息头标准

> **适用范围**: `D:\Users\Chen\Desktop\经方学习系统（旧版）` 及其子目录下的所有 `.md` 文件  
> **强制执行**: 2026-07-02 起，所有新建/修改的 `.md` 文件必须包含此元信息头  
> **自举**: 本文档本身已按此标准格式化

## 一、元信息头模板（必须包含）

所有 `.md` 文件的最顶部（第1行开始）必须包含以下元信息头：

```markdown
---
文档编号: SH-{类型}-{YYYYMMDD}-{NNN}
版本: v{主}.{次}
日期: YYYY-MM-DD
用途: {一句话说明本文档的作用}
关联文档:
  · {关联文档编号} — {关联文档名}
  · {关联文档编号} — {关联文档名}
状态: {初稿/活跃/已确认/已归档}
变更历史:
  | 日期 | 版本 | 变更人 | 变更内容 | 影响范围 |
  |------|------|--------|----------|----------|
  | YYYY-MM-DD | vX.X | {人} | {内容} | {范围} |
---
```

### 1.1 字段说明

| 字段 | 必填 | 格式 | 说明 |
|------|------|------|------|
| `文档编号` | 是 | SH-{类型}-{YYYYMMDD}-{NNN} | 全局唯一标识符 |
| `版本` | 是 | v{主}.{次} | 语义化版本，重大变更升主版本 |
| `日期` | 是 | YYYY-MM-DD | 本文档最后更新日期 |
| `用途` | 是 | 一句话 | 本文档的核心作用，30字以内 |
| `关联文档` | 是 | 列表 | 反向链接，指向相关文档（至少1个） |
| `状态` | 是 | 枚举 | 当前文档的生命周期状态 |
| `变更历史` | 是 | 表格 | 所有版本变更记录，按时间倒序 |

### 1.2 编号规则

**文档编号格式**: `SH-{类型}-{YYYYMMDD}-{NNN}`

| 类型前缀 | 含义 | 适用场景 | 示例 |
|----------|------|----------|------|
| `ARCH` | 架构设计 | 系统架构、Schema设计、技术选型 | SH-ARCH-20260702-001 |
| `DESIGN` | 功能设计 | 具体功能的设计文档 | SH-DESIGN-20260702-001 |
| `REQ` | 需求文档 | 交互需求、功能需求 | SH-REQ-20260702-001 |
| `REPORT` | 分析报告 | 调研、评估、统计报告 | SH-REPORT-20260702-001 |
| `DECISION` | 决策记录 | 关键决策及理由 | SH-DECISION-20260702-001 |
| `EXPERIENCE` | 经验记录 | 踩坑、流程、方法论 | SH-EXPERIENCE-20260702-001 |
| `STD` | 标准规范 | 文档标准、命名规范、流程规范 | SH-STD-20260702-001 |
| `PLAN` | 执行计划 | 具体任务的执行计划 | SH-PLAN-20260702-001 |
| `PROMPT` | 提示词 | 给AI对话的提示词 | SH-PROMPT-20260702-001 |
| `CHANGELOG` | 变更登记 | 全局变更历史 | SH-CHANGELOG-20260702-001 |
| `SNAPSHOT` | 进度快照 | 阶段性进度记录 | SH-SNAPSHOT-20260702-001 |

**编号递增规则**:
- 同一天同一类型，从 `001` 开始递增
- 跨天创建：日期部分更新，`NNN` 重新从 `001` 开始
- 文档迁移/复制：编号不变，版本更新

## 二、状态机定义

```
[初稿] ──审阅通过──→ [活跃] ──稳定使用──→ [已确认] ──过期/替代──→ [已归档]
   ↑                      ↓                      ↓
  修订                  废弃                   更新
   │                      │                      │
   └───重大修改后返回────┘                      └───创建新版本，旧版归档──→ [已归档]
```

| 状态 | 定义 | 能否修改 | 修改规则 |
|------|------|----------|----------|
| **初稿** | 刚创建，尚未经过审阅 | ✅ 可自由修改 | 无需更新版本号，修改后直接进入活跃 |
| **活跃** | 正在使用，可能持续更新 | ✅ 可修改 | 每次修改必须更新版本号（小版本+1） |
| **已确认** | 经过审阅，相对稳定 | ⚠️ 谨慎修改 | 重大修改需创建新版本（大版本+1），旧版归档 |
| **已归档** | 历史版本，不再更新 | ❌ 不可修改 | 仅参考，如需修改则创建新文档 |

**状态切换触发条件**:
- 初稿 → 活跃：用户/AI确认"此文档可用"
- 活跃 → 已确认：用户明确说"此文档已确认，不再大改"
- 活跃 → 已归档：用户明确说"此文档已废弃/替代"
- 已确认 → 已归档：被新版文档替代，或内容过期

## 三、关联文档规则

### 3.1 为什么要关联文档

- 文档之间形成知识图谱，AI可以自动追踪依赖链
- 查找相关文档时，不需要凭记忆
- 变更影响分析：修改某文档时，可以快速找到所有关联文档

### 3.2 关联文档格式

```markdown
关联文档:
  · SH-ARCH-20260702-001 — 系统架构总览
  · MISSION.md — 项目使命
  · 对话总控看板.md — 多对话协作状态
```

**规则**:
- 至少关联1个文档（通常是父级或上游文档）
- 使用文档编号（如有）+ 文档名
- 关联文档应该是真正相关的，不要硬凑
- 关联文档本身也应在变更历史中记录反向链接

## 四、变更历史规则

### 4.1 变更历史表格格式

```markdown
变更历史:
  | 日期 | 版本 | 变更人 | 变更内容 | 影响范围 |
  |------|------|--------|----------|----------|
  | 2026-07-02 | v1.0 | AI | 初始版本 | 新建 |
  | 2026-07-03 | v1.1 | 陈医生 | 补充编号规则 | 全局 |
  | 2026-07-05 | v2.0 | AI | 重写状态机定义 | 全局 |
```

**规则**:
- 按时间倒序排列（最新变更在最上面）
- 每次修改必须新增一行记录
- `变更内容` 用一句话概括，不超过20字
- `影响范围` 用关键词：全局/局部/新建/修正/归档

### 4.2 版本号递增规则

| 变更类型 | 版本号变化 | 示例 | 说明 |
|----------|-----------|------|------|
| 初始创建 | v1.0 | v0.0 → v1.0 | 新建文档 |
| 小修正 | 小版本+1 | v1.0 → v1.1 | 错别字、补充示例、格式调整 |
| 内容更新 | 小版本+1 | v1.1 → v1.2 | 新增字段、更新数据、补充说明 |
| 结构重写 | 大版本+1 | v1.9 → v2.0 | 状态机变化、编号规则变化、架构变化 |
| 文档替代 | 新文档 | v2.0(旧) → v1.0(新) | 旧版归档，新版创建 |

## 七、迁移指南（现有文档如何处理）

### 7.1 新建文档
- **必须**按此标准执行，无例外

### 7.2 现有文档（逐步迁移）
- 不一次性全部修改，避免混乱
- 每次修改某文档时，顺手添加元信息头
- 优先级：核心文档 > 设计文档 > 经验文档 > 分析报告
- 迁移时版本号从 v1.0 开始（视为"首次标准化"）

### 7.3 变更历史补登
- 现有文档的变更历史，如能追溯则补登
- 如无法追溯，第一行写：`| 2026-07-02 | v1.0 | 陈医生/AI | 文档标准化（补登） | 全局 |`
- 后续变更正常记录

## 八、常见错误与修正

| 错误 | 示例 | 修正 |
|------|------|------|
| 缺少分隔符 | `文档编号: SH-xxx` 无 `---` | 顶部和底部加 `---` |
| 编号格式错误 | `SH-2026-07-02-001` | `SH-STD-20260702-001`（无分隔符） |
| 版本号格式错误 | `V1.0` 或 `1.0` | `v1.0`（小写v） |
| 日期格式错误 | `2026年7月2日` | `2026-07-02` |
| 状态拼写错误 | `草稿` | `初稿`（固定枚举） |
| 变更历史正序 |  oldest 在最上面 |  newest 在最上面（倒序） |
| 关联文档无编号 | `· 系统架构` | `· SH-ARCH-20260702-001 — 系统架构` |
