## 需求背景

用户希望在学习页面中增加一个**条文系统**，功能要点：

1. 浮动按钮增加 **"S"（条文/条文）**按钮，在"N"（笔记）按钮下方
2. 点击"S"打开条文系统，显示该方剂关联的所有**原文条文**
3. 每条条文有独立功能：
   - **"问 Kimi"** 按钮（与方剂卡片的逻辑一致）
   - **"记笔记"** 按钮（可记录对该条文的理解）
4. **双向链接**：条文与方剂卡片可互相跳转
5. **位置**：在经验记录下方，笔记上方（见图中标注位置）

---

## 方案 A：内联条文区块（Slide-down 展开）

### 设计理念

**"不跳出当前页面，保持学习沉浸感"**。

条文系统作为学习页面的一个可折叠区块，展开后直接嵌入到页面流中。用户在阅读方剂和条文之间无需切换上下文，所有操作在同一页面内完成。适合深度学习场景，条文就是方剂的"上下文材料"，与方剂本身融为一体。

### 视觉呈现

```
┌─────────────────────────────────────────────────────┐
│  左栏              │  右栏                            │
│  ────────────────────  ─────────────────────────────│
│  原文条文            │  病机 [显示]                     │
│  症状谱              │  禁忌 [显示]                     │
│  核心药物            │  煎服法 [显示]                   │
│  药物组成            │  参考资料                        │
│                     │  经验记录                        │
│                     │  ──────────────────────          │
│                     │  📜 条文系统 [S]                  │  ← 点击S展开
│                     │  ┌─────────────────┐             │
│                     │  │ 条文① 太阳病... │ 问Kimi 📒   │  ← 每条条文卡片
│                     │  │ 条文② 太阳病... │ 问Kimi 📒   │
│                     │  └─────────────────┘             │
│                     │  ──────────────────────          │
│  📝 我的笔记         │  ← 笔记仍位于最底部              │
│  [编辑]              │                                  │
└─────────────────────────────────────────────────────┘
```

### 交互流程

1. 点击右下角"S"按钮 → 滚动到"条文系统"区块并展开
2. 每条条文以卡片形式展示，默认显示原文前30字，点击展开全文
3. 展开后显示：原文完整文本、问Kimi按钮、记笔记按钮
4. 点击"问Kimi" → 打开条文专属的Kimi prompt（基于该条文内容）
5. 点击"记笔记" → 打开文本编辑器，输入该条文的理解笔记
6. 笔记保存后，在条文卡片下方显示笔记摘要（可点击展开）

### 数据结构

```json
{
  "id": "gui-zhi-tang-src-001",
  "type": "source_card",
  "source": "伤寒论",
  "chapter": "太阳病篇",
  "text": "太阳病，头痛，发热，汗出，恶风，桂枝汤主之。",
  "mentioned_formulas": ["桂枝汤"],
  "symptoms": ["汗出", "恶风"],
  "note": "用户记录的条文笔记",
  "noteUpdatedAt": "2026-06-17T22:00:00"
}
```

### 优点
- 不打断学习流，所有信息在同一页面内
- 条文与方剂内容直观并列，方便对比阅读
- 实现简单，无需额外弹窗/面板管理

### 缺点
- 页面内容会变长，需要更好的滚动管理
- 多条条文堆叠时可能占据过多空间

## 方案 B：侧边抽屉面板（Slide-in 面板）

### 设计理念

**"核心内容不遮挡，侧边可扩展的辅助空间"**。

条文系统作为右侧抽屉面板，从页面边缘滑出。这样可以在展示条文的同时，不遮挡当前的方剂内容。适合"查阅式"学习场景：用户想快速查看条文原文，但不想打乱当前页面的布局。

### 视觉呈现

```
┌─────────────────────────────────────────────────────┐
│  左栏              │  右栏              │  条文面板   │
│  ────────────────────  ───────────────────  ┌──────│
│  原文条文            │  病机 [显示]      │  📜 条文   │  ← 滑动展开
│  症状谱              │  禁忌 [显示]      │  ──────  │
│  核心药物            │  煎服法 [显示]    │  ① 太阳..│  ← 条文列表
│  药物组成            │  参考资料         │  ② 太阳..│
│                     │  经验记录         │  ──────  │
│                     │                   │  📖 原文  │  ← 当前条文详情
│                     │                   │  太阳病..│
│  📝 我的笔记         │                   │  🤖问Kimi│  ← 按钮
│  [编辑]              │                   │  📝 笔记 │  ← 按钮
└─────────────────────────────────────────────────────┘
```

### 交互流程

1. 点击"S"按钮 → 右侧滑出条文面板，覆盖在页面右侧（宽度约300px）
2. 面板分三栏：
   - **顶部**：面板标题"📜 条文系统" + 关闭按钮
   - **左侧**（占面板30%）：条文列表，点击切换当前条文
   - **右侧**（占面板70%）：当前条文详情
3. 详情区包含：原文完整文本、章节信息、问Kimi按钮、记笔记区域
4. 笔记输入为内联文本框，输入后实时保存
5. 点击"X"或再次点击"S"按钮 → 面板滑出，页面恢复原状

### 优点
- 不遮挡主页面内容，主页面布局不受影响
- 条文列表和详情分栏，方便在多条条文间快速切换
- 视觉上有"进入子系统"的感觉，适合条文深度阅读

### 缺点
- 在窄屏设备上（如平板竖屏），面板可能占据过多空间
- 需要额外的面板管理逻辑（打开/关闭/状态保持）
- 与方剂页面的"交互流"略有分离感

## 方案 C：弹窗模态框（Modal 弹窗）

### 设计理念

**"全屏沉浸式条文阅读，专注深度研读"**。

条文系统以模态框形式全屏或半屏展示，给用户提供一个专注的条文研读环境。适合"条文精读"场景：用户想要脱离方剂页面，纯粹地阅读、分析、笔记条文内容。

### 视觉呈现

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│  ┌─────────────────────────────────────────────┐  │
│  │  📜 条文系统 ──────────────── [×] 关闭      │  │  ← 模态框头部
│  │  ─────────────────────────────────────────  │  │
│  │  ┌───────────┐  ┌────────────────────────┐  │  │
│  │  │ 条文列表   │  │ 📖 条文原文              │  │
│  │  │ ① 太阳..   │  │ ──────────────────────  │  │
│  │  │ ② 太阳..   │  │ 太阳病，头痛，发热..     │  │
│  │  │ ③ 太阳..   │  │ ──────────────────────  │  │
│  │  │            │  │ 🤖 问Kimi  📝 记笔记      │  │
│  │  │            │  │ ──────────────────────  │  │
│  │  │            │  │ 📝 我的笔记              │  │
│  │  │            │  │ 此处粘贴从Kimi复制的..     │  │
│  │  │            │  │ ──────────────────────  │  │
│  │  │            │  │ 🔗 关联方剂：桂枝汤      │  │  ← 双向链接
│  │  └───────────┘  └────────────────────────┘  │  │
│  └─────────────────────────────────────────────┘  │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 交互流程

1. 点击"S"按钮 → 弹出模态框，背景半透明遮罩
2. 模态框内分栏：
   - **左侧栏**：条文列表（按章节排序），点击切换当前条文
   - **右侧栏**：当前条文详情区
3. 详情区从上到下：
   - 原文完整文本（大字号，突出显示）
   - 操作按钮："问Kimi"（打开条文专属prompt）+"记笔记"（展开文本编辑器）
   - 笔记区域（有笔记时显示，可编辑）
   - 关联信息：章节、关联方剂（可点击跳回方剂卡片）
4. 点击"×"或按 Esc → 关闭模态框，返回方剂页面

### 优点
- 全屏沉浸式体验，适合深度研读条文
- 条文列表和详情分栏清晰，不拥挤
- 模态框有"进入子系统"的心理暗示，专注度高
- 可扩展性强（未来可增加条文对比、条文检索等）

### 缺点
- 完全遮挡了原页面内容，无法同时看方剂和条文
- 需要频繁打开/关闭，对于"快速查阅"不太方便
- 实现复杂度最高，需要管理模态框状态、动画、遮罩等

## 三方案对比

| 维度 | 方案A：内联区块 | 方案B：侧边面板 | 方案C：弹窗模态 |
|---|---|---|---|
| **学习体验** | 不跳出，沉浸感强 | 可扩展，主页面可见 | 全屏专注，沉浸最强 |
| **页面遮挡** | 不遮挡，但会变长 | 轻微遮挡右边缘 | 完全遮挡 |
| **实现复杂度** | ⭐⭐ 低 | ⭐⭐⭐ 中 | ⭐⭐⭐⭐ 高 |
| **适合场景** | 深度对比学习 | 快速查阅条文 | 条文精读 |
| **多条文切换** | 需要滚动 | 侧边列表快速切换 | 左侧列表快速切换 |
| **笔记体验** | 内联编辑器 | 内联编辑器 | 大空间编辑器 |
| **与页面融合** | 融为一体 | 辅助扩展 | 独立子系统 |

---

## 推荐倾向

- **如果用户主要想"在看方剂的同时扫一眼条文"** → 方案A
- **如果用户想"频繁在多条条文间切换"** → 方案B
- **如果用户想"专注研读某条条文，做大量笔记"** → 方案C
