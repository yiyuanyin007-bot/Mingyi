# 统计视图设计方案 v1.0

> **日期**：2026-06-15  
> **背景**：用户要求统计视图不只是展示数字，而是成为「学习者的参谋」——告诉用户今天学了什么、哪里薄弱、明天该优先复习什么。  
> **设计原则**：数据说话，建议可执行，界面不堆砌。

---

## 一、数据模型设计

### 1.1 需要新增的数据记录

目前系统只记录了「掌握度」（level、status、streak、next_review），但不足以支撑用户想要的统计功能。需要补充：

| 数据项 | 记录内容 | 用途 | 存储位置 |
|--------|----------|------|----------|
| `answer_history` | 每次答题记录：时间、卡片、向量、对错 | 统计错误率、学习次数 | `localStorage` |
| `daily_log` | 每天学习的方剂列表、答题数 | 今天学了哪些 | `localStorage` |
| `card_stats` | 每张方剂的累计答题数、错误数 | 学习次数最多、错误率最高 | `localStorage` |

### 1.2 数据结构定义

```json
{
  "answer_history": [
    {
      "timestamp": "2026-06-15T10:30:00Z",
      "cardId": "gui-zhi-tang",
      "cardName": "桂枝汤",
      "vector": "0→1",
      "vectorLabel": "方名→症状",
      "isCorrect": false,
      "mode": "practice-card"
    }
  ],
  "daily_log": {
    "2026-06-15": {
      "cardIds": ["gui-zhi-tang", "ma-huang-tang"],
      "totalQuestions": 12,
      "right": 8,
      "wrong": 4
    }
  },
  "card_stats": {
    "gui-zhi-tang": {
      "totalAttempts": 15,
      "totalErrors": 5,
      "errorRate": 0.33,
      "lastError": "2026-06-15T10:30:00Z",
      "vectorErrors": {
        "0→1": 2,
        "1→0": 1,
        "0→2": 2
      }
    }
  }
}
```

### 1.3 数据记录时机

| 时机 | 记录内容 | 更新位置 |
|------|----------|----------|
| 练习/考试答题后 | answer_history 追加一条 | `localStorage` |
| 练习/考试答题后 | card_stats[cardId] 更新累计次数和错误数 | `localStorage` |
| 每日首次答题时 | daily_log[今天] 初始化 | `localStorage` |
| 每日答题后 | daily_log[今天] 更新题数和卡片列表 | `localStorage` |

## 二、统计视图界面设计

### 2.1 页面布局（三栏/卡片式）

```
┌──────────────────────────────────────────────────┐
│  学习统计                              [返回仪表盘]  │
├──────────────────────────────────────────────────┤
│  ┌──────────────┐  ┌──────────────┐  ┌────────────┐ │
│  │ 今日概览      │  │ 方剂排行      │  │ 薄弱分析    │ │
│  │              │  │              │  │            │ │
│  │ 12题 8对 4错  │  │ 错误率最高    │  │ 最弱向量    │ │
│  │ 正确率 67%   │  │ 学习次数最多  │  │ 复习建议    │ │
│  │              │  │              │  │            │ │
│  └──────────────┘  └──────────────┘  └────────────┘ │
├──────────────────────────────────────────────────┤
│  今日复习建议（按优先级排序）                       │
│  ┌──────────────────────────────────────────────┐  │
│  │ 🔴 桂枝汤 — 方名→症状 错误率 67% (今天错2次) │  │
│  │ 🟡 麻黄汤 — 症状→方名 错误率 50% (昨天错1次) │  │
│  │ 🟢 小柴胡汤 — 全部掌握 随机抽检              │  │
│  └──────────────────────────────────────────────┘  │
├──────────────────────────────────────────────────┤
│  历史趋势（最近7天）                              │
│  [简单柱状图：每天答题数/正确数]                    │
└──────────────────────────────────────────────────┘
```

### 2.2 模块详细说明

#### 模块 A：今日概览

| 数据 | 来源 | 说明 |
|------|------|------|
| 今日答题数 | `daily_log[今天].totalQuestions` | 今天答了多少题 |
| 今日正确数 | `daily_log[今天].right` | 今天答对多少 |
| 今日错误数 | `daily_log[今天].wrong` | 今天答错多少 |
| 正确率 | 计算 | 正确数 / 答题数 |
| 今日学习方剂数 | `daily_log[今天].cardIds.length` | 今天涉及多少张方 |

#### 模块 B：方剂排行（两个子排行）

**错误率最高（TOP 5）**：
- 排序：`cardStats[cardId].errorRate` 降序
- 显示：方名、累计答题数、错误次数、错误率
- 条件：只显示累计答题 ≥ 3 次的（避免只答1次就100%错误率的误导）

**学习次数最多（TOP 5）**：
- 排序：`cardStats[cardId].totalAttempts` 降序
- 显示：方名、累计答题数、错误率、最近复习时间

#### 模块 C：薄弱分析

**最弱向量**：
- 遍历 `cardStats` 中 `vectorErrors`，统计每个向量的总错误数
- 显示：向量类型（如"方名→症状"）、总错误次数、涉及方剂数

**向量覆盖度**：
- 已掌握向量数 / 总向量数（210个）
- 各向量类别的掌握进度

## 三、复习建议算法（核心）

### 3.1 用户原始需求

> "今天刚错的可以先不提醒，而是要重点提醒那些经常错、每天都错的方剂和剂量"

这意味着复习建议不是简单的「今天错了明天复习」，而是需要**历史权重**和**错误模式分析**。

### 3.2 优先级计算模型

每张方剂的每个向量，计算一个「复习优先级分数」：

```
priority_score = error_weight × recency_penalty × streak_factor

其中：
- error_weight = 累计错误数 / 累计答题数（错误率）
- recency_penalty = 1 / (1 + 0.1 × 距离上次错误的天数)
  → 今天刚错的：recency_penalty ≈ 1.0
  → 3天前错的：recency_penalty ≈ 0.77
  → 7天前错的：recency_penalty ≈ 0.59
- streak_factor = 1 + 连续错误次数 × 0.3
  → 连续错3次的：streak_factor = 1.9
```

**关键设计**：
- 今天刚错的项目：recency_penalty 高，但可以通过**设置冷却期**（如今天错的不进入明日复习）来降低优先级
- 经常错的项目：error_weight 高，即使已经过了几天，仍然优先级高
- 连续错的项目：streak_factor 进一步放大优先级

### 3.3 复习建议列表生成

```
1. 计算所有向量（已掌握的不算）的 priority_score
2. 过滤掉「今天刚错」的（冷却期1天）
3. 按 priority_score 降序排序
4. 取前5个作为「建议优先复习」
5. 如果前5个不够，补充已掌握的随机抽检（保持手感）
```

### 3.4 显示格式

| 优先级 | 颜色 | 显示内容 | 操作 |
|--------|------|----------|------|
| 🔴 高 | 红色 | 方名 + 向量 + 错误率 + "连续错X次" / "X天内错Y次" | 点击直接开始该向量练习 |
| 🟡 中 | 黄色 | 方名 + 向量 + 错误率 + 上次错误时间 | 点击直接开始该向量练习 |
| 🟢 低 | 绿色 | 方名 + 向量 + "已掌握，随机抽检" | 点击直接开始该向量练习 |

## 四、实现方案

### 4.1 优先级（分两轮实现）

| 轮次 | 内容 | 预计时间 | 风险 |
|------|------|----------|------|
| **Round 1** | 数据记录层（answer_history + card_stats + daily_log）+ 今日概览 + 方剂排行 | 1天 | 低，纯数据逻辑 |
| **Round 2** | 薄弱分析 + 复习建议算法 + 历史趋势图 + 点击跳转练习 | 1-2天 | 中，算法需要调试 |

### 4.2 技术实现

**数据记录**：在 `handleSelectOption` 中，答完题后追加记录：
```javascript
function recordAnswerHistory(cardId, vector, isCorrect, mode) {
  // 追加 answer_history
  // 更新 card_stats[cardId]
  // 更新 daily_log[今天]
}
```

**统计视图**：新建 `StatsView.js` 组件：
- 从 `localStorage` 读取所有统计数据
- 计算排行、薄弱分析、复习建议
- 渲染为三栏布局

**复习建议跳转**：点击建议项 → 直接生成该向量题目 → 进入练习模式

### 4.3 与现有系统的集成

- 统计视图入口：顶部栏「统计」按钮点击后 `setPage('stats')`
- 数据持久化：所有统计数据存到 `localStorage` 新键 `sh_v9_stats`
- 不影响现有功能：统计数据是「只读分析」，不修改掌握度或复习间隔

## 六、待确认的问题

1. **历史数据量**：`answer_history` 只保留最近 30 天还是全部保留？（建议 30 天，避免 localStorage 超限）
2. **错误率计算**：累计答题 ≥ 3 次才算有效样本？还是 ≥ 5 次？
3. **冷却期**：今天错的题目，明天是否完全不进入复习建议？还是只是降低优先级？
4. **历史趋势图**：用简单 CSS 柱状图还是 SVG 图表？（建议 CSS 柱状图，简单可靠）
5. **点击跳转**：复习建议点击后，是直接开始单题练习（只出该向量1题），还是进入该卡片的完整练习？

## 七、总结

**统计视图的核心价值**：不是「告诉你答了多少题」，而是「告诉你明天该学什么」。

实现路径：
1. 先实现数据记录层（答一题记一笔）
2. 再实现统计计算（排行、薄弱分析）
3. 最后实现复习建议算法（优先级计算 + 冷却期）

**我的建议**：先实现 Round 1（数据记录 + 今日概览 + 方剂排行），这样用户能立即看到「今天学了什么」和「哪里最薄弱」。Round 2（复习建议算法）作为增强功能，在 Round 1 稳定后实现。
