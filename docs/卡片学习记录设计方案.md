# 卡片学习记录设计方案

> 目标：在仪表盘卡片列表中，为每张方剂卡片增加"学习记录"信息，帮助用户一眼掌握学习进度、错误分布和复习节奏。

---

## 1. 数据可用性分析

### 1.1 当前可读取的数据

| 数据源 | 字段 | 说明 | 当前状态 |
|---|---|---|---|
| `mastery`（卡片内嵌） | 6向量状态 | 0→1/1→0/0→2/2→0/0→usage/0→contra | ✅ 每个卡片都有，状态为"未知"/"已掌握"/"学习中" |
| `mastery.next_review` | 下次复习时间 | 毫秒时间戳，0表示未设定 | ✅ 可读取 |
| `traces`（学习轨迹） | 类型+时间戳 | card_view/section_view/exam/wrong等 | ⚠️ 当前为空，但代码已实现记录功能，使用后会逐步累积 |
| `study_notes`（错题本） | 错题记录 | 题目/错因/笔记/复习计划 | ⚠️ 当前为空，但代码已实现，使用后会逐步累积 |
| `exam.answers` | 最近考试答案 | 正确/错误/选择 | ⚠️ 当前为空，但考试结束后会保留 |

### 1.2 数据可读取性确认

✅ **mastery 数据已确认可读取**：每个卡片的 6 个向量有 `status` 和 `next_review` 字段
✅ **traces 数据结构已确认**：每条 trace 包含 `type`/`timestamp`/`cardId`/`formulaName`，可按 cardId 过滤
✅ **study_notes 数据结构已确认**：每条笔记包含 `cardId`/`diagnosis`/`question`/`reviewSchedule`

**结论：需求可实现。所有数据源都有对应的读取函数，只是当前 traces/study_notes 为空（用户尚未使用这些功能）。**

---

## 2. 设计目标

1. **一瞥即知**：用户扫一眼卡片，就知道这张方剂的学习状态
2. **不显拥挤**：学习记录是卡片的"增值信息"，不能喧宾夺主
3. **渐进丰富**：数据越少越简洁，数据越多越详细（从 mastery 单点到 traces+错题本多维）
4. **区分状态**："还未学习"、"正在学习"、"已掌握"、"有错误"要有明显视觉区分

---

## 3. 三版方案

### 版本A：底部进度条版（最简洁）

**核心思想**：在卡片底部增加一行"6向量进度条"，用颜色点表示各向量状态。

**布局**：
```
┌────────────────────────────────────┐
│ 桂枝加葛根汤                       │
│ 太阳中风兼项背强痛                  │
│ [太阳病] [项背强几几] [汗出]       │
│ ──────────────────────────────────│
│  学习进度  ●○●○○○  3/6 掌握        │
│  上次学习: 2天前  ·  下次复习: 今天│
└────────────────────────────────────┘
```

**元素**：
- 6个圆点（直径8px），绿色=已掌握，灰色=未学习，橙色=学习中
- 进度数字（3/6 已掌握）
- 上次学习时间（从 traces 取最近一条）
- 下次复习时间（从 mastery.next_review 取最近一条，如果为0则不显示）
- 如果有错题，在右侧显示红色小徽章（💡 1条错题）

**优点**：最简洁，不占用额外空间，一瞥即知
**缺点**：信息密度低，无法展示具体哪个向量错了
**适用场景**：卡片列表浏览，快速筛选需要学习的卡片

### 版本B：详情展开版（信息最全）

**核心思想**：卡片默认显示简洁摘要，点击"展开记录"后显示详细学习数据。

**默认状态**：
```
┌────────────────────────────────────┐
│ 桂枝加葛根汤           [展开记录 ▼]│
│ 太阳中风兼项背强痛                  │
│ [太阳病] [项背强几几] [汗出]       │
│ 进度: ●●●○○○ 3/6 · 错题: 2       │
└────────────────────────────────────┘
```

**展开状态**：
```
┌────────────────────────────────────┐
│ 桂枝加葛根汤           [收起记录 ▲]│
│ 太阳中风兼项背强痛                  │
│ [太阳病] [项背强几几] [汗出]       │
│ ──────────────────────────────────│
│ 向量掌握状态                        │
│ 症状→方名 ●●●●○○ 4/6 已掌握       │
│ 方名→症状 ●●○○○○ 2/6 学习中       │
│ 方名→药组 ●○○○○○ 1/6 初学         │
│ 药组→方名 ●○○○○○ 1/6 初学         │
│ 禁忌      ○○○○○○ 0/6 未开始       │
│ 煎服法    ○○○○○○ 0/6 未开始       │
│ ──────────────────────────────────│
│ 学习轨迹                            │
│ 上次学习: 3天前 · 总计学习: 5次    │
│ 最近考试: 2天前 (答对3/5)          │
│ 下次复习: 今天 (2题待复习)         │
│ ──────────────────────────────────│
│ 错题记录                            │
│ 🔀 类方混淆: 1次 (桂枝汤 vs 桂枝加葛根汤) │
│ 🕳️ 知识缺口: 1次 (症状→方名)       │
└────────────────────────────────────┘
```

**优点**：信息最全，可以展示所有维度的学习记录
**缺点**：展开后卡片变高，需要滚动更多；默认状态不够直观
**适用场景**：用户想深入了解某张卡片的学习情况

### 版本C：侧边迷你版（平衡简洁与信息）

**核心思想**：在卡片内部右侧开辟一个"迷你学习面板"，用竖向进度条和关键指标展示学习状态。

**布局**：
```
┌────────────────────────────────────────────┐
│ 桂枝加葛根汤                    │ 学习记录 │
│ 太阳中风兼项背强痛              │ ┌────┐ │
│                                 │ │███│ │  3/6│
│ [太阳病] [项背强几几] [汗出]   │ │███│ │  掌握│
│                                 │ │░░░│ │     │
│                                 │ │░░░│ │     │
│                                 │ │░░░│ │     │
│                                 │ └────┘ │
│                                 │ 2天前  │
│                                 │ 2条错题│
│                                 │ 今天复习│
└────────────────────────────────────────────┘
```

**元素**：
- 右侧竖向进度条（6段，每段对应一个向量，填充表示掌握）
- 掌握数/总数（如 3/6）
- 上次学习时间（从 traces 取）
- 错题数量（从 study_notes 按 cardId 统计）
- 下次复习提示（从 mastery.next_review 取最近一条，如果今天到期则高亮）

**优点**：平衡了简洁和信息量，竖向进度条视觉独特，不占用卡片下方空间
**缺点**：卡片宽度需要增加，窄屏可能显示不全；设计复杂度高
**适用场景**：桌面版宽屏，卡片列表足够宽时

## 4. 数据读取逻辑（三版共用）

```javascript
// 获取卡片学习记录
function getCardStudyRecord(cardId) {
  const card = getCard(cardId);
  const mastery = card?.mastery || {};
  
  // 1. 向量掌握状态
  const vectorStatus = {};
  Object.keys(mastery).forEach(k => {
    vectorStatus[k] = mastery[k].status;
  });
  
  // 2. 已掌握数/总数
  const totalVectors = Object.keys(mastery).length;
  const masteredCount = Object.values(mastery).filter(m => m.status === '已掌握').length;
  
  // 3. 最近学习/考试时间（从 traces 取）
  const traces = getCardTraces(cardId); // 按 cardId 过滤 traces
  const lastStudy = traces.length > 0 ? traces[traces.length - 1].timestamp : null;
  
  // 4. 学习次数（从 traces 统计）
  const studyCount = traces.filter(t => t.type === 'card_view').length;
  const examCount = traces.filter(t => t.type === 'exam').length;
  
  // 5. 错题数（从 study_notes 按 cardId 统计）
  const wrongNotes = getCardStudyNotes(cardId); // 按 cardId 过滤错题
  const wrongCount = wrongNotes.length;
  
  // 6. 下次复习时间（从 mastery 取最近的 next_review）
  const nextReviews = Object.values(mastery)
    .map(m => m.next_review)
    .filter(t => t > 0);
  const nextReview = nextReviews.length > 0 ? Math.min(...nextReviews) : null;
  
  // 7. 错误分布（按 diagnosis 统计）
  const wrongDiagnoses = {};
  wrongNotes.forEach(n => {
    wrongDiagnoses[n.diagnosis] = (wrongDiagnoses[n.diagnosis] || 0) + 1;
  });
  
  return {
    vectorStatus, masteredCount, totalVectors,
    lastStudy, studyCount, examCount,
    wrongCount, nextReview, wrongDiagnoses
  };
}
```

## 5. 视觉设计规范（三版共用）

### 5.1 颜色系统
- **已掌握（绿色）**：`var(--success)` 或 `#22c55e`（实心圆点/填充段）
- **学习中（橙色）**：`var(--accent)` 或 `#f59e0b`（半实心或闪烁）
- **未学习/未知（灰色）**：`var(--text-muted)` 或 `#d1d5db`（空心圆点/空段）
- **有错题（红色）**：`var(--danger)` 或 `#ef4444`（小徽章或边框提示）
- **今天复习（高亮）**：背景色 `#fef3c7` 或浅黄色，配合 ⚠️ 图标

### 5.2 字体规范
- 进度数字：13px/600（中等字重）
- 时间提示：12px/400（灰色）
- 错题提示：12px/600（红色）

### 5.3 响应式
- **桌面版**：三版都可用，推荐A或C
- **手机版**：简化为版本A（底部进度条），版本B/C在小屏幕上信息过载

---

## 6. 推荐方案

根据当前数据状态（mastery 有但 traces/错题本为空）和用户的临床使用场景：

**短期推荐：版本A + 版本B的组合**
- 默认用版本A（底部进度条），最简洁，不干扰浏览
- 点击卡片进入学习页时，显示版本B的完整学习记录（详情面板）

**长期演进：版本C**
- 当 traces/错题本数据丰富后，版本C的侧边迷你面板能展示更多维度的信息
- 需要卡片宽度足够（桌面版 1200px 容器内可以容纳）
