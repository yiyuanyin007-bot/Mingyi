## 一、项目背景

### 1.1 项目定位

**项目名称**：《伤寒论》《金匮要略》方剂思维训练系统

**核心目标**：以倪海厦注解的《伤寒论》《金匮要略》为知识底座，构建方剂思维训练系统，提升中药开方思路。

**系统定位**（来自v3.0设计文档）：

| 组件 | 定位 | 说明 |
|------|------|------|
| 卡片体系 | 进度管理工具 | 筛选今天学什么、追踪掌握度、安排艾宾浩斯复习 |
| 真正学习 | 读原文 + AI导师对话 | 发生在卡片体系之外/之后，是学习的核心环节 |
| 前端程序 | 可视化呈现 | 用户自己写，读取JSON文件，调用AI导师API |
| WorkBuddy（佐助） | 后台支持 | 卡片提炼、设计文档、后台任务，不参与实时对话 |

### 1.2 原型开发目标

**原型阶段目标**：快速验证核心交互设计，不追求完整功能实现。

**原型阶段原则**：
- 只实现核心功能，未来再优化
- 使用mock数据，不连接真实API
- 专注交互体验，不关注性能优化
- 快速迭代，发现问题立即修复

## 二、原型开发生命周期

### 2.1 v1.0 原型（2026-06-11，初始版本）

**开发背景**：用户要求根据v3.0设计文档，快速出一个可交互的原型。

**核心功能**：
- 三栏布局（左：方剂卡片列表，中：学习详情，右：掌握度）
- 学习模式 / 考试模式切换
- 5道题目的考试流程
- 题目反馈功能

**已知问题**：
- 考试选项顺序固定（正确答案总在第一个位置）
- 左边卡片点击后中间内容不变
- "换个方式考你"功能未实现

### 2.2 v2.0 原型（2026-06-11，第一次迭代）

**开发背景**：用户测试v1.0后发现多个bug，要求修复。

**修复内容**：
1. **修复：考试选项顺序固定**
   - 问题：`submitAnswer()`中`correctAnswers = [0,0,0,0,0]`，正确答案索引硬编码为0
   - 修复：在`startNewExam()`中增加`correctAnswerText`字段；在`renderOptions()`中用Fisher-Yates算法随机打乱选项索引

2. **修复：左边卡片点击中间不变**
   - 问题：`renderLearnCenter()`函数为空，中间内容是静态写死的
   - 修复：在`renderLearnCenter()`中动态渲染卡片数据（CARD_DATA数组）

3. **修复：换个向量考不行**
   - 问题：`switchVectorExam()`函数只是弹了个alert，没有真正实现换向量的逻辑
   - 修复：修改`startNewExam(oldQuestions)`函数，支持换向量逻辑

**新增功能**：
- 实现"换个方式考你"功能（切换向量类型）
- 实现不同向量类型的题目生成（症状→方名、方名→症状、方名→药物、药物→方名、方名→用法）

### 2.3 v3.0 原型（2026-06-12，第二次迭代）

**开发背景**：用户继续测试v2.0，发现更多bug和新需求。

**修复内容**：
1. **修复：换了向量以后题目出错了**
   - 问题：correctAnswerText和options都是固定写死的方剂名称，没有根据向量类型变化
   - 修复：添加EXAM_DATA数据，修改startNewExam()根据向量类型设置correctAnswerText

2. **修复：桂枝汤煎煮服方法题目下有"干扰项4"选项**
   - 问题：renderOptions()中，当vector是"方名→用法"时，选项去重后只剩3个
   - 修复：改用EXAM_DATA.filter((_, i) => i !== q.cardIdx)来获取其他卡片的数据

3. **修复：药物黏在一起**
   - 问题：EXAM_DATA中herbs字段没有分隔符
   - 修复：herbs改成'桂枝、芍药、生姜、大枣、甘草'（添加"、"分隔符）

4. **修复：症状关键词黏在一起**
   - 问题：EXAM_DATA中symptom字段没有分隔符
   - 修复：symptom改成'发热、汗出、恶风、脉浮缓'（添加"、"分隔符）

**新增功能**：
1. **考试结束面板QWER交互**
   - 需求：考试结束后，按Q/W/E/R直接选择"再来复习"/"换个方式考你"/"随机测试"/"返回学习"
   - 实现：添加键盘事件监听，检测examEndPanel是否显示

2. **右侧栏重构**
   - 需求：右侧栏既要体现当下的时间和准确率，也要提示今日已完成多少题目
   - 实现：
     - 添加"今日已完成：X 题 ▼"入口，可点击展开/收起
     - 展开后显示卡片列表（名称、掌握度、状态、跳转按钮）
     - "本次统计"显示进度（X/5）、正确率%、连续对次数
     - 使用localStorage持久化每日统计

3. **修复：右侧掌握度和左侧卡片没关联**
   - 问题：renderMastery()函数静态渲染，没有根据currentCardIdx动态更新
   - 修复：修改renderMastery()函数，让它根据currentCardIdx动态渲染

### 2.4 v4.0 原型（2026-06-12，第三次迭代）

**开发背景**：用户提出"考试这张卡"按钮的逻辑不对，应该是考这张卡的各种向量，而不是考5道题。

**需求变更**：
- 原需求："考试这张卡"按钮点击后，考5道题（随机抽卡）
- 新需求："考试这张卡"按钮点击后，只考当前卡片的各个向量（5道题），左侧其他卡片置灰不可点击

**修复内容**：
1. **开发单卡考试模式**
   - 添加全局变量`examMode`（`all` | `single`）和`examSingleCardIdx`
   - 修改`startExamFromLearn()`：设置`examMode='single'`和`examSingleCardIdx=currentCardIdx`
   - 修改`startNewExam()`：当`examMode='single'`时，只考当前卡片的每个向量
   - 添加CSS类`.card-item.disabled`：置灰样式（opacity:0.5; cursor:not-allowed）
   - 修改`renderLeftPanel()`：根据`examMode`决定标题，单卡模式下其他卡片添加`disabled`类且移除onclick
   - 修改`selectCard()`：单卡模式下不能点击其他卡片（直接返回）
   - 修改`backToLearn()`：重置`examMode='all'`

2. **修复：做完题后点击返回学习就卡死了**
   - 问题：`backToLearn()`函数没有隐藏考试结束面板，导致面板遮挡界面
   - 修复：在`backToLearn()`中添加`document.getElementById('examEndPanel').classList.remove('show')`

### 4.3 关键算法

#### Fisher-Yates算法（选项随机打乱）
```javascript
// 随机打乱选项（Fisher-Yates）
let indices = [0,1,2,3];
for (let i = 3; i > 0; i--) {
  const j = Math.floor(Math.random()*(i+1));
  [indices[i], indices[j]] = [indices[j], indices[i]];
}
const shuffledOpts = indices.map(i => opts[i]);
```

#### 向量切换算法（避免重复）
```javascript
// 如果oldQuestions不为null（换向量），则选择一个不同于上次的向量
if (oldQuestions) {
  const oldQ = oldQuestions.find(q => q.cardIdx === cid);
  if (oldQ) {
    const lastVectorIdx = oldQ.vectorIdx;
    const available = card.vectors.map((_, vi) => vi).filter(vi => vi !== lastVectorIdx);
    vectorIdx = available.length > 0 ? available[Math.floor(Math.random()*available.length)] : 0;
  }
}
```

### 4.4 设计决策记录

#### 决策1：使用单文件HTML原型
- **背景**：需要快速验证交互设计
- **方案A**：使用React/Vue框架 + Vite构建
- **方案B**：使用单文件HTML（无框架）
- **决策**：选择方案B
- **理由**：原型阶段不需要构建工具，单文件更方便分享和测试

#### 决策2：使用mock数据而非连接API
- **背景**：原型需要展示完整功能，但后端尚未开发
- **方案A**：先开发后端API，再开发前端
- **方案B**：前端使用mock数据，快速迭代
- **决策**：选择方案B
- **理由**：原型目标是验证交互设计，不是验证技术架构

#### 决策3：使用localStorage而非后端数据库
- **背景**：需要持久化每日统计 data
- **方案A**：连接后端数据库（SQLite/PostgreSQL）
- **方案B**：使用localStorage
- **决策**：选择方案B
- **理由**：原型阶段数据量小，localStorage足够用

#### 决策4：考试题目硬编码而非动态生成
- **背景**：需要展示5种向量类型的题目
- **方案A**：实现题目生成算法（根据向量类型动态生成）
- **方案B**：硬编码5种向量类型的题目
- **决策**：选择方案B（部分实现）
- **理由**：原型阶段只需要展示题目样式，不需要完整的题目生成逻辑

#### 决策5：单卡考试模式 vs 全卡考试模式
- **背景**：用户点击"考试这张卡"按钮后，应该考什么？
- **方案A**：考5道题（随机抽卡）
- **方案B**：考当前卡片的5个向量（单卡模式）
- **决策**：选择方案B
- **理由**：用户期望"考试这张卡"是专门针对这张卡的测试，而不是随机测试

## 五、已知问题与风险

### 5.1 功能缺陷

| 问题 | 严重程度 | 描述 | 解决方案 |
|------|----------|------|----------|
| 掌握度是mock数据 | 中 | 右侧掌握度面板显示的是硬编码数据，不是真实计算结果 | 需要连接后端API，实现掌握度计算逻辑 |
| 考试题目是硬编码 | 中 | 考试题目是前端写死的，不是根据卡片数据动态生成 | 需要连接题目生成API |
| 随机测试功能未实现 | 低 | 考试结束面板点击"随机测试"按钮后，没有真正实现随机测试 | 需要实现随机抽卡逻辑 |

### 5.3 设计风险

| 风险 | 概率 | 影响 | 缓解措施 |

### 7.2 经验教训

**成功经验**：
1. **快速迭代**：通过多次小步快跑，快速验证设计假设
2. **用户参与**：让用户早期参与测试，及时发现问题
3. **mock数据**：使用mock数据快速验证交互，不等待后端开发
4. **文档同步**：及时记录设计决策，避免遗忘

**失败教训**：
1. **过度承诺**：在原型阶段承诺了太多功能，导致开发周期拉长
2. **测试不足**：每次修改后没有进行充分的回归测试，导致老bug复发
3. **文档滞后**：设计文档更新滞后于代码实现，导致文档与代码不一致

### 7.3 改进建议

**对开发流程的改进**：
1. **引入自动化测试**：每次修改后自动运行测试用例，避免老bug复发
2. **引入代码审查**：每次提交代码前进行代码审查，提高代码质量
3. **引入持续集成**：自动构建和部署，提高开发效率

**对项目管理方法的改进**：
1. **引入敏捷开发**：采用Scrum或Kanban方法，提高项目管理效率
2. **引入需求管理工具**：使用Jira或Trello管理需求和任务
3. **引入版本控制**：使用Git管理代码版本，避免代码丢失
