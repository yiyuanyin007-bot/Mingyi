### 4.4 6向量掌握度系统

| 向量 | 含义 | 方向 |
|------|------|------|
| `0→1` | 方名 → 症状 | 给定方名，选出症状 |
| `1→0` | 症状 → 方名 | 给定症状，选出方名 |
| `0→2` | 方名 → 药物 | 给定方名，选出药物组成 |
| `2→0` | 药物 → 方名 | 给定药物，选出方名 |
| `0→usage` | 方名 → 煎服法 | 给定方名，选出煎服法 |
| `0→contra` | 方名 → 禁忌 | 给定方名，选出禁忌 |

每个向量包含：`level`（0-5）、`streak`（连续正确次数）、`next_review`（下次复习时间）、`total_attempts`（总尝试次数）等。

## 五、子系统架构

### 5.1 标准化病人（SP）系统

**定位**：将中医经典条文转化为结构化临床问诊考试（OSCE风格）

**架构**：

```
standardized-patient/
├── SKILL.md                          # 核心定义（触发规则、角色框架、信息分层）
├── references/
│   ├── json_schema.md                # SP 数据规范（schema_version、字段定义）
│   ├── persona_system.md             # 5种人格系统 + 40方人格映射
│   ├── oral_expression_guide.md        # 症状口语表达库（283个症状）
│   ├── ten_inquiries_framework.md    # 十问歌问诊框架
│   └── source_article_map.md         # 条文映射（symptom_pool / clue_map / difficulty）
└── data/                             # SP 病例数据（可选，实际在 data/sp_cases.json）
```

**信息分层模型**：

| 层级 | 获取方式 | 示例 |
|------|----------|------|
| L0 | 主诉自动输出 | "我发烧两天了，汗一直出" |
| L1 | 问对方向即给 | 问"怕冷吗？"→"怕，风一吹就起鸡皮疙瘩" |
| L2 | 追问细节才给 | 问"汗什么时候多？"→"晚上盗汗，白天动则汗出" |
| L3 | 误导/噪声（30%概率） | "我觉得是颈椎病引起的脖子僵" |

**两种模式**：
- `article` 模式：从条文出发，学生问完后选择对应条文
- `formula` 模式：从方剂出发，5个选项为方剂名，考察方证鉴别

### 5.3 临床录入系统

**定位**：模拟真实临床问诊，从自由文本输入到方证匹配的完整工作流

**两阶段工作流**：

```
┌──────────┐    ┌──────────────┐    ┌────────────┐    ┌──────────┐    ┌────────────┐
│ 自由输入  │ → │ 采集评估引擎  │ → │ 评估结果页  │ → │ 补采/匹配 │ → │ 匹配结果页  │
│ (textarea)│    │ (13维度评估) │    │ (完整性评级)│    │ /跳过    │    │ (3层方证匹配)│
└──────────┘    └──────────────┘    └────────────┘    └──────────┘    └────────────┘
       │                                                              │
       │                                                              ▼
       │                                                       ┌────────────┐
       │                                                       │ 条文联动   │
       │                                                       │ (L1快速条文│
       │                                                       │  + L2面板) │
       │                                                       └────────────┘
       │
       └──────────────────────────────────────────────────────→ 档案管理
                                                                 (P-编码 + 复诊)
```

**13维度采集评估**：寒热 / 汗出 / 头身 / 二便 / 饮食 / 胸腹 / 耳目 / 口渴 / 旧病诱因 / 服药 / 妇科 / 脉象 / 查体

**方证匹配三层**：
1. `necessary` 准入：必见症缺失直接排除
2. `common` 匹配：常见症匹配度排序
3. 条文增强：匹配 source_text_ids 关联条文

**禁忌校验**：排除方剂的 contraindications

### 7.2 技术债务

| 债务 | 描述 | 风险等级 |
|------|------|----------|
| 单文件应用（8,459行） | 功能膨胀，维护困难 | 🔴 高 |
| 无构建工具 | 无类型检查、无模块化、无Tree Shaking | 🟡 中 |

| 前端直接操作数据 | 无API层，数据校验在前端 | 🟡 中 |
| mobile.html 功能滞后 | 移动端体验不完整 | 🟡 中 |
| 无云端同步 | 数据仅限单设备 | 🟡 中 |

### 7.3 架构风险

| 风险 | 描述 | 缓解措施 |
|------|------|----------|
