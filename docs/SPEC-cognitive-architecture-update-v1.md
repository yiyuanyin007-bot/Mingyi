## 一、用户的核心洞察：学习的本质是"认知切换"

用户提出了一个根本性的认知模型，远超我之前的"控制论"框架。核心洞察如下：

### 1.1 大脑的工作方式

> "人的大脑对故事和场景非常敏感，对文字没那么敏感。如果一个人对文字过于敏感，往往会无形中遗漏场景中的细节，没法在抽象和具象之间无缝切换。"

这意味着：
- **文字是压缩的符号**："太阳之为病，脉浮，头项强痛而恶寒"是一串符号
- **场景是展开的感知**：大脑需要把这串符号还原为"清晨、披着衣服、脖子僵硬、摸脉浮起"的完整画面
- **学习的本质是解压缩**：从文字→画面→心理表征→临床决策的连续切换能力

### 1.2 三个阶段的认知本质

用户的三阶段不是"学习→考试→临床"的功能流程，而是**三个不同表征层级的认知切换**：

```
阶段1（文字→画面）：情境化理解
     输入：经典条文（抽象符号）
     输出：临床场景（具象画面）
     核心能力：解压缩——从文字还原出完整的患者画面

阶段2（画面→表征）：模式压缩
     输入：症状组合（具象画面）
     输出：方证标签（抽象表征）
     核心能力：认知压缩——从纷繁症状中提炼出"这就是桂枝汤证"的模式

阶段3（表征→行动）：临床映射
     输入：真实患者（具象感知）
     中间：心理表征（抽象匹配）
     输出：处方决策（具体行动）
     核心能力：映射——从"眼睛看到"到"脑子概括"的瞬时对应
```

### 1.3 系统的真正目标

> "用计算机大量模拟这个过程，尽量不要生硬。……让所谓的表象变得越来越具体。"

系统的核心目标不是"让用户记住六向量"，而是：
**让用户的大脑建立一条从"具象感知"到"抽象表征"再到"具象行动"的流畅高速公路。**

六向量（0→1, 1→0, 0→2, 2→0, 0→usage, 0→contra）只是这条高速公路上的六个收费站，不是高速公路本身。

## 二、基于用户框架，我需要修正的三个问题

### 2.1 数据收集：从"结果数据"到"过程数据"

#### 之前的错误

我在之前的文档中关注的是：
- 答对了多少题（结果）
- 掌握度状态（静态标签）
- 错题记录（错误结果）

这些都是**结果数据**，不关心"用户是怎么想的"。

#### 用户框架下的正确数据

应该收集的是**认知路径数据**——用户在每个阶段是如何完成切换的：

| 数据类型 | 具体含义 | 收集方式 | 为什么重要 |
|---------|---------|---------|-----------|
| **反应时延** | 看到题目到选择答案的时间 | 自动记录 | 时延长 = 心理表征构建困难，卡在"压缩"环节 |
| **犹豫模式** | 是否反复切换选项、修改答案 | 自动记录 | 反复切换 = 心理表征不清晰，在多个模式之间摇摆 |
| **问诊路径** | SP 场景中先问什么、再问什么 | 自动记录 | 问诊路径 = 认知策略，反映用户的临床思维模式 |
| **表征笔记** | 用户做决策前的中间思考过程 | 鼓励记录 | 这是最珍贵的数据：从"看到症状"到"形成结论"的压缩过程 |
| **切换痕迹** | 用户在文字和场景之间切换的频率 | 记录操作 | 切换频率高 = 表征不稳定，需要更多训练 |

#### 核心修正

**不是记录"他选了什么"，而是记录"他怎么想的"。**

具体来说：

```
旧记录（结果导向）：
{
  "question": "桂枝汤的必要症状",
  "selected": "发热汗出恶风",
  "correct": true,
  "time": 3.2s
}

新记录（过程导向）：
{
  "question": "桂枝汤的必要症状",
  "user_thinking": "看到脉浮缓，先想到太阳中风，然后脑子里出现一个怕风的人，汗出...",  // 用户笔记
  "selected": "发热汗出恶风",
  "confidence": 4,  // 用户自评信心度（1-5）
  "hesitation_count": 2,  // 换了2次选项
  "time_to_first_click": 5.8s,  // 第一次点击的时间（表征构建时间）
  "time_to_final": 12.3s,  // 最终确认的时间（表征校正时间）
  "mental_image": "一个披衣的人，脖子僵硬，汗微微出，脉浮缓"  // 用户描述的心理画面
}
```

### 2.2 专利：从"算法专利"到"认知架构专利"

#### 之前的错误

我之前列出的专利候选（六向量映射、干扰项生成、多路径检索）都是**底层算法**，没有触及用户真正的创新。

用户的核心创新是：**场景化认知迁移的训练架构**——让计算机模拟人脑在抽象和具象之间切换的过程。

#### 用户框架下的正确专利方向

真正应该保护的，是这个**认知管道的架构设计**：

**候选专利 A：中医经方场景化认知迁移训练系统**

> 一种基于中医经方学习的场景化认知迁移训练系统，其特征在于：
> 1. **文字情境化模块**：将经典条文自动还原为临床场景描述，包含患者姿态、环境、时间等情境要素，使学习者从文字符号还原为具象画面；
> 2. **心理表征构建模块**：基于症状组合生成"方证"心理表征，支持学习者从具象症状到抽象方证的认知压缩，并在不同症状组合中识别不变的方证模式；
> 3. **临床印证模块**：通过标准化病人模拟问诊，记录学习者从"感知症状"到"形成表征"到"输出决策"的完整认知路径；
> 4. **认知切换训练模块**：在"文字-画面-表征-临床"之间设计双向切换练习，强化学习者在不同表征层级之间的迁移能力，使表象从抽象走向具体。

**可专利性评估：高**
- 这是一个完整的**系统架构**，不是单一算法
- 每个模块都有明确的技术实现（计算机程序 + 数据交互）
- 技术效果是"提升认知切换流畅度"，可量化（反应时间、犹豫次数、表征稳定性）

**候选专利 B：基于表征层级切换的中医学习效果评估方法**

> 一种基于表征层级切换的中医学习效果评估方法，其特征在于：
> 1. 将经方学习过程分解为三个表征层级：文字符号层、心理表征层、临床行动层；
> 2. 记录学习者在相邻层级之间的切换时延和切换成功率；
> 3. 根据切换瓶颈识别学习者的薄弱环节：
>    - 若文字→画面切换时延过长，判定为"情境化理解不足"；
>    - 若画面→表征切换时延过长，判定为"模式识别能力不足"；
>    - 若表征→行动切换时延过长，判定为"临床映射能力不足"；
> 4. 基于瓶颈识别结果，自动生成针对性的训练内容。

**可专利性评估：高**
- 这是一个**评估方法**，具有明确的技术步骤和算法逻辑
- 与传统"正确率评估"相比，这是一个全新的评估维度
- 技术效果可量化：切换时延、瓶颈识别准确率

### 2.3 验证：从"正确率验证"到"认知切换流畅度验证"

#### 之前的错误

我之前列出的验证指标是：
- 答题正确率
- 记忆保持率
- 类方鉴别准确率

这些都是**结果指标**，不区分用户是"真的理解了"还是"死记硬背了"。

#### 用户框架下的正确验证指标

应该验证的是**认知切换能力**，不是记忆结果：

| 层级切换 | 验证指标 | 测量方法 | 目标值 |
|---------|---------|---------|--------|
| **文字→画面（情境化）** | 条文还原完整度 | 给一条条文，让用户描述"你看到了什么画面"，与专家标准画面对比 | 关键要素覆盖率 ≥ 80% |
| **画面→表征（模式压缩）** | 表征构建速度 | 给一组症状，记录用户说出"这是XX方证"的时间 | 平均时延 ≤ 5 秒 |
| **表征→行动（临床映射）** | 映射准确率 | SP 场景中，从看到患者到选择方剂的匹配度 | 与专家一致率 ≥ 70% |
| **双向切换（灵活性）** | 切换一致性 | 同一方证的不同症状组合，用户能否一致识别 | 一致性率 ≥ 85% |
| **表征稳定性** | 抗干扰能力 | 在类方干扰下，用户能否保持表征稳定 | 干扰下准确率 ≥ 60% |

#### 核心修正

**不是验证"用户记住了多少"，而是验证"用户的大脑能否在抽象和具象之间自由切换"。**

具体验证实验：

**实验 A：情境化理解测试**

```
给 10 条《伤寒论》条文，让用户：
1. 读条文
2. 用文字描述"你脑子里看到了什么画面"
3. 专家根据标准画面评分（覆盖关键要素：时间、姿态、症状、环境）

评分：
- 优秀：覆盖了条文中的全部关键要素，且画面连贯
- 合格：覆盖了大部分关键要素，但画面有缺失
- 不足：只记住了文字，没有形成画面
```

**实验 B：表征构建速度测试**

```
给一组症状（5-8 个），记录：
1. 用户说出方证名称的时间（表征构建时延）
2. 用户解释"为什么是这个方证"的完整性（表征质量）
3. 用户能否说出"如果不是这个方证，可能是什么"（表征区分度）

对比：
- 训练前 vs 训练后（自身对照）
- 系统用户 vs 传统学习用户（组间对照）
```

**实验 C：SP 临床映射追踪**

```
在 SP 场景中：
1. 记录用户的问诊路径（先问什么、再问什么）
2. 记录用户形成初步结论的时间点
3. 记录用户从"看到患者"到"确认处方"的完整认知轨迹
4. 与专家的标准认知轨迹对比，计算相似度

关键指标：
- 认知轨迹与专家轨迹的相似度（表征结构是否趋同）
- 从"感知"到"决策"的时延是否在缩短（切换流畅度提升）
```

## 三、用户框架带来的新启发

### 3.1 对"六向量"的重新理解

用户让我意识到：六向量不是学习的**目标**，而是**诊断工具**——用来诊断用户在哪个切换环节卡住了。

| 向量 | 对应切换环节 | 卡住的信号 | 训练方向 |
|------|------------|----------|---------|
| 0→1（方名→症状） | 表征→具象（从方证标签展开为症状画面） | 知道方名但想不起症状 | 强化"方证展开"能力 |
| 1→0（症状→方名） | 具象→表征（从症状压缩为方证标签） | 看到症状但说不出方名 | 强化"模式压缩"能力 |
| 0→2（方名→药组） | 表征→具象（从方证标签展开为药物画面） | 知道方名但想不起药组 | 强化"方药对应"能力 |
| 2→0（药组→方名） | 具象→表征（从药物压缩为方证标签） | 看到药组但说不出方名 | 强化"药证辨识"能力 |
| 0→usage | 表征→行动（从方证标签到具体用法） | 知道方名但记不清煎服法 | 强化"临床操作"能力 |
| 0→contra | 表征→边界（从方证标签到禁忌边界） | 知道方名但记不清禁忌 | 强化"安全边界"能力 |

**关键洞察：六向量的真正价值不是"训练内容"，而是"认知 CT"——扫描用户大脑的哪个切换环节有堵塞。**

### 3.2 对"SP 系统"的重新理解

用户让我意识到：SP 不是"考试"，而是**认知显微镜**——用来观察用户从"眼睛看到"到"脑子概括"的完整切换过程。

在 SP 场景中，应该记录的不是"他选对了没有"，而是：
- 他问了哪些问题？（他的认知切入点是什么）
- 他在什么时候"顿悟"了？（从"不知道"到"知道"的切换点）
- 他有没有"过早闭合"？（还没问完就下结论，表征构建不充分）
- 他有没有"过度犹豫"？（问了太多无关问题，表征构建缺乏效率）

### 3.3 对"数据收集"的重新理解

用户让我意识到：最有价值的数据不是"答题结果"，而是**认知切换的"摩擦痕迹"**。

具体来说：
- 用户在 SP 问诊中问了 8 个问题，但前 3 个都是无关的 → 说明他的切入策略有问题
- 用户看到题目后想了 15 秒，最后选了正确答案 → 说明他的表征构建慢但稳定
- 用户看到题目后立刻选了答案，但错了 → 说明他的表征是"伪表征"（表面模式匹配）
- 用户做笔记时写了很长的推理过程 → 说明他的切换过程需要外化辅助，还未内化

这些数据才是"让表象变得越来越具体"的关键。

### 3.4 主观体验数据：比客观对错更珍贵的维度

用户特别强调：「让他感受自己构建结论的过程」。这个「感受」意味着系统需要记录用户在「构建结论」时的**主观体验**，而这种主观体验往往比客观对错更能揭示认知的真实状态。

| 主观体验数据 | 具体含义 | 收集方式 | 为什么比客观对错更有价值 |
|-------------|---------|---------|----------------------|
| **信心度波动** | 从"不确定"到"有把握"再到"确信"的主观感受变化 | 每道题/每个SP场景后，让用户滑动选择信心度（1-5分） | 高信心+错 = 伪表征（危险）；低信心+对 = 表征不稳定（需巩固） |
| **顿悟时间点** | 在SP问诊中，什么时候突然"明白了" | 在SP界面增加"顿悟"按钮，用户可随时标记 | 顿悟前的数据 = 表征构建的挣扎过程；顿悟后的数据 = 表征固化的标志 |
| **模糊感描述** | 用户用文字描述"我觉得哪里不对劲" | 在答题/SP决策前，增加"现在的感受"输入框 | "我觉得症状像A又像B" = 两个表征在竞争，说明模式边界不清晰 |
| **身体反应** | 用户是否感到紧张、困惑、流畅 | 可选的体感自评（紧绷/顺畅/模糊） | 身体反应是认知状态的直接信号：流畅 = 表征已内化；紧绷 = 卡在切换环节 |
| **画面 vivid 度** | 脑子里画面的清晰程度 | 学习卡片后，让用户自评"画面有多清楚"（1-5分） | 画面越清楚 = 情境化越充分；画面模糊 = 文字还没被解压缩 |

**关键洞察：客观对错只能告诉我们「结果对不对」，主观体验才能告诉我们「为什么对/为什么错」。一个选对了但「感觉是猜的」的用户，和一个选对了但「感觉画面很清楚」的用户，他们的认知状态完全不同——前者需要巩固，后者已经内化。**

## 四、修正后的行动框架

### 4.1 数据收集（重新设计）

#### 立即启动（Phase 1，现在）

**目标：收集"认知切换过程数据"**

```
1. 在 ExamView 中增加：
   - 答题前的"思考笔记"输入框（可选，鼓励记录）
   - 答题后的"信心度"自评（1-5 分）
   - 自动记录：反应时延、犹豫次数、选项切换轨迹

2. 在 SP 场景中增加：
   - 问诊路径记录（每问一个问题，记录问题内容和顺序）
   - 决策时间点记录（何时形成初步结论、何时确认处方）
   - 决策理由输入（"我为什么选这个方"，必须填写）

3. 在 LearnView 中增加：
   - "我看到的心理画面"输入框（学习每张卡片时，让用户描述画面）
   - 与标准画面的对比评分（用户自评或 AI 辅助）
```

### 4.2 专利（重新设计）

#### 优先申请（Phase 1 后）

**核心专利：场景化认知迁移训练系统（架构级）**

- 保护对象："文字→画面→表征→临床"的完整认知管道
- 权利要求：四个模块的协同工作方式（情境化、表征构建、临床印证、切换训练）
- 技术效果：提升认知切换流畅度（可量化）

**辅助专利：表征层级切换评估方法（方法级）**

- 保护对象：基于切换时延和瓶颈识别的学习效果评估方法
- 权利要求：三层表征分解、切换瓶颈诊断、针对性训练生成
- 技术效果：精准定位学习薄弱环节（可量化）

### 4.3 验证（重新设计）

#### 四层次验证（更新版）

| 层次 | 验证内容 | 方法 | 指标 | 周期 |
|------|---------|------|------|------|
| **L1：情境化** | 用户能否把文字读成画面 | 条文还原测试 | 画面完整度、关键要素覆盖率 | 2 周 |
