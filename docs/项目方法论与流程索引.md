## 一、当前阶段

项目已经从「单批资料清洗归档」进入「数据整理流程设计」阶段。

目标不再是处理某一份资料，而是建立一套可复制、可迭代、可验证的 **数据飞轮**：

```text
产出（清洗/提取/制卡）
        ↓
    审阅（人工/规则）
        ↓
    入库（data/*.json）
        ↓
    使用（前端学习/练习/考试）
        ↓
    反馈（错题、薄弱向量、使用数据）
        ↓
    迭代（补充资料、修正卡片、优化题目）
        ↓
    再回到产出
```

## 三、共性问题框架

后续提纲挈领式讨论，建议围绕以下共性主题展开：

### 3.1 数据分层与边界

- 经典层（`source_cards`）vs 经验层（`experience_cards` / `references`）的边界在哪里？
- 后世注家观点能否进入 `formula_card.canonical`？
- 药物卡（`herb_cards`）是否独立？与方剂卡如何双向引用？

### 3.2 参考资料策略

- 什么资料值得挂到方剂卡？
- `references` 字段的结构如何设计？
- 本地 HTML/Markdown 与外部 URL 如何并存？
- 主题不相关但又有价值的资料放哪里？

### 3.3 HTML/CHM 处理路径

- 直接 Skill 提炼 vs 先清洗成 Markdown 再提炼？
- 通用清洗脚本如何配置化？
- 不同博客平台（Sina / QZone）如何统一处理？

### 3.4 Schema 与字段规范

- `experience_card` 是否需要扩展 `patient_profile` / `physician_formula` / `author_type` 等字段？
- `formula_card` 是否新增 `references` 数组替代现有 `core_sources` + `core_source_urls`？
- 如何标注方剂版本差异（如八味除烦汤）？

### 3.5 审阅与入库流程

- 候选卡片的生命周期：谁审阅、抽样比例、通过标准？
- 人工审阅与 LLM 自动审阅如何分工？
- 入库前必须满足哪些条件？

### 3.6 前端挂载与使用

- 参考资料区如何渲染 `references`？
- 经验卡如何在卡片页展示？
- 错题/薄弱向量如何驱动资料补充？

### 3.7 数据飞轮的反馈机制

- 哪些使用数据值得收集？（练习正确率、错题分布、停留时长）
- 如何根据反馈决定下一步补充哪类资料？
- 如何量化“资料质量对学习效果的提升”？

## 五、建议的推进节奏

### 第一阶段：共性问题定型（1–2 周）

1. 确认参考资料选择原则（已初步成文）。
2. 完成 HTML 处理路径 AB 测，确定默认路径。
3. 确定 `references` 字段结构和 `experience_card` schema 扩展。
4. 确定数据分层边界（经典 vs 经验 vs 药物）。

### 第二阶段：流程工具化（2–3 周）

1. 写通用 CHM 清洗脚本配置草案。
2. 写 references 提取 Skill。
3. 修复前端 `getExperience(id)` bug。
4. 更新 `card_manager.py` 支持新的 schema。

### 第三阶段：试点跑通（1–2 周）

1. 选一个最小闭环：如“大柴胡汤”从黄煌资料中提取 references 并挂到前端。
2. 验证前端渲染、练习生成、审阅流程。

### 第四阶段：批量飞轮（持续）

1. 按 60 → 57 → 64 → 3 的顺序批量处理。
2. 每批入库后观察练习数据，补充薄弱环节。
3. 定期回顾 `docs/项目方法论与流程索引.md`，更新方法论。
