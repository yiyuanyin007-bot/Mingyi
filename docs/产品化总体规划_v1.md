> **文档编号**：PROD-PLAN-20260702-001  
> **版本**：v1.0

## 第一部分：第一性原理声明

### 1.1 问题本质

中医经方学习的核心痛点不是"资料不够"，而是：
- **学了记不住**（记忆痕迹不巩固）
- **记住了不会用**（从条文到临床的断裂）
- **用了不知道对不对**（缺乏即时反馈和诊断）
- **对的不知道为什么对**（缺乏循证验证）

### 1.2 第一性原理

> **系统目标 = 建立"经方认知能力"的可训练、可测量、可进化系统**

不是做一个"伤寒论APP"，而是做一个**认知训练器**——让学习者通过系统化的训练，建立从条文到方证到临床的多向映射能力。

### 1.3 验证标准（第一性）

任何功能是否值得做的唯一判断：
- **是否帮助建立认知映射？**（八向量训练）
- **是否提供即时反馈？**（诊断标签、掌握度追踪）
- **是否连接条文与临床？**（SP信息分层、临床录入）
- **是否可验证知识质量？**（循证审计、文献溯源）

### 3.3 数据验证规则（自动化）

每个数据文件必须可通过 `scripts/governance.py check-data` 验证：

```bash
# 验证脚本接口
python scripts/governance.py check-data --file data/formula_cards.json --schema schemas/formula_card.json
python scripts/governance.py check-data --file data/sp_cases.json --schema schemas/sp_case.json
```

验证内容包括：
1. JSON 语法合法性
2. 必填字段存在性
3. 字段类型正确性
4. 关联字段一致性（如 formula_cards.source_text_ids 必须在 source_cards 中存在）
5. 枚举值合法性（如 mastery 键名必须是 6 个固定向量之一）
6. 唯一性约束（如 id 不重复）

### 3.4 数据版本控制

数据文件纳入 Git 版本控制，不手动添加版本号。变更通过：
1. Git commit message 记录变更原因
2. 修改前自动备份到 `data/archive/`
3. 变更后更新 README 中的"最后更新"和"变更历史"

> **目标：让学习数据在任意设备上可用，且用户感到"安全"。**

## 第六部分：治理与文档管理

### 6.1 文档状态机

每个文档都有生命周期：

```
草稿 → 审阅中 → 已确认 → 已执行 → 已归档
  ↑      │         │         │
  └──────┴─────────┴─────────┘（发现错误时回退）
```

| 状态 | 含义 | 谁可修改 |
|------|------|----------|
| 草稿 | 初稿，未审阅 | 作者 |
| 审阅中 | 已提交审阅，等待反馈 | 作者+审阅者 |
| 已确认 | 内容已确认，可执行 | 仅作者（需变更时重新进入审阅） |
| 已执行 | 文档内容已落实为代码/数据 | 仅作者（需变更时走变更流程） |
| 已归档 | 过时但保留历史 | 无人（只读） |

### 6.2 变更流程

```
1. 发现需要变更（bug/新需求/文档错误）
2. 创建变更记录（docs/CHANGELOG.md 或 阶段验收清单）
3. 评估影响范围（架构/数据/代码/测试）
4. 更新相关文档（标记为"审阅中"）
5. 实施变更（代码修改 + 测试）
6. 验证（测试通过 + 数据验证）
7. 更新文档状态（"已确认" → "已执行"）
8. 登记变更（CHANGELOG + 备份）
```
