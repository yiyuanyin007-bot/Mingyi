# 经方学习系统 v8 · 循证文献检索工作手册（v3.0）

> **版本**：v3.0 — 循环审计系统  
> **编制**：循证文献检索专家角色  
> **适用范围**：用户已写好的方剂卡片「生理学与病理生理学解读」笔记  
> **核心任务**：对笔记中的病理生理推论链进行逐节点文献验证与审计  
> **产出形式**：独立的证据审计报告（Markdown存档，不嵌入页面）  
> **执行模式**：循环任务——每次会话启动时检测变动、更新任务清单、执行任务、记录经验、划掉任务  
> **文档性质**：方法论框架 + 操作规范 + 质控体系 + 跨任务协作接口 + 循环审计系统

---

## 引言：从单次审计到循环审计系统

v1.0 设计了单次审计流程，v2.0 对齐了用户真实笔记结构，v3.0 将系统升级为**持续运转的循环审计引擎**。

核心设计思想：

> **你的笔记是命题，我的工作是对这些命题进行持续科学审计。审计报告是底层支撑文档，不呈现在前端。修正笔记以结构化 JSON 输出，支持一键导入覆写。审计智能体独立复核，验证结果驱动任务清单状态流转。**

```
  ├─ 步骤8：向用户汇报：今日完成/新增/待处理
  └─ 等待用户指令
```

## 第二章：数据层——笔记读取与解析

### 2.1 数据读取：方案 B（WebBridge 持续读取）

**核心优势**：每次会话启动时获取最新数据，无需用户手动导出。

#### 读取流程

```
WebBridge navigate → http://localhost:8100/app/index.html
  ├─ snapshot → 获取页面结构（确认在正确的页面）
  ├─ evaluate → 执行 JavaScript 读取 localStorage
  └─ 返回 JSON 数据 → 保存到 data/notes_backup/snapshot_YYYYMMDD_HHMMSS.json
```

#### 读取脚本（WebBridge evaluate）

```javascript
// 读取 localStorage 全部数据
const data = {};
for (let i = 0; i < localStorage.length; i++) {
  const key = localStorage.key(i);
  try {
    data[key] = JSON.parse(localStorage.getItem(key));
  } catch (e) {
    data[key] = localStorage.getItem(key); // 非 JSON 数据原样保存
  }
}
return JSON.stringify(data);
```

#### 增量 Diff 检测

将当前快照与上次快照对比，检测：

| 变动类型 | 检测方法 | 处理 |
|---------|---------|------|
| **新增笔记** | 上次快照中该卡片无 notes 字段，本次有 | 新增「待读取」任务 |
| **修改笔记** | 上次快照中该卡片 notes 内容与本次不同（哈希对比） | 新增「待读取」任务 |
| **删除笔记** | 上次快照中有，本次无 | 标记该任务为「已删除」 |
| **无变动** | 内容完全一致 | 不操作 |

#### 快照管理

- 快照文件：`data/notes_backup/snapshot_YYYYMMDD_HHMMSS.json`
- 保留策略：保留最近 10 个快照，自动删除旧快照
- 最新快照：`data/notes_backup/latest_snapshot.json`（软链接或复制）

## 第三章：监视系统与任务清单

### 3.1 任务清单（Task Board）

**文件位置**：`docs/evidence/task_board.md`

**任务状态流转**：

```
待读取 ──→ 待审计 ──→ 审计中 ──→ 待验证 ──→ 验证中
                                              │
                        ┌─────────────────────┘
                        │
                        ↓
                ┌─── 已通过 ───┐
                │              │
                ↓              ↓
              已完成       需修正
                             │
                             ↓
                           已修正
                             │
                             ↓
                    待验证(修正版)
                             │
                             ↓
                           已通过
                             │
                             ↓
                           已完成
```

**状态转换规则**：

| 从状态 | 到状态 | 触发条件 | 操作者 |
|--------|--------|---------|--------|
| 待读取 | 待审计 | 已获取笔记内容，提取了推论 | 循证文献检索专家 |
| 待审计 | 审计中 | 开始执行检索 | 循证文献检索专家 |
| 审计中 | 待验证 | 审计报告已生成 | 循证文献检索专家 |
| 待验证 | 验证中 | 审计智能体开始复核 | 审计智能体 |
| 验证中 | 已通过 | 审计智能体确认无问题 | 审计智能体 |
| 验证中 | 需修正 | 审计智能体发现需修正 | 审计智能体 |
| 需修正 | 已修正 | 循证文献检索专家生成修正 JSON | 循证文献检索专家 |
| 已修正 | 待验证(修正版) | 用户一键覆写修正笔记 | 用户 |
| 待验证(修正版) | 已通过 | 审计智能体再次验证通过 | 审计智能体 |
| 待验证(修正版) | 需修正 | 审计智能体再次发现需修正 | 审计智能体 |
| 已通过 | 已完成 | 用户确认无需进一步操作 | 用户（或自动） |
| 任何状态 | 待读取 | 检测到笔记再次修改 | 监视系统 |

### 3.3 每次会话启动时的更新流程

```python
def session_start_update():
    # 1. 读取当前 task_board
    board = read_task_board()
    
    # 2. 读取上次快照
    last_snapshot = read_last_snapshot()
    
    # 3. 通过 WebBridge 读取当前 localStorage
    current_snapshot = read_localstorage_via_webbridge()
    
    # 4. 增量 diff
    changes = diff_snapshots(last_snapshot, current_snapshot)
    
    # 5. 处理变动
    for card_id, change in changes.items():
        if change['type'] == '新增':
            board.add_task(
                task_id=f"{card_id}-{today()}-001",
                card_id=card_id,
                status='待读取',
                last_modified=change['timestamp']
            )
        elif change['type'] == '修改':
            # 如果该卡片已有任务，更新为「待读取」
            existing_task = board.find_task_by_card_id(card_id)
            if existing_task:
                board.update_task_status(existing_task['task_id'], '待读取')
                board.update_task_note(existing_task['task_id'], '笔记已修改，需要重新审计')
            else:
                board.add_task(
                    task_id=f"{card_id}-{today()}-001",
                    card_id=card_id,
                    status='待读取',
                    last_modified=change['timestamp']
                )
    
    # 6. 保存更新后的 task_board
    board.save()
    
    # 7. 保存当前快照为最新快照
    save_snapshot(current_snapshot)
    
    return board.summary()
```

### 3.4 用户查询响应

当用户问：**"目前我的笔记里有哪些内容需要修正？"**

**响应逻辑**：

```python
def answer_user_query():
    board = read_task_board()
    
    # 1. 已验证需修正
    needs_fix = board.get_tasks_by_status('需修正')
    
    # 2. 已修正待覆写
    corrected = board.get_tasks_by_status('已修正')
    
    # 3. 待验证（已审计但未验证）
    pending_verification = board.get_tasks_by_status('待验证')
    
    # 4. 待审计（笔记已更新但未审计）
    pending_audit = board.get_tasks_by_status('待审计')
    
    # 5. 待读取（刚检测到变动）
    pending_read = board.get_tasks_by_status('待读取')
    
    # 构建回复
    response = []
    
    if needs_fix:
        response.append("## 🔴 已验证需修正（审计智能体已确认）")
        for task in needs_fix:
            response.append(f"- **{task['formula_name']}**：{task['correction_count']} 项修正")
            response.append(f"  - 修正摘要：{task['verification_summary']}")
            response.append(f"  - 输入编号「{task['task_id']}」选择此项")
    
    if corrected:
        response.append("## 🟡 已修正待覆写（修正笔记已生成，等待你确认）")
        for task in corrected:
            response.append(f"- **{task['formula_name']}**：修正笔记已就绪")
            response.append(f"  - 输入编号「{task['task_id']}」选择此项，获取一键导入脚本")
    
    if pending_verification:
        response.append("## 🔵 已审计待验证（审计报告已生成，等待审计智能体复核）")
        for task in pending_verification:
            response.append(f"- **{task['formula_name']}**：审计完成于 {task['audit_date']}")
    
    if pending_audit or pending_read:
        total = len(pending_audit) + len(pending_read)
        response.append(f"## ⚪ 待审计/待读取（笔记已更新，等待执行审计）")
        response.append(f"- 共 {total} 张卡片：{'、'.join([t['formula_name'] for t in pending_audit + pending_read])}")
    
    if not any([needs_fix, corrected, pending_verification, pending_audit, pending_read]):
        response.append("✅ 所有已审计笔记均已验证通过，无待修正项。")
    
    return '\n'.join(response)
```

## 第四章：分析层——逐节点可验证性审计

### 4.1 审计对象

对每个节点，审计两个层面：

- **层面 A**：节点本身是否成立（该生理机制是否有文献支持）
- **层面 B**：节点间因果是否成立（前一节点是否导致后一节点）

### 4.2 节点类型与验证策略

| 节点类型 | 典型表述 | 可验证性 | 验证策略 |
|---------|---------|---------|----------|
| **触发因素** | 外邪侵袭体表 | 中 | 操作化为温度/机械/化学刺激，查感受器文献 |
| **系统功能紊乱** | 皮肤交感-汗腺轴功能紊乱 | 高 | 直接查交感神经-汗腺调节文献 |
| **组织病理改变** | 颈背部肌群筋膜微循环障碍 | 高 | 查肌筋膜疼痛综合征、微循环文献 |
| **炎症介质** | 炎症介质刺激 | 高 | 查缓激肽、前列腺素、P物质在肌筋膜疼痛中的作用 |
| **临床表现** | 肌筋膜痉挛僵硬 | 高 | 查肌筋膜触发点、痉挛的生理学测量 |
| **代偿机制** | 代偿性汗出散热 | 中 | 查体温调节中的代偿性出汗机制 |

### 4.3 节点-命题-检索式转换

每个节点转换为可检索的科学命题，使用 PECO 框架：

**示例：GZJGG-002（皮肤交感-汗腺轴功能紊乱）**

| 转换步骤 | 输出 |
|---------|------|
| 节点原文 | 皮肤交感-汗腺轴功能紊乱 |
| 核心命题 | 皮肤交感神经调控异常导致汗腺分泌功能紊乱 |
| PECO 检索式 | P: 自主神经功能障碍患者或健康志愿者；E: 热/机械刺激；C: 基线/无刺激；O: 出汗率、皮肤交感神经活动（SSNA）、皮肤电反应 |
| PubMed 检索式 | `("sudomotor function"[MeSH] OR "sympathetic skin response"[All Fields]) AND ("dysfunction"[All Fields])` |

### 4.4 节点间因果链评级

| 评级 | 定义 | 示例 |
|------|------|------|
| **Strong** | 有文献直接证明 A→B 的因果链 | 实验证明"交感兴奋 → 局部血管收缩 → 肌筋膜缺血" |
| **Moderate** | 有文献分别证明 A→C 和 C→B，但 A→B 的直接证据不足 | 分别证明"交感兴奋→血管收缩"和"血管收缩→肌筋膜缺血" |
| **Weak** | 只有理论推测或间接证据 | 基于生理学知识推测，但无直接实验 |
| **Unsupported** | 无证据支持该因果链 | 文献不支持该因果方向 |

## 第五章：检索层——执行规范

### 5.1 数据库优先级

| 优先级 | 数据库 | 用途 |
|--------|--------|------|
| P1 | PubMed/MEDLINE | 核心英文文献 |
| P2 | Embase | 药物与生理补充 |
| P3 | Cochrane Library | 系统综述 |

| P5 | Google Scholar | 补充覆盖 |
| P6 | Sci-Hub | 全文获取 |

### 5.2 PRISMA 筛选流程

```
总检索结果（n = 120）
  ├─ 去重（n = 98）
```

## 第六章：评估层——证据质量与匹配度

### 6.1 GRADE 证据等级

| 等级 | 研究类型 | 处理策略 |
|------|---------|---------|
| 高 | RCT、系统综述、高质量队列 | 直接引用 |
| 中 | 小样本 RCT、中等质量观察性、机制实验 | 引用，标注局限 |
| 低 | 病例对照、横断面、体外实验 | 引用，明确标注 |
| 极低 | 专家意见、理论推导 | **不引用** |

### 6.2 匹配度评级

| 匹配等级 | 定义 | 处理 |
|---------|------|------|
| A | 直接验证该节点 | 直接引用 |
| B | 验证相关机制，但不完全相同 | 引用，标注差异 |
| C | 支持相关领域，但不直接验证 | 归入相关文献，不支持命题 |
| D | 不支持或矛盾 | 触发命题修正 |
| N | 无相关文献 | 标记缺口 |

## 第十章：多学科理论支撑

### 10.1 管理学：PDCA + TOC + 看板管理

| 概念 | 应用 |
|------|------|
| **PDCA** | 每次会话是一次完整的 Plan-Do-Check-Act 循环 |
| **TOC 约束** | 瓶颈是"概念操作化"→建立 `concept_mapping.json` 消除 |
| **看板管理** | task_board.md 就是数字看板，可视化任务状态 |
| **80/20** | 每节点 30 分钟检索上限，最小充分证据即停止 |

### 10.2 认知神经科学：双重编码 + 工作记忆

| 概念 | 应用 |
|------|------|
| **双重编码** | 笔记（语言编码）+ 审计报告（非语言编码：证据等级、DOI、图表）= 更稳固记忆 |
| **工作记忆容量** | 核心链条 4~5 节点符合 Miller 法则（4±1） |
| **间隔重复** | 证据更新时自动触发该卡片重新进入审计队列 |

### 10.3 逻辑学：溯因推理 + 因果链 + 证据支持

| 概念 | 应用 |
|------|------|
| **溯因推理** | 用户笔记是溯因产物（从症状推病机）；审计是评估"最佳解释是否有证据" |
| **类比推理** | 中医概念与生理学映射是类比，必须标注边界条件和置信度 |
| **Bradford Hill** | 药物作用机制使用九准则评估因果强度 |
| **Dempster-Shafer** | 多个低质量证据组合可提供中等确信度 |

### 附录D：审计智能体工作指南（给审计智能体使用）

#### 审计智能体收到任务时的操作步骤

1. **读取任务**：从 `docs/evidence/task_board.md` 中找到状态为「待验证」的任务

   - 每个节点的检索策略是否合理？

#### 验证通过的标准

- 所有节点的检索策略至少覆盖了 PubMed 和 CNKI
- 每个节点至少有 1 个 A 级或 B 级匹配的证据
- 所有证据都有有效的 DOI
- 节点间因果链评级有明确的文献或理论依据
- 没有发现用户笔记中重要节点被遗漏

## 结语

v3.0 将循证文献检索从"单次审计"升级为"持续审计系统"：

1. **自动检测**：每次会话启动时检测笔记变动
2. **任务看板**：task_board.md 可视化所有任务状态
3. **循环执行**：自动读取 → 提取 → 检索 → 评估 → 报告 → 修正
4. **人机协作**：用户只需关注「需修正」和「已修正」的列表，其他由系统自动推进
5. **可验证**：审计智能体独立复核，验证结果驱动状态流转
6. **可修正**：修正 JSON 支持一键导入，自动备份，安全覆写

> **最终愿景**：你的笔记系统中的每张卡片，背后都有一份经过循证审计的科学支撑文档。当你在学习、临床或教学时，随时知道你的每一个病理生理推论是有据可依还是待验证推测。这不仅是给中医经验以科学坐标，更是给你的学习以确定性。
