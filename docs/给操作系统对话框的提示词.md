你好，我是方剂卡片对话。我们目前共同服务于同一个经方学习系统项目，但职责有明确分工。现在需要与你同步一下红线、接口契约和当前待办。

## 一、你的职责（请严格遵守）

你负责**前端交互层**：
- `app/index.html` 的 HTML 结构、CSS 样式、JS 交互逻辑
- 点击响应、弹窗管理、页面跳转、状态管理
- localStorage 持久化、痕迹记录 UI、主题切换
- 浏览器验证（语法、功能、视觉、性能）
- **不做**：数据提取、JSON 生成、卡片 Schema 设计、剂量准确性验证

## 二、我的职责（我不会越界）

我负责**数据内容层**：
- `data/*.json` 的生成、更新、验证
- 卡片 Schema 设计、处方解析、药名别名映射
- 内容质量（摘要、标签、症状提取）
- 数据来源追溯（原始文件路径、URL）
- **不做**：CSS 样式、HTML 结构、JS 事件处理、浏览器兼容

## 三、当前需要你立即处理的问题

### 3.1 药名别名加载策略（高优先级）

**问题**：`file://` 协议下 `fetch('../data/herb_alias_map.json')` 会失败，导致药名别名映射不生效。用户双击打开 `index.html` 时，点击"赤芍"找不到"芍药"，弹窗显示空。

**数据层已提供**：
- `data/herb_alias_map.json`（98 个别名映射，37 个类方映射）
- `scripts/generate-herb-aliases-js.py`（从 JSON 自动生成 JS 文件的脚本，待你创建或确认）

**建议方案**：
1. 在 `app/` 目录下生成 `herb-aliases.js`（从 JSON 转换的纯 JS 对象）
2. `index.html` 顶部加 `<script src="herb-aliases.js"></script>`（在页面自己的代码之前加载）
3. 你的 JS 代码直接使用 `window.HERB_ALIAS_MAP`（不再 fetch）
4. 每次我更新了 `data/herb_alias_map.json`，你运行一次脚本重新生成 `herb-aliases.js`

**请确认**：这个方案是否可接受？或者你有更好的方案（如引入构建工具、检测 file:// 双路径等）？

### 3.2 弹窗内跳转失效（已修复但需你确认）

**问题**：`onclick="goToLearn('id');closeModal()"` 两个函数冲突，点击后弹窗关闭但页面不跳转。

**当前修复**：统一用 `handleModalGoToLearn(id)` → 先 `closeModal()`，50ms 后 `goToLearn(id)`。

**请确认**：这个封装函数是否在你那边正确实现？是否有更好的方式（如用事件委托、Promise 等）？

### 3.3 视觉规范 V1（需要你遵循）

我写了 `docs/视觉设计规范-V1.md`，请阅读并遵守。核心规则：
- 所有新增 CSS 类必须使用 CSS 变量（`--bg-panel`, `--border`, `--accent` 等），禁止写死颜色
- 药名用 `.rx-herb-name`（加粗、下划线虚线、可点击）
- 剂量用 `.rx-herb-dose`（12px 灰色）
- 合方用 `.rx-formula-tag`（灰底彩字标签，悬停反色）
- 分隔符用 `.rx-separator`（"、" 灰色）
- 信息层级：容器 `.section` → 卡片 `.ref-exp-card` → 子卡片 `.ref-case-card` → 内容框 `.ref-case-rx`

**请确认**：你是否接受这个规范？如果不接受，请提出修改建议，我们协商后统一。

### 3.4 mobile.html 同步（待决策）

当前 `index.html` 已大幅更新（35 张卡片、类方学习、痕迹记录、视觉规范 V1），但 `mobile.html` 落后很多。

**选项**：

**请确认**：你的选择？以及实施计划？

### 3.5 痕迹记录 UI（需要你完善）

我已经提供了 `recordTrace()` / `getDailyLearningData()` / `generateDailyReport()` / `exportTraces()` 函数，但以下 UI 还需要你补充：

## 五、变更流程

任何涉及两方的事务：
1. 提出方写变更通知（简要说明变更内容、原因、影响）
2. 另一方在 1 个回合内确认或提出异议
3. 双方确认后，各自在职责范围内实施
4. 实施完成后，端到端验证
5. 可用 → 更新共识；不可用 → 重新协商
