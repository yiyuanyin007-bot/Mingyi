## 一、资料画像

### 1.1 规模与分类

| 类别 | 篇数 | 占比 | 核心内容 | 与学习系统的对应关系 |
|---|---:|---|---|---|
| 医案 | 81 | 70.4% | 沙龙讨论式医案：患者信息、病史、舌脉、网友讨论、黄师处方、疗效随访 | 主要落点：`experience_cards.json` |
| 五十味药证 | 27 | 23.5% | 单味药的《本经》记载、仲景原文考证、方根、常用配方、体质、剂量 | 主要落点：`formula_cards.json` 的药物字段补强；未来可做 `herb_cards.json` |
| 临床经验 | 3 | 2.6% | 西医病名 + 体质分型 + 适用方剂 + 验案 + 按语 | `experience_cards.json` + `formula_cards.json` 临床应用字段 |
| 经验方 | 2 | 1.7% | 八味除烦汤、八味解郁汤的组成、剂量、主治、加减、方解 | 可作为新 `formula_card` 或现有方的变体 |
| 常用经方 | 1 | 0.9% | 讲座记录：13 张常用经方的现代病名定位、关键指征、加减套路 | `formula_cards.json` 的参考链接与现代应用字段 |
| 经方言论 | 1 | 0.9% | 120+ 条语录，涵盖体质、辨证、单药经验、方剂应用、用量思想 | `experience_cards.json` 碎片、Kimi 导师素材、练习干扰项 |

- **总篇数**：115
- **总字符数**：178,200
- **平均每篇**：1,549 字
- **原始出处**：黄煌新浪博客（2011 年前后整理发布），部分讲座记录源自 2007 年广东省中医院讲座。

### 1.2 内容特征

1. **临床密度高**：不是泛泛的科普，而是带剂量、带体质、带加减的临床话语。
2. **沙龙讨论式**：医案类资料夹杂大量网友跟帖，必须把「黄师处方/按语」和「网友个人观点」严格分开。
3. **跨类别重复**：八味除烦汤、八味解郁汤、大柴胡汤、小柴胡汤等在医案、经验方、言论中反复出现，需要统一 ID。
4. **版本差异**：八味除烦汤存在「枳实版」与早期「甘草版」的差异，入库必须标注版本与出处。
5. **结构分层明显**：药证最规范 → 经验方/常用经方次之 → 医案需先做讨论区清洗 → 言论最碎片。

## 二、使用原则

### 2.1 不改变经典层

- 黄煌资料属于**临床解释层 / 经验层**，不能覆盖或替代《伤寒论》原文层（`source_cards.json`）。
- 任何由黄煌资料补强的字段，都必须保留原始来源标注，方便用户区分「仲景原文」与「后世注家经验」。

### 2.2 来源可追溯

- 每篇资料都有 `source_url`（新浪博客原文地址）和 `date`，接入时必须保留。
- 建议新增字段：`source_type`（如 `讲座记录`、`沙龙医案`、`药证讲义`、`经验方`、`言论汇编`）。

### 2.3 区分作者身份

- 医案中的处方/思路必须标注 `author_type`：
  - `黄师`：黄煌本人的处方、按语、回复。
  - `网友`：沙龙参与者的猜测、提问、个人经验。
  - `整理者/解析者`：如黄波等人后续解析。
- 只有 `黄师` 和经过核验的 `整理者` 内容才进入正式卡片。

### 2.4 版本控制

- 同一方剂若有不同组成（如八味除烦汤），必须分版本记录，不能简单合并。
- 建议用 `lineage.variant_path` 或 `references.version` 字段承载。

### 2.5 先轻后重，先验证后批量

- 不要一次性把 115 篇全部结构化。先选一个**试点方剂**做端到端打通，验证 schema、前端渲染、练习生成都没有问题，再批量扩展。

## 三、与现有系统的关系

当前学习系统已有三层卡片结构：

```
source_cards.json（原文条文）
        ↑
formula_cards.json（方剂卡片）
        ↓
experience_cards.json（医案/经验卡片）
```

黄煌资料的落点：**不新增第四层，而是补强第二、三层，并为未来可能的第四层（药物卡）准备素材**。

| 现有挂载点 | 当前状态 | 黄煌资料可做的事 |
|---|---|---|
| `formula_card.data.canonical.core_sources` | 35/35 已填充 | 增加「黄煌教授经方沙龙」等来源名称 |
| `formula_card.data.canonical.core_source_urls` | 10/35 已填充 | 把黄煌相关方的博客链接挂上来 |
| `formula_card.experience_ids` | 1/35 已填充 | 批量关联医案、临床经验、常用经方经验 |
| `formula_card.data.canonical.herbs` | 已存在 | 从五十味药证补入药证、配伍、体质 |
| `formula_card.lineage.variant_path` | 基本未填充 | 经验方（八味除烦/解郁）可作为变体 |
| `experience_cards.json` | 仅 1 张 | 医案、临床经验、言论切片的主要落点 |

**一个已知前端 bug 需要修复**：`app/index.html` 中 `getExperience(id)` 当前实现为 `EXPERIENCES.find(e => e.id === e.id)`，会永远返回第一张经验卡。在批量接入经验卡之前必须修复为 `EXPERIENCES.find(e => e.id === id)`。

## 四、分层使用方法论

把黄煌资料的使用分成 5 个层次，每层有独立的目标、产出和验收标准。

### L0：归档层（已完成）

- **目标**：把 CHM 解包后的原始 HTML 清洗成可读的 Markdown，并建立目录。
- **产出**：
  - `extracted/黄煌教授经方沙龙/cleaned/<类别>/<标题>.md`
  - `extracted/黄煌教授经方沙龙/catalog.json`
  - `extracted/黄煌教授经方沙龙/catalog.md`
- **验收标准**：115 篇全部可读、元数据完整、分类可统计。
- **状态**：✅ 已完成。

### L1：参考链接层（低风险、快速 win）

- **目标**：把常用经方、经验方、临床经验、言论中涉及的方剂，作为参考资料链接挂到对应 `formula_card`。
- **适合资料**：
  - `常用经方/黄煌教授_我常用的几张经方.md`（13 张常用方）
  - `经验方/*.md`（八味除烦汤、八味解郁汤）
  - `临床经验/*.md`（血小板增多症、干燥综合征、自身免疫性溶血性贫血）
- **挂载字段**：
  - 现有：`formula_card.data.canonical.core_sources` / `core_source_urls`
  - 建议新增规范：`formula_card.data.canonical.references` 数组，结构见第六节。
- **验收标准**：
  - 35 张现有方剂卡中，凡在黄煌资料中被明确提及的，至少有 1 条 reference。
  - 前端「参考资料」区域能正确渲染新增链接。

### L2：药证补注层（补强方剂卡的药物维度）

- **目标**：从「五十味药证」中提取单味药的「药证 / 方根 / 常用配方 / 体质 / 剂量」，补强 `formula_card.herbs` 字段。
- **适合资料**：`五十味药证/*.md`（27 篇）。
- **两种做法**：
  - **轻量做法**：为每张 `formula_card` 的 `herbs` 数组增加 `herb_evidence` / `constitution` / `dosage_note` 等字段。
  - **重量做法**：新建 `data/herb_cards.json`，把 27 味药做成独立药物卡，未来与方剂卡双向引用。
- **建议**：先做轻量做法，验证后视需要决定是否建独立药物卡。
- **验收标准**：
  - 35 张方剂卡的核心药物都有黄煌药证摘要。
  - 不改变原有 `herbs.name` / `dosage` 字段，避免破坏现有练习题目生成。

### L3：医案经验层（核心增值层）

- **目标**：把 81 篇医案和 3 篇临床经验结构化生成 `experience_cards.json`，并通过 `parent_formula_id` 关联到方剂卡。
- **关键预处理**：
  - 分割「黄师部分」与「网友讨论部分」。
  - 提取 `patient_profile`、`chief_complaint`、`signs`、`physician_formula`、`herbs_dosage`、`outcome`、`physician_rationale`。
- **挂载方式**：
  - `experience_card.parent_formula_id` → `formula_card.id`
  - `formula_card.experience_ids` → 新增 experience_card.id
- **验收标准**：
  - 每张经验卡都能明确追溯到黄煌新浪博客原文。
  - 每张经验卡至少关联 1 张 `formula_card`。
  - 经验卡中的处方与方剂卡中的药物组成一致或能说明加减。

### L4：训练生成层（最后一步）

- **目标**：基于 L1-L3 的新数据，生成新的练习题目和掌握度向量。
- **可生成题型**：
  - `1→0`：症状 → 方名（从医案主诉/体征中抽取）。
  - `2→0`：药物组合 → 方名（从药证方根、经验方组成中抽取）。
  - `case` 类：给出医案片段，选择最可能处方（需新增题型支持）。
  - `confusable` 类：利用黄煌言论中的鉴别观点生成易混淆方对比题。
- **验收标准**：
  - 新题目有明确来源标注。
  - 跑一轮冒烟测试，人工抽检 20 题，错误率 <10%。

## 六、数据规范建议

### 6.1 新增 `references` 数组（推荐）

现有 `core_sources` + `core_source_urls` 两个平行数组容易不同步。建议在 `formula_card.data.canonical` 下新增结构化 `references`：

```json
{
  "data": {
    "canonical": {
      "references": [
        {
          "title": "黄煌教授 我常用的几张经方",
          "source": "黄煌教授经方沙龙",
          "source_type": "讲座记录",
          "url": "http://blog.sina.com.cn/s/blog_766c0caf0100vz3n.html",
          "type": "article",
          "note": "2007 年广东省中医院讲座记录，列出 13 张常用经方"
        },
        {
          "title": "黄煌教授医案 胃十二指肠炎案",
          "source": "黄煌教授经方沙龙",
          "source_type": "沙龙医案",
          "url": "http://blog.sina.com.cn/s/blog_766c0caf0100wtsl.html",
          "type": "case",
          "note": "大柴胡汤去大黄加黄连治胃十二指肠炎"
        }
      ]
    }
  }
}
```

`type` 枚举：`article`（文章/讲座）、`case`（医案）、`experience`（经验/言论）、`lecture`（讲座记录）。

### 6.2 扩展 `experience_card` 字段

建议新增或明确以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `parent_formula_id` | 字符串 | 关联主方 ID（已有，需正确使用） |
| `source_url` | 字符串 | 新浪博客原文链接 |
| `source_type` | 字符串 | `沙龙医案` / `临床经验` / `讲座记录` / `言论切片` |
| `author_type` | 字符串 | `黄师` / `整理者` / `网友` |
| `patient_profile` | 对象 | `{gender, age, body_type, constitution}` |
| `chief_complaint` | 字符串 | 主诉 |
| `signs` | 对象 | `{tongue, pulse, abdomen, others}` |
| `physician_formula` | 字符串 | 黄师最终处方方名 |
| `herbs_dosage` | 字符串/数组 | 药物与剂量 |
| `modifications` | 字符串 | 加减说明 |
| `outcome` | 字符串 | 疗效随访 |
| `physician_rationale` | 字符串 | 用方思路/按语 |
| `discussion_note` | 字符串 | 网友讨论中值得注意但未采纳的观点 |
| `efficacy` | 对象 | 已有，保留 `{subjective_effective, objective_change, confidence_level}` |
| `tags` | 数组 | 方名 + 症状 + 体质标签 |

### 6.3 版本差异标注

以八味除烦汤为例：

```json
{
  "lineage": {
    "base_formula": "栀子厚朴汤",
    "variant_path": ["加黄芩、连翘、半夏、茯苓、苏梗"],
    "reference_source": "黄煌教授经方沙龙"
  },
  "data": {
    "canonical": {
      "references": [
        {
          "title": "黄煌教授经验方 八味除烦汤",
          "source_type": "经验方",
          "url": "...",
          "type": "article",
          "version": "现行版：枳实，无甘草",
          "note": "见言论整理版第 20 条；第 78 条记载早期用甘草，后改枳壳"
        }
      ]
    }
  }
}
```

## 七、风险与边界

| 风险 | 说明 | 应对策略 |
|---|---|---|
| **观点层级混淆** | 黄煌是后世注家，不能替代《伤寒论》原文 | 所有黄煌资料明确标注来源；经典层字段不动 |
| **网友观点混入** | 医案类资料含大量网友猜测 | 提取时强制区分 `author_type`；仅黄师/整理者内容入库 |
| **方剂版本冲突** | 同一方剂在不同资料中组成不同 | 分版本记录，用 `lineage.variant_path` + `references.version` |
| **过度扩充卡片** | 81 篇医案全部接入可能导致数据爆炸 | 先试点 3-5 个代表方，验证后再批量 |
| **前端渲染瓶颈** | 经验卡增多后 `getExperience` bug 会暴露 | 阶段 0 必须修复 |
| **练习选项质量下降** | 新题目若来源不可靠会污染题库 | 每批新题人工抽检 20%，错误率 <10% |
